# H 層評価の手順書(Phase 1 版)

台帳 v3.2-3 の H 層(人間による重大誤読ゲート)と、所有者指示(2026-08-04)項3
(案A/案B を同一対象・同一情報・同一タスクで比較)・項5(手順・質問・合否基準・記録様式)に基づく。

**H 層は、この手順で実施されるまで `UNASSESSED` である。実施前に PASS を名乗らない(項7)。**

## 前提

- 被験者は模型の作成に関与していない者(自己評価の罠を避ける。事前分析 §9.2)。
- 人数は合否条件に含めない(O 層の観測値)。1名からでも実施でき、合否は「実施済みの全参加者」について判定する。
- 記録者は被験者と別に一名(進行と記録に専念)。
- 使用物: `prototype/index.html`(commit を記録すること)・`record-form.md` の複製・時計。

## 手順

1. **準備**: index.html を開く。対象は T1〜T5・T7〜T8 = 実在三対象のうち一つ(被験者ごとに割り当てを変える)、T6 = `fixture-rare-states(架空)`。操作数計数器を 0 に戻す。
   (旧版にあった A/B モード順の交互は、所有者判断 2026-08-04 で構成図が採用されたため廃止。DESIGN-001 参照。)
2. **教示**: 「画面の言葉だけを根拠に答えてください。分からない場合は『分からない』と答えてください(それは失敗ではありません)」。凡例・用語の事前説明はしない(凡例なし誤読の検出のため)。
3. **タスク実施**: T1 から順に、質問を読み上げ→被験者が操作と口頭回答→記録者が record-form に記入(回答・正誤・操作数・所要・誤読の種類)。
4. **事後質問**: 記法の意味(状態章の色や破線の意味)を尋ね、凡例なしで誤読された記法を特定する。
5. **保存**: `usability-tests/records/R-<日付>-<被験者番号>.md` として保存する(氏名は書かない)。

## タスク(質問)と正答条件

| # | 画面 | 質問 | 正答条件 | 検出したい誤読 |
|---|---|---|---|---|
| T1 | システム | この系は何のために在り、外部の誰と何をやり取りするか | purpose と外部要素・主要な交換を言える | 箱の集合を目的と取り違える |
| T2 | システム(詳細) | 要素〈X〉が担うこと・担わないことを一つずつ挙げよ | 責務と非責務を区別して言える | 機能一覧を責任と取り違える |
| T3 | システム | 要素〈X〉は何を受け、何を返すか。それぞれの種類(データ/命令/イベント/人の行為)は | IN/OUT と種類を正しく言える | 方向・種類の混同 |
| T4 | シナリオ | 正常系で〈受信者〉に最終的に何が返るか。例外系では何が違うか | outcome と例外の差を言える | 正常系だけで説明する |
| T5 | 保証 | (a) 証拠付きで確認されているのはどれか (b) `claimed` と `planned` の違いは何か (c) `unknown` の行は「問題が無い」という意味か | (a) verified のみを挙げる (b) 方法の有無を言える (c) 「いいえ(記録が無いだけ)」 | **unknown→問題なし / claimed→planned・verified / planned→verified** |
| T6 | 保証(fixture) | `failed` と `stale` の行について、いま信じてよい保証はどれか。`stale` の証拠はなぜ使えないか | どちらも今は信じられない・stale は前提(構成)が変わったから、を言える | **stale→有効な証拠** |
| T7 | システム→詳細 | 〈verified の契約〉の根拠(証拠)を示せ | 3 操作以内で証拠(環境・版・観測日つき)に到達する | 主張と証拠の同一視 |
| T8 | システム(図) | 〈要素X〉から出た流れ〈F〉を図の上で辿れ。最終的に誰へ届き、何が戻ってくるか | 経路(中継含む)と戻り(フィードバック)を図から言える | 方向の誤読・フィードバックの見落とし |

〈X〉・〈verified の契約〉は対象ごとに記録者が事前に固定する(record-form に記載欄)。

## 合否基準

- **H 層合格** = 実施済みの全参加者で、太字の誤読(T5 の3種+T6 の1種)が **0 件**(台帳 v3.2-3 の文言どおり)。
- 誤読が 1 件でもあれば H 層は不合格 — 記法・文言を直し、次の被験者で再実施する。
- 凡例なしで誤読された記法(事後質問)は削除または再設計する(M 層へ還流)。
- T7 が 3 操作を超えた場合は M-14 の再測(build 時判定との食い違いを調べる)。
- 正答率・所要・操作数・A/B の主観差は **O 層の観測値**であり、合否に使わない(サンプル計画が決まるまで。台帳 v3.2-3)。
