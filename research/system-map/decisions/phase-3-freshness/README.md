# 鮮度の規則を、上流の宣言から導く(作業の記録)

- 日付: 2026-08-17
- 位置づけ: **実験ブランチ内の作業の記録**であり、統治木の ADR ではない。
- 経緯: doctrine#294 第13信 §6 で上流が鮮度の判定規則を ICD-002 に一度だけ定め、
  **「読み手はこの規則を再定義しない」**と宣言した。当方はそれを受けると第6信 §6 で答えた。
  これはその実施である。

## 正本(上流 `doctrine_docs/graph/ICD.md`「測った木の版と作り手」・ADR-172 決定3)

> 記録時といまの `source_revision` が共に完全 SHA で等しく、かつ、いまの `source_dirty` が
> false なら「同一」。共に完全 SHA で異なれば「相違」。どちらかが null、または、
> いまの `source_dirty` が true か null なら「不明」。三値であり、不明を肯定(同一)に丸めない。

## 出荷していた規則は、宣言と 7 行で食い違っていた(RED)

`build-overlay.mjs:245` の一行の三項式:

```js
rev_state: !known ? "unknown" : observedRev === a.source_revision ? "same" : "advanced",
```

宣言から起こした 11 行の表に掛けた生ログ: `logs/RED-rev-state-vs-declaration.log`。**7 行が食い違う。**

| # | 食い違い | 危険 |
|---|---|---|
| 1 | **`source_dirty` を判定に入れていない** | **高**。汚れた木でも「記録時 rev と同一(照合済)」と断言していた。未コミットの変更が在れば rev が同じでも中身は同じでない |
| 2 | 完全 SHA かを検めず、ただの文字列比較 | 中。実データに `"en/stable(2026-08-03〜04 取得)"` のような値が在り、比較が成立しないのに「相違」を名乗る |
| 3 | 宣言に無い条件(記録した rev が履歴に在るか)を足していた | 低。相違を不明へ寄せる向きなので安全側だが、**再定義であることに変わりはない** |
| 4 | 三値目の名が `advanced`(前進) | 中。**測っていない方向を主張していた**。宣言は「異なる」としか言っていない |

1 と 4 は、この木がずっと潰してきた「機械が言えないことを画面が肯定として出す」形そのものである。

## 直した形

- **規則は `lib/rev-state.mjs` の一関数だけが持つ。** 宣言の本文を綴りの中へ引き、出所を名指す。
- `build-overlay.mjs` は呼ぶだけにした。`known` の git 呼び出し(`cat-file -e`)は宣言に無い条件なので**消えた** ——
  副産物として、候補ごとの子プロセス起動が一つ減る。
- 語彙を `advanced` → `differs` にし、`policy.display.rev_state` の説明文を宣言の字面へ合わせた。
  `same` の説明には**汚れの条件**を書いた(以前は書いていなかったので、画面の断言に根拠が無かった)。

## 宣言に曖昧な点が一つ在る(#294 第7信で上げる)

三文は次の一点で重なる:

> 両方が完全 SHA で**異なり**、かつ、いまの `source_dirty` が true のとき、
> 第二文は「相違」と言い、第三文は「不明」と言う。

**第二文を採った。** 理由: rev が異なることは既に測れており、汚れはその差を打ち消さない。
汚れが効くのは「同じである」と**肯定する**ときだけである。判断は `lib/rev-state.mjs` の
末尾に註として残した。**上流が逆に裁定したら直す。規則の正本はこちらではない。**

## 段を一つ増やした

`registry.json` の `gates[].cwd` は `"overlay"` を**許していたのに、使う段が一つも無かった**
(記録の無い繋ぎ忘れ。#294 第5信 §2 で「設えを足して使い忘れる」同型の抜けとして報告した)。
鮮度の規則の検めはそこが正しい家なので、段 `overlay` を作って入れた。

| 物 | 中身 |
|---|---|
| 段 | `overlay`(`cwd: overlay` / `node test-rev-state.mjs`)。`chaos` の後、`targets-wired` の前 |
| 不変条件 | **M-F1** 鮮度の三値は上流の宣言から導き、こちらで再定義しない。不明を同一に丸めない |
| 検査器 | `overlay:rev-state-declared`(判ずる対象は `gate`) |
| 表 | 11 行。各行に宣言の**どの文**から来たかを書く |

**この段はまだ overlay の鮮度(commit 済みの物が今の rev の物か)を検めていない。** それは別の主題である。

## 途中で二度、安全装置が鳴った

`display-static` の段は `rev_state` の語を生成器の綴りから採る。規則を lib へ移したので
**採れる語が 3 → 1 に落ち**、下限を割って **FAIL ではなく ERROR** で止まった。
走査元を直したら今度は 2 件で、また止まった —— 最後の枝が三項式で `return "same"` の形に
なっていなかったためである。

**二度とも「採れなかった回」が「合っていた回」に化けなかった。** PR6 でこの下限を
入れたときの判断が、今回効いた。走査を広げるのではなく、規則の綴りを素直にして直した。

## この記録が保証していないこと

- **実装が宣言と一致することを示しただけで、宣言が正しいことは検めていない。**
- 表は 11 行であり、**宣言の全ての場合を尽くしているとは言っていない。**
  特に「完全 SHA」の判定は 40 桁の十六進かどうかしか見ておらず、その SHA が実在する
  コミットを指すかは見ていない(宣言もそこまでは言っていない)。
- `unparsed` と `unbound-repo` の枝は `rev_state` に `"unknown"` を**直書き**している。
  規則を通していない —— そもそも測れていない枝であり、規則へ渡すと `observedRev` と
  記録が偶然一致したときに「同一」を名乗りうるからである。**この判断は綴りの中に書いた。**
- 画面がこの三値を**どう描くか**は別の主題である。この記録は生成器までを見ている。
