## 何によって解消したか

**`610387d`(2026-08-03T12:19Z、CHANGE-023・024・ADR-028)である。**

この一つの変更が、`docs-linter.py --batch` を `package.json` の `check` と CI の

## 上流の更新は何を消したか — 10 件(94 件のうち)

同じ統治木(`632df83`)を 0.8.0 と v0.11.0 で測った差は **94 → 85** である。

消えた 10 件は**すべて同じ形**だった:

```
[ERROR] lens/spec/SPEC-001..008: 禁止同義語『エラー』→ 承認語『所見』を使う。
[ERROR] lens/decisions/ADR-018, IMPACT-004: 同上
```

SPEC の必須節の名が `エラー時挙動` であり、その断片『エラー』をこちらの辞書が禁じていた。
節を書けば禁止同義語、節を消せば必須節の不在という板挟みである(上流 #197)。
上流はこれを機構で解いた(ADR-135。必須節の名の覆いを登録簿から導く)。

**逆に v0.11.0 で 1 件増えた**: `_system/glossary.md` の `owner` が雛形の指示文のままだという
`PLACEHOLDER_VALUE`。当時の木の話であり、現行の木には無い。

つまり上流の周知(2026-08-08、#12)の「板挟み由来の分は構造的に消えます」は**正しかったが、
消えるのは 94 件のうち 10 件**である。`MISSING_SECTION` 13 件は v0.11.0 でも残る(節の不在は
節の不在であって板挟みではない)。上流は 2026-08-09 に自ら「表B の軸では板挟みが残る」と訂正しており、
この数字はその訂正と両立する。

## #12 の提案の現況

#12 は `docs:check` に全件のリンタを足す差分を提案した。**その差分は不要である** ——
既に別の口として配線されている。

```jsonc
// package.json
"check":     "npm run typecheck && npm run test && npm run compile && npm run docs:check
              && npm run docs:lint && npm run docs:terms && npm run docs:measured"
"docs:lint": "python3 \"$(node tools/doctrine-path.mjs)/scripts/docs-linter.py\" --batch ."
```
```yaml
# .github/workflows/check.yml
- name: 統治木の全件監査   { run: npm run docs:check }
- name: 統治木の全件点検   { run: npm run docs:lint }
```

`docs:check` に連結するのではなく `docs:lint` という別の段にしたので、どちらが落ちたかが分かれる。

## 残る穴 — 重さ WARN の所見 178 件を誰も見ていない

`--batch` は**重さ ERROR の所見だけを数え、WARN を捨てる**(`docs-linter.py` の `_run_batch`)。
現行の木を宣言済みの一件検査の口(PostToolUse の封筒)で全件回すと:

| 重さ | 検査 | 件数 |
|---|---|---|
| WARN | `UNDEFINED_TERM` | 153 |
| WARN | `CALQUE_WORDTRAP` | 25 |
| | **合計** | **178**(123 文書中 93 文書) |

上位の語は `PR`(32)・`L0`/`L1`/`L2`/`L3`(40)・`README`(10)・`CSS`(9)・`SVG`(5) など、
略語と固有名が多い。**これらは辞書の側を直すべきものと、本文を直すべきものが混ざっている。**
本再測定では**分類していない**。門にも入れていない。別の主題である。

#12 が言った「片側の門しか回していないので、もう片側が守るはずのものが誰も守っていない」は、
形を変えて**まだ成り立っている** —— 回してはいるが、重さ WARN の側は誰も見ていない。

## 上流へ返す論点(規則 14。こちらで上流の仕様を実装しない)

所有者が 2026-08-09 に #12 で書いた:

> それまでは、**そちらの表B に必須節名(およびその断片)を入れないでください** —— 入れると逃げ道がありません。

**これを機械で守る手段が、こちらには無い。** 必須節の名の一覧は上流の登録簿が正本であり、
それを返す宣言済みの口が存在しない(`scaffold.py` は `_system` の最小配置だけを作る)。

- 上流の内部モジュールを直読みすれば守れるが、読み口の規律(台帳 v3.2-14)に反する。
- こちらへ節名を書き写せば守れるが、同じ事実の二重定義になり、上流が名を変えたとき黙って古びる。

いま成り立っている検査は「**いま使われている節名は書ける**」までである(それは `docs:lint` が
既に検めている)。守れないのは「**まだこの木に無い型**の節名を、表B が後から禁じてしまう」場合である。
この木には `API`・`DATA`・`PROC` の文書が無いので、その型の節名を表B が禁じても、最初の一件を書くまで誰も気付かない。

**必須節の名を返す口を宣言してもらえないか**、を #212 へ提案する。

## 答えが黙って崩れないようにする — `tools/gates-wired.test.mjs`

**いま 0 件なのは、門が走っているからである。** その事実を守るものが無かった。段を一つ消しても、
命令の連なりから一つ落としても、誰も気付かないまま「所見 0」に戻る —— 走っていないから 0 なのか、
守れているから 0 なのかを、区別できない状態に戻る。#12 が報告したのはまさにその状態だった。

そこで、配線そのものを凍結する試験を置いた。**これは欠陥の再現ではない**(書いた時点で通る)。
回帰の門である。したがって、**発火することを潰して実測した**:

| 潰した先 | 落ちた試験 |
|---|---|
| `check` から `&& npm run docs:lint` を落とす | 1. 手元の check が全件のリンタを含む七段を通す |
| `check.yml` の「統治木の全件点検」段を `echo skip` に変える | 2. CI が同じ七段に加えてホスト試験・画面・配布物を回す |
| `docs:lint` の `--batch .` を `.` に変える(一件検査の口になり常に 0 を返す) | 3. docs:lint は全件走査の口を叩く |
| `docs:check` から `--fail-on error` を外す | 4. docs:check は所見の重さで落ちる |
| `docs:check` の上流の引き方を版つきの直書きに変える | 5. 門はどれも上流の実体を doctrine-path.mjs 経由で引く |

五つの潰しが、それぞれ**対応する一件だけ**を落とした(潰さなければ 5 件とも通る)。
潰しは一時の木の複製に対して行い、実物の作業木には触れていない。

なお、六つ目の潰しを試みたとき、変異器が**潰す先が 4 箇所あることを理由に拒んだ**。
曖昧な潰しを黙って全箇所へ当てない側の振る舞いであり、一意な箇所へ絞り直して測った。

**`npm run mutate` はこの試験を守れない。** `tools/mutate-check.mjs` の判定は
`out/test/*.test.js` だけを回し、`tools/*.test.mjs` を含まない(`TEST_GLOB`)。
潰しても基準線が緑のままなので「守られていない」と誤って報告する。
判定の命令を `npm test` と揃えるのは別の主題として残す。

## 処遇

**#12 は閉じる。** 報告された欠陥(全件のリンタが門に入っていない)は `610387d` で解消しており、
本再測定で現行の木・3 つの上流の版すべてが 0 件であることを確かめた。

残るものは #12 とは別の主題なので、この記録から名指しで引き継ぐ:

1. 重さ WARN の所見 178 件が門に入っていない(分類も未了)
2. 表B の罠を機械で守れない(上流へ口の宣言を提案する)
