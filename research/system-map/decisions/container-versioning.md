# DESIGN-003: 器の版の進め方 — 受け入れる集合が狭まったら名を上げる(実験ブランチ内の設計判断の記録)

- 日付: 2026-08-14
- 位置づけ: **実験ブランチ内の設計判断の記録**であり、統治木の ADR ではない。
- 経緯: doctrine#294 で当方が版の進め方を提案し、上流が受けた(ADR-165 決定4)。
  その直後、**提案した規約に穴が在り、しかもその穴に当方自身が落ちていた**ことが実測で分かった。
  所有者判断(2026-08-14)により、規約を直して版を上げる。

## 何が起きていたか

上流は当方の指摘(#294 第2信)を受け、**器の形を写すのをやめ、当方の `schema.json` の一枚から
必須欄と語彙を導く**ようにした(ADR-165・EXT-007)。同梱したのは当方の tag
`system-map/phase-1-continue`(`d920130f`)時点の `schema.json` である。

そこまでは正しい。**ずれていたのは当方の側である。**

| | sha256 の頭 | 大きさ |
|---|---|---|
| 上流が同梱した器 | `d927a69a…` | 15041 byte |
| 当方の tag 時点 | `d927a69a…` | 15041 byte |
| **当方の現行** | **`f74f4d07…`** | **15840 byte** |

差は二つで、どちらも `b9f65ee`(Phase 2 前半・**この合意より前**)で入った:

1. `SystemElement` の **`realization` と `realized_by` の排他**
2. 証跡などの欄の **`minLength: 1`**(空文字列を禁じる)

**必須欄と語彙は一つも動いていない**(機械で突き合わせた)ので、上流の導出は今も正しく、
現に何も壊れていない。**危険は潜在的で、狭い** —— 上流が両方の欄を持つ要素や空文字列の証跡を
描いたとき、上流の門は通し、当方の門が落とす。

## 提案した規約に在った穴

#294 で当方はこう書いた:

> 欄の追加(既存の投影が通り続ける物)は版を上げない。**必須欄の追加・削除、語彙の縮小**は
> `0.1 → 0.2` と名を上げる。

上の二つはそのどちらでもない。**「制約の追加」を分類していなかった。** 当方の提案の抜けである。

結果として、**同じ `$id: system-map/gold-model/0.1` を名乗る器が二つ在り、受け入れる集合が
違う**状態になっていた。これは Phase 2 でずっと潰してきた「**名が嘘をつく**」形そのものである。

## 決定

1. **規約を直す。** 版を上げる条件を「受け入れる集合が狭まる変更」とし、
   **必須欄の追加・語彙の縮小に加えて、制約の追加(排他・`minLength` など)も含める。**
2. **器を `0.1` → `0.2` へ上げる。** `$id`・`properties.schema.const`・当方の四模型が追随する。
3. **上げたことを #294 へ告知する**(合意どおり。逆はしない。正本は一つ)。
4. **規約の本文は `schema.json` の `$comment` が持つ。** この記録は経緯であって正本ではない
   —— 器を読む者が規約も同じ一枚で読めるようにする。

### 却下した案

- **`0.1` のまま、新しい tag を切って上流に貼り直してもらう。** 安く、現に何も壊れていない。
  しかし**同じ名で中身が違う状態が残る**。今回まさに叩いた欠陥(名乗った器に適合しない)を、
  当方の側に残すことになる。
- **排他と `minLength` を外して tag 時点へ戻す。** 検めを弱めることになる。
  二つとも「欠落を正常値として通さない」ための制約であり、外す理由が無い。

## 影響

| 物 | 追随 |
|---|---|
| `gold-model/schema.json` | `$id`・`title`・`properties.schema.const`・`$comment`(規約の本文) |
| 当方の四模型 | `"schema"` の文字列 |
| `gold-model/spec.mjs` | **不要**(`properties.schema.const` から導いている) |
| 上流 | 同梱する一枚を新しい固定点へ貼り直す(#294 で告知する) |
| `decisions/` の起草物(`phase-2-e2e/doctrine/draft-doctrine.json`) | **書き換えない。** 当時の測定の記録である |
| `overlay/0.1` | **無関係**(別の器) |

## この記録が保証していないこと

- **上流の追随は当方の手の外に在る。** 告知するまで、上流は `0.1` の一枚から導き続ける。
  その間に描かれた投影は、当方の器が `0.2` を要求するので **`schema` の値で落ちる**。
  告知と追随が済むまでの窓が在ることを、隠さずに書いておく。
- 版を上げても、**器は「形」と「不変条件」の二層のままである。** M 層の不変条件は
  `schema.json` に書けず、当方の validator が持つ。上流が起草時にそれを知る術は、
  当方が `--requirements` の口を作るまで無い(#294 の宿題)。
- 今回の二つの制約が**十分**であることは言っていない。他に schema で書けるのに書いていない
  制約が在るかは、検めていない。
