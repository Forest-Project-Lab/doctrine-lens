# [doctrine-lens] 合意台帳 v3.2 — 自己完結版(正本)。v3.1 を置換

**性質**: v3.1(所有者 2026-08-03 20:08 明示 ACK)に、所有者の第二裁定(2026-08-04、doctrine セッション経由で原文伝達:「A ACK / tag 規則 ACK / 「1操作」定義 ACK」)の3件と [doctrine] 補強2点を反映した自己完結版。**変更は v3.2-5 の (e)→(e′)・対象確定と、v3.2-15・16 の新設のみ**。他は v3.1 と同文(全文再掲)。補強2点の文言化は本版が初出のため、[doctrine] は相違があれば当該箇所のみ指摘されたい。

**Phase 0 の開始**: G 節全項消化により、**本台帳の掲出をもって Phase 0(Gold Model 着手)を開始する**(v3.1 E 節・G 節の帰結。[doctrine] の同旨の理解と一致)。

## A. 決定事項(全文)

**v3.2-1. 現行製品の不変**: Lens の帰結画面・REQ-000・NONGOAL-001、doctrine のスキーマ(型・必須キー)は本検証の間、変更しない。NONGOAL の変更は「狭める」ではなく、証拠を得てから理由ごと書き換える(前提条件: v3.2-3 の M 層通過 ∧ H 層合格、データ源が文書依存グラフでないことの明記、全面禁止から scoped な禁止+理由への書き換え)。

**v3.2-2′. 検証の置き場 = doctrine-lens の実験ブランチ**(所有者 P2 の文言を正とする):
- ブランチ `experiment/system-map`(作成済み `fcf62d5`)。配置 `research/system-map/{gold-model, prototype, usability-tests, decisions}/`。
- `research/` は `doctrine_docs/` の外に置く。既知の失敗型「木の外に在るものは統治の外に在る」(lens CHANGE-025)への対処として、ブランチの存在と終端条件を両統治木の記録(v3.2-8)から名指す(lens ADR-029・doctrine ADR-112 が名指し済み)。
- 条件: (1) Phase 0–1 完了前に製品コードまたは `main` へ統合しない。(2) 実験用 Gold Model を doctrine の正式スキーマとして扱わない。(3) Phase の節目の commit へ tag を付ける。(4) doctrine からの参照は tag または SHA へ固定する。(5) Phase 1 終了時に「正式移管/検証継続/閉鎖」を必ず判断する。(6) 終了条件のない恒久的な実験ブランチにしない。(7) 独立した利用者・公開スキーマ・リリース周期の必要性が実証されるまで、別リポジトリ化しない。
- プロトタイプは製品コード(`src/`)から独立した静的物とし、固定された検証用 JSON だけを読む。

**v3.2-3. ゲートは三層**:
- **M 層(機械・常時実行可能)**: 事前分析 §6.4 の不変条件 / 未確認 `proposed` 値が正本表示に混入していない / 全辺に意味ラベルがある / TraceAnchor が解決可能 / 同一対象に鮮度判定器が複数ない / 宣言済み CLI 以外を読んでいない / 要素→コードまたは証拠へ規定操作数(v3.2-16: 初期値 3)以内で到達できる。
- **H 層(人間による重大誤読ゲート)**: 前提条件として所定の理解タスクが実施済みであること。その上で — `unknown`→問題なし 0人 / `claimed`→`planned` または `verified` 0人 / `planned`→`verified` 0人 / `stale`→有効な証拠 0人 / 凡例なし誤読が出た記法は削除または再設計済み。**未実施の場合、H 層は合格ではなく `UNASSESSED`** であり、製品統合の Go を出さない。
- **O 層(観測指標)**: 正答率・タスク時間・操作数・参加人数・役割別差。サンプル計画が決まるまで観測値。

**v3.2-4. 書く道具と表示製品の分離**: 意味の確認・昇格という書き込みは、Phase 0–1 では人の直接編集、Phase 4 以降は doctrine 側の道具(doc-author 系 Skill)の受け持ち。表示製品は読み取り専用。**書き込みを持つ画面は Lens ではない。**

**v3.2-5. Gold Model 三対象**(所有者裁定 A を反映):
- 対象: (1) Doctrine+Lens。(2) Lens の出荷プロセス(保守者・手動 `.vsix`・VS Code Marketplace)。(3) **Celery**(イベント駆動対象として確定。RQ は 2026-08-03 の判定で不合格 — (d) 配送意味論と (e) 順序の出所が公開文書の確認箇所から取れなかった。出所と判定は本 issue の G-8 報告二件のとおり)。
- 意味被覆: (a) リトライの流れと Control/Assumption、(b) 失敗の Feedback、(c) タイムアウト、(d) 配送意味論の Assumption/Guarantee 対 — いずれも出所取得済み(Celery userguide/tasks・workers)。
- **(e′) 順序保証の状態を、公開文書に忠実に四状態(不明/該当なし/明示的に無し/未検証)のいずれかで記録できること。** 出所が沈黙している場合は `unknown` のまま表示し、H 層の誤読検査(「不明」を「保証あり」と読ませない)の題材とする。
- **負の出所の必須化**([doctrine] 補強1): `unknown` を記録するときは、**どの公開文書のどの箇所を、いつ確認して沈黙だったか**(URL・確認日)を負の出所として必ず添える。出所欄の空白(未調査)と「確認したが無い」を表示上も区別するためである。
- **切替条件の明記**([doctrine] 補強2): 対象の切替(既往: RQ→Celery)は、意味被覆のいずれかの出所が公開文書から取れないと判明したときに行う。判明の記録(確認箇所・確認日)と切替の裁定を台帳の版で残す。以後の切替も同条件・同手続きとする。
- 安全例(Loss/Hazard)は任意の第四対象で、STPA ハンドブックの実例を流用し、doctrine の型にはしない。

**v3.2-6. 一画面一問の受入 = 判断単位規則 ∧ REQ-002 三検査**(切替操作子なし・同入力同表示・答えない問いの明記)。判断単位規則 — 一画面につき、利用者が完了させる主要な判断または理解タスクを一つだけ持つ。常時表示する情報はその判断に必要なものへ限定し、別の問いに答える詳細は別画面または明示的なドリルダウン先へ置く。どちらか単独を門と呼ばない。詳細パネルの判断単位は「契約充足の評価」一つとする(B 節 P1)。

**v3.2-7. Phase 4 凍結**: doctrine の新型・新必須キー・ハザード語彙・Flow の器は、意味モデルが最低二回改訂され、v3.2-3 の M 層を通過し H 層に合格する(`UNASSESSED` でない)まで作らない。解除は根拠 ADR の置換によってのみ。

**v3.2-8. 記録**: 各 Phase 完了ごとに両統治木へ記録する(lens: ADR+CHANGE/IMPACT、doctrine: ADR+必要に応じ EXT 参照点+投影の再描画)。

**v3.2-9. 保証状態は事前分析 §6.3 の七状態が正本**: `unknown / claimed / planned / verified / failed / stale / not_applicable`。`claimed` は主張のみ(方法・証拠なし)。`planned` は検証方法・予定ありだが結果なし。`verified` は対象の保証に結び付いた合格結果+証跡最小形(成果物の指紋・実行環境・版・終了状態・時刻)がある場合だけ成立し、証拠ファイルの存在だけでは成立しない。ADR-081 の語彙への対応は `planned` ↔「検証戦略」。状態の統合・再定義をしない。対応表(七状態 ↔ ADR-081 語彙 ↔ doctrine 正本語彙)を Gold Model に同梱する。

**v3.2-10. 鮮度判定の権威は TraceAnchor ごとに一つ**: 分割基準は対象種別ではなく、どの契約がその鮮度に権威を持つか。doctrine の宣言済み契約・CLI が管理する対象(文書、および `trace-index/1` が指紋を持つコード範囲を含む)は doctrine の fingerprint / view stamp(ICD-005 `view-stamp-format`)を使う。doctrine の契約外(外部資料・外部試験結果等)は Gold Model の `observed_at`/`fingerprint` を使う。同一アンカーに複数の鮮度判定を適用しない。

**v3.2-11′. 規範資料の扱い**: 公開リポジトリに置くのは資料メタデータのみ(名称・発行主体・版・参照 URL・参照ページ・概念対応・必要なら指紋)。PDF 本体・ページ画像・大量の翻訳文は、再配布条件を確認するまでコミットしない。両リポジトリの untracked 抽出物は作業用に留める。`Reference_material/` の gitignore 登録は両側完了(doctrine `8cd29bd`・lens `30b060f`)。

**v3.2-12. 帰属**: 意味の正本は — Phase 4 の凍結解除(根拠 ADR の置換)を経て初めて — doctrine。見せ方は doctrine-lens。検証は実験ブランチ。UI 派生データは実行時生成または破棄可能キャッシュ。OSS 評価モデルの最終帰属は(採用時)lens の test fixture / examples。

**v3.2-13. trace-index の契約化(完了)**: doctrine は ICD-002 へ `trace-index-api` を宣言し SPEC-026 と結んだ(`8cd29bd`)。lens は SPEC-004 の参照先を追随した(`30b060f`)。

**v3.2-14. 読み口の規律**: プロトタイプ・道具は doctrine の宣言済み CLI の実行出力だけを読む。`.claude/.cache` の直読みは契約外。

**v3.2-15. tag 規則(新設。所有者裁定)**: Phase の節目の commit には `system-map/phase-<n>` の形で tag を打つ(例: Phase 0 終了 = `system-map/phase-0`)。Phase 1 終了時は裁きの結果を接尾に添え `system-map/phase-1-<transfer|continue|close>` とする。tag は実験ブランチ上の commit を指し、ブランチ削除後も参照を生かす(v3.2-2′ 条件3・4)。**統治木からの参照は tag 名に、その時点の commit SHA を併記して行う。** 規則の正本は `research/system-map/decisions/` に置く。

**v3.2-16. 「1操作」の数え方(新設。所有者裁定)**: 1操作 = 利用者による一回の明示的な起動。クリック・Enter 等のキー起動・リンク遷移・パネル展開・ドリルダウン・ブラウザの「戻る」を各 1 と数える。スクロール・ホバー・視線移動は数えない。M 層の「規定操作数以内」の**規定操作数の初期値は 3**(要素→コードまたは証拠)。変更は台帳の版でのみ行う。

## B. 確定済み(所有者の明示 ACK)
