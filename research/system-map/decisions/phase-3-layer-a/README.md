## 作った物

| 物 | 役割 |

**捕獲は欠落を正常値へ変換しない。** 口が答えない・形が違う・空を返すを別の状態として記録し、
一つでも捕れなければ `exit 1` で止まる。四口の `source_revision` が揃うかも記録する
（上流 ICD-002 が「同じ木を測った」ことの照合として宣言している用途）。

## 設計は独立三案 → 審査 → 統合で決めた

三つの立脚点（欠落を先に／実測を主役に／統治の形を見せる）から独立に起案し、
三つの観点（過大主張・勘違い防止・実装可能性）で審査した。

**審査は 61 件の過大主張を挙げた。** 点は 4〜7/10。うち実装で潰した主な五つ:

| 挙がった過大主張 | 潰し方 |
|---|---|
| **散文へ数を焼き込む** —— 焼いた数（印の無いファイル 142・所見 36・所見 8）は**焼いたその日のうちに** 146・52・24 へ動いていた | 数は必ず `num()` を通し、台帳へ出所ごと記録する。門が「台帳に無い数」を落とす（M-V2） |
| **鮮度の三値を四口どうしの比較から出す** | 規則（上流 ICD-002）は「記録時」と「いま」の二回の観測を要る。この画面は build 時に一度しか叩かないので**構造上いつも「不明」**である。そう描き、なぜ「同一」も「相違」も出ないかを画面に書いた |
| **「40 種の検査が走った」** | `checks_run` は上流の静的な定数一覧であり実行の証跡ではない。「この版が名乗る検査の名簿」と書き、「走った」と書かない |
| **`excluded` を「未到達」と描く** | 保存則は `reached = annotated + unmarked + exempt + Σexcluded`。除外は**届いた内側**である。届かなかったのは刈った枝だけ |
| **辺の種別を「五語の語彙」と描き、出なかった語を 0 件と並べる** | 口は実在する種別しか返さない。**観測された種別だけ**を出し、「語彙」と呼ばない |

## 「できた」と勘違いさせないための仕掛け

**修辞ではなく構造で守る。**

1. **問いの形** ——「機械が測れたのはどこまでで、**その外側はどれだけ在るか**」。
   答えに必ず外側が入るので、欠落を落とすと**画面が壊れる**。
2. **M-V1**（`screen:no-authored-facts`）—— 手書き模型の字句も、捕獲の道具が書いた散文も、
   出荷物に現れない。押せる連結・外部の取得・環境の漏れも無い。
3. **M-V2**（`screen:numbers-have-provenance`）—— **画面に出る数が全て台帳に載り、出所を名乗る。**
   これで散文へ数を焼く経路が構造的に閉じる。
4. **M-V3**（`build:closures-hold`）—— 内訳が口の名乗る総数に閉じる。閉じなければ丸めずにそう描く。
5. 画面の第一節が「木の側に無いもの」で、意味モデルの件数が最初に出る。

### 途中で門が二度、私を止めた

- **M-S1（単一正本）** が、私が潰しと門の註に書いた**模型のファイル名**を咎めた。
  正本（`TARGETS`）から引く形へ直した。門を弱めていない。
- **M-V1 が二件の所見を出したが、調べると偽陽性だった** —— `Forest-Project-Lab` は
  文書が front-matter で挙げた URL の一部として口が返しており、手書き模型の**名そのもの**は
  **上流の道具がその模型について挙げた所見の `path`** として返していた。
  どちらも画面が模型を読んだのではなく、**道具が測って返した値**である。
  完全一致から部分一致へ照合を直した（除外を広げたのではなく、判定を正しくした）。

## まだ出来ていないこと（ここが肝心）

- **新しい画面はまだ出荷物ではない。** VSIX と拡張機能が読むのは依然として
  `prototype/index.html`（手書きの模型から描く古い画面）である。
  **所有者の言う「完全に除外」は、差し替えるまで達成されていない。**
- 差し替えると、いまの画面を判じている**検査器 8 件**の主題が変わる
  （M-13 通信・M-14 到達と操作数・M-L1 ラベル・M-19/M-20 語彙と区別）。
  再照準するか、正直に退役させるかを、一件ずつ決める必要がある。
- **意味モデルが 0 件である間、M-14（要素からコードへの到達）は検める対象を持たない。**
  差し替え後は VACUOUS になり、了解の記録が伸びる。それが正直な姿である。
- 実ブラウザでの操作数の実測を、新しい画面に対して行っていない（`<details>` 一段・
  押せる連結 0 は静的に検めたが、実機で数えていない）。
- 手書きの四模型は木の中に残っている。**統治木へ移すのは別の主題である。**
- 設計の統合が挙げた不変条件のうち、I-6（語彙の網羅）・I-9（実ブラウザの操作数）・
  I-12（捕獲の値を変えると画面が変わる変異）・I-14（口を落とした負例の撮影）は**未実装**である。
