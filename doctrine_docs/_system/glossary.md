# 用語辞書

本文書は用語辞書の正本である。各語は一つの意味だけを持つ。右列の同義語は使わない。承認語を増やす、または意味を変えるときは、ADRで決め、この表を更新する。各文書はこの表を二重定義しない。

| 承認語 | 唯一の意味 | 禁止する同義語 |
|---|---|---|
| 文書 | 管理対象の最小単位（S1000Dのデータモジュールに当たる） | ドキュメント、資料、ページ |
| ファイル | ディスク上の実体。「文書」の意味では使わない | （文書の意味でのファイルを禁止） |
| ドメイン | 交換できる区画（LRU／ARINC 653パーティションに当たる） | 領域、サブシステム、コンテキスト |
| ICD | ドメインが公開するインターフェース定義文書 | IF、インターフェース（単独語）、接続仕様 |
| 境界 | ドメインとドメインの接点 | つなぎ目、接合部 |
| 正本 | ある事実の唯一の権威ある出所 | マスター、原本、オリジナル |
| 投影 | モデルから描画した派生表示。手で保守しない。人が解釈するビューと混同しない | レンダリング結果（投影の意味で「出力」と書かない。関数や過程が返す値の意味の「出力」は使ってよい） |
| ビュー | 正本をある時点で人向けに解釈した体系外の文書。手で保守し、刻印で参照時点を示す（機械が描画する投影と混同しない） | ビューポイント |
| 刻印 | ビューが記す参照時点（どの正本の・いつの状態を見て書いたか） | スタンプ、タイムスタンプ |
| 現行 | いま有効な版（status=current/accepted） | 最新、現在、アクティブ、有効 |
| 非現行 | 現行でない版。廃止・置換・アーカイブ・提案中を一つに束ねた言い方（どれかは status が言う） | 失効（非現行の意味で「死んだ」と書かない。止まった process の意味の「死んだ」は使ってよい） |
| 履歴 | 過去の状態の記録 | 経緯、過去、来歴 |
| 廃止 | 方針を撤回した状態（status=deprecated） | 廃案、ボツ |
| 置換 | 後継で入れ替えた状態（status=superseded） | 差し替え（操作名としては可。状態名は置換） |
| アーカイブ | 証跡として倉庫へ退避した状態（status=archived） | 退役、保管 |
| 要求 | 文書または機能が存在してよい理由 | 要件、ニーズ |
| 依存 | 文書が他文書を前提とする関係（depends_on） | （リンクの意味の「参照」とは区別する） |
| 参照 | 文書から別文書への指し示し（リンク）。依存とは限らない | （依存と混同しない） |
| 孤児 | どの現行文書からも依存されない文書 | 浮き、迷子 |
| 逆孤児 | あるべき文書の不在。対応する仕様を持たない要求、対応する試験を持たない受入基準など。孤児の対称 | （逆孤児の意味で「抜け」「漏れ」と書かない。普通の日本語の「漏れる」「すり抜ける」は使ってよい） |
| ガード | 違反を機械的に拒否するHook | （ガードで統一） |
| リンタ | 文書を機械的に点検するスクリプト | （用語チェッカーはリンタの一機能） |
| 用語チェッカー | リンタのうち、未承認語と未定義語を弾く機能 | （上記で統一） |
| 起点 | いま編集器で開いている位置から決まる、帰結をたどり始める文書（ADR-012） | 基点、フォーカス（起点の意味で「選択」と書かない。選ぶ行いそのものは「選択」でよい） |
| 帰結 | 起点を変えたときに直すことになるものの集合（ADR-012） | 影響範囲、インパクト、波及先 |
| 波 | 起点からの距離で分けた帰結の段。第1波は起点に直接ぶら下がるもの（ADR-012） | レイヤ、階層、世代 |
| 明細 | 帰結を順に並べた一枚の一覧。図ではない（ADR-012） | リスト、一覧表、レポート |
| 記号 | 明細の各行の左端に置く一文字。何をすべきかを表す。五つに固定（ADR-012） | アイコン、マーク、バッジ |
| 指紋 | 印が囲む範囲の内容から取る sha256。範囲の中身が変われば変わる（刻印と混同しない。刻印は参照時点、指紋は内容） | ハッシュ、チェックサム、ダイジェスト |
| 循環 | 依存が閉じていて、どちらを先に直すか決まらない組（ADR-012） | ループ、サイクル、堂々巡り |
| 所見 | 上流の監査が挙げた一件。検査の名・重さ・文を持つ | （所見の意味で「指摘」と書かない。「警告」「エラー」は重さの語としてだけ使う） |
| 検査 | 上流の監査が走らせる判定の一つ | チェック、ルール、バリデーション |
| 統治木 | この体系が管理する文書の集まり。`doctrine_docs/` の実体 | ドキュメントツリー、文書ツリー |
| 範囲 | 印（`doctrine:begin`／`doctrine:end`）が囲むコードの行の連なり | ブロック、セクション、区間 |
| 上流 | 規則と判定の正本を持つ doctrine プラグイン | doctrine 側（上流の意味で「本体」「親」「コア」と書かない。拡張機能の Node 側・親プロセス・DDD のコアドメインはそれぞれ別の物である） |
| 画面 | 拡張機能が編集器に出す面（人が手で書くビューと混同しない） | パネル、UI、画面表示（画面の意味で `view` と書かない。英語の地の文の view、`webview`・`preview`・`doc-review`・`view.ts` は別の物である） |
| 門 | 壊れたら赤くなる仕掛け。試験・監査・写し・突然変異の総称（違反を拒む Hook であるガードと混同しない） | ゲート、関門 |
| 試験 | この製品が自分で書いた検証（上流の監査が走らせる検査と混同しない） | テスト、ケース、スイート |
| webview | 固有名 | |
| 影響するテスト | 固有名 | |
| エラー時挙動 | 固有名 | |
| 標準エラー | 固有名 | |

意味欄が「固有名」の行は、外部が付けた公式名である。禁止同義語の照合から外れる。
`webview` は VS Code の API 名、`標準エラー` は stderr の日本語名、
`影響するテスト`・`エラー時挙動` は**上流の登録簿が定める必須節の名**である。
節名は上流が正本であり、こちらの承認語で言い換えると必須節が無いと判じられる。
上流は同じ形を一度踏んで `選択肢` を手で例外に入れているが、登録簿から導いていない
（CHANGE-023。上流へ問題として出した）。

承認語に加えて、英語の比喩・構文・一語訳をなぞった表現も使わない。

| 使わない（カルク） | 直す | なぞった英語 |
|---|---|---|
| 同じページにいる | 認識を揃える | on the same page |
| テーブルの上にある | 検討中 | on the table |
| 針を動かす | 効果を出す | move the needle |
| 一日の終わりには | 結局 | at the end of the day |
| 〜を可能にする（過剰） | 〜できる | enable |
| 〜の文脈で（過剰） | 〜では／〜について | in the context of |
| 深く潜る／掘り下げる | 詳しく見る | deep dive |
| 予算（資源量の意味で） | 上限・割り当て | budget |
| ロールアップ | 統合・一本化 | roll up |

一語訳の罠（辞書の一番目を疑う）: status→位置づけ・区分、native→標準で・組み込みで、robust→壊れにくい、leverage→活かす。

定着した借用語（データ・リスク・JSON・YAML・CLI・HTML・URL・MIT・CI・LLM・BOM・CRLF・TF・IDF等）と普通の否定文はカルクではない。
