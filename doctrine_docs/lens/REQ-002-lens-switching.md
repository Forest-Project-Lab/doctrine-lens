# 一つの画面は一つの問いだけに答える

## 要求文

各画面は、答える問いを一つだけ持つ。**答えない問いを画面に明記する。**

問いが増えたときは、画面の中に切り替えの仕掛けを足すのではなく、**別の画面を作る**。

一つの画面の中に、「見え方を切り替える」ための操作子を置かない。
出す内容は入力（いま開いている場所と、上流が返す事実）から一意に定まる。

この要求が満たされたことは、次の三つで確かめる。

1. 画面に、表示の仕方を変えるための選択欄・釦が一つも無い。
2. 同じ入力に対して、常に同じ表示になる（利用者の設定によって見え方が分岐しない）。
3. 画面が、自分が答えない問いを文で述べている。

## 優先度

高。これを守らないと、問いが増えるたびに一枚が重くなり、
どの問いにも中途半端にしか答えない画面になる。実際に一度そうなった（ADR-012）。

## 出所

本書 §3.3.3。

```
一つの領域に複数の課題がある場合は、課題ごとに別のモデルを作ったほうがよいこともあるでしょう。
…一つの業務領域に一つのモデルという固定観念は持たないでください。
```
（『ドメイン駆動設計をはじめよう』§3.3.3 より。外の文なので一字も変えない。）

この要求は、以前は「同じ一枚の地図を四つのダイヤルで切り替える」「画面は増やさない」と
書いてあった。**出所と正反対の結論だった。** 出所は「課題ごとに別のモデルを作れ」と言っている。

Rich Hickey "Simple Made Easy" も同じことを別の言葉で言う。柔軟にするために選択肢を
足すのは easy（手近）であって simple（撚りが無い）ではない。
実際、旧実装では深度が配置と絞りの効きを決めており、「四つは互いに独立」という
要求文は嘘だった。仕様（旧 SPEC-003）はそれを自白してもいた——
「L1 に二つ置くのは、配置を独立したダイヤルとして成り立たせるためである」。
**独立して見せるために、意味のない選択肢を足していた。**
