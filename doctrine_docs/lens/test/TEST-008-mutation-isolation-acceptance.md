# 潰しの隔離の受入

## 受入基準への対応

SPEC-008 の受入基準の八項に一対一で対応させる。手立ては `tools/mutate-worktree.test.mjs` に
置く。**字面のレビューでは守れない性質なので、実物の git リポジトリを一時ディレクトリに
立てて実測する。**

| 確かめること | 手立て |
|---|---|
| 隔離木が作業木の外に立ち、対象 commit の中身を持つ | 見本のリポジトリを立てて隔離木を作り、場所と中身を見る |
| 隔離木を潰しても作業木が一バイトも動かない | 隔離木のファイルを書き換え、作業木の中身と状態の指紋が変わらないことを見る |
| 隔離木を消すと実体も git の登録も残らない | 消したあとに実体の有無と `worktree list` を見る |
| 走行が二つ重なると後の一つが潰しの前に失敗する | 錠を取った状態でもう一度取り、拒まれることを見る |
| 死んだ走行が残した錠を引き継げる | 錠の中の pid を生きていない値に書き換え、取り直せることを見る |
| 孤児の片づけが利用者の worktree に触らない | 利用者名義の worktree を立てて片づけを回し、残ることを見る |
| 孤児の片づけがいま走っている自分の隔離木に触らない | 自分の隔離木を作って片づけを回し、残ることを見る |
| 作業木の追跡下が動けば照合が捉える | 追跡下のファイルを書き換え、状態の指紋が変わることを見る |

## この試験が赤いときの意味

**利用者の作業木を壊しうる。** 守っている性質は「どの経路でも作業木が一バイトも動かない」
であり、ここが赤いということはその保証が無いということである。`npm run mutate` を回す前に
直すこと。

## 走らせ方

`npm test` に含める。`tools/*.test.mjs` の一つとして回る。編集器も束ねも要らない。

## 実物での確認

単体の試験に加えて、実物の走行で次を確かめた（2026-08-02、Node v22.22.3）。

| 見たこと | 結果 |
|---|---|
| `npm run mutate` の走行の前後で作業木の `git status` が変わらないこと | 一致 |
| 表の38件がすべて捕まること（隔離木の中で） | 38/38 |
| 走行のあとに隔離木の残骸が無いこと | `git worktree list` は作業木のみ、一時ディレクトリに残骸なし |
| 判定の履歴に「潰した木」が刻まれること | `潰した木: /tmp/doctrine-lens-mutate-…（隔離。作業木ではない）` |

## 覆わないもの

- 強制終了の直後に隔離木が残ること。次回起動が片づけることは単体の試験が見るが、
  「強制終了そのもの」は再現の対象にしない。
- 合否の判定。TEST-007 が受け持つ。
