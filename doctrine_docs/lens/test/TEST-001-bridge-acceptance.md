# 橋渡しの受入

## 受入基準への対応

SPEC-001 の受入基準の十項に一対一で対応させる。

| 確かめること | 手立て |
|---|---|
| 統治木が無いフォルダで不在が返る | 空のフォルダを作って解決を呼ぶ |
| 統治木があれば節点と辺が返る | 見本の統治木を組み、取得を呼ぶ |
| 未知の項があっても既知の項が変わらない | 上流の出力を模した値に未知の項を足して読ませる |
| 失敗しても直前の結果が保たれる | 終了コードが 0 でない状態を作り、保った値を見る |
| 規則の写しが実装に無い | `src/` の字面を走査し、型の一覧と status の語彙の不在を確かめる |
| 登録簿の並びが上流と一致する | `_registry` の原文から型の並びを取り出して突き合わせる |
| 統治木が二つ目以降のフォルダでも解決できる | 候補の集め方を、統治木を持つフォルダが後ろに在る一覧で確かめる |
| 覚えたフォルダが消えたら先頭へ落ちる | 候補に無い名を覚えた状態で選び直しを呼ぶ |
| 経路の突き合わせが Windows を吸収する | 区切りと大小文字を引数で与え、両方の環境を踏む |
| 速い拍で判定と判定の時刻が保たれる | 引き継ぎの規則（`carryAudit`）へ、速い拍・失敗した拍・判定が空で返った拍の三つを与えて結果を見る。あわせて session がその規則を自前で書き直していないことを字面で確かめる |

| 判定そのものが引き継がれる | 監査を飛ばした回のあと、所見と走らせた検査が前回の値のまま残ることを見る。時刻だけが進む形にならないこと |

## 退行観点

- 判定から導いたものだけを引き継がないこと。所見そのものを引き継がないと、
  保存のたびに画面が「壊れている 0」と言い、脚注が「0 検査を走らせた時刻」になる
  （ADR-008 の意図を ADR-017 が広げた）。

- `docs` という名のフォルダを、`_system` を持たないのに統治木と誤って認めないこと。
  上流の登録簿が定める判定であり、緩めてはならない。
- 統治木の不在を異常として扱わないこと。異常にすると、統治木を持たないプロジェクトで
  拡張機能が警告を出し続ける。
- 上流へ書き込む命令を呼ばないこと。呼ぶ命令は読み取り専用のものに限る。
- 「判定が取れていない」と「判定が取れて食い違いが無かった」を混ぜないこと。
  混ぜると、監査を一度も走らせていない状態で「指紋は一致している」と断定する。
- 取得が失敗した拍で判定の時刻だけを進めないこと。失敗した拍は直前に成功した結果が
  そのまま返るので、古い判定に新しい時刻が付き、帯が「いま確かめた」と嘘をつく。

## 合否基準

上表の十項がすべて通ること。一つでも落ちれば不合格とする。
規則の写しの走査は、型コードらしき大文字の並びと status の語彙の双方について行う。
