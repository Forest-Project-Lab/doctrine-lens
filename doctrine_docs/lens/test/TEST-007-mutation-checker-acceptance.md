# 潰しの検査器の合否の受入

## 受入基準への対応

SPEC-007 の受入基準の八項に対応させる。手立てはすべて `tools/mutate-verdict.test.mjs` に置く。
判定器を別ファイル（`tools/mutate-verdict.mjs`）へ出したのは、副作用を持つ実行スクリプトの
中では検査器自身を検められないためである。

| 確かめること | 手立て |
|---|---|
| 既定 reporter に依らず、落ちる試験を `試験が落ちた` と読む | 一時ディレクトリに落ちる試験を書き、reporter を `tap` に固定して回し、判定と名前を見る |
| 束ねが無い・読み込めないとき `検査器の異常` になる | 実在しない試験ファイルを指し、終了符号が非ゼロ・`not ok` が零件・判定が異常であることを見る |
| `signal` で死んだ走行が `検査器の異常` になる | `signal: "SIGKILL"` の四つ組を直に与え、判定と理由の文を見る |
| `status` 0 なのに `not ok` が在る矛盾が `検査器の異常` になる | その四つ組を直に与える |
| 自己点検の二つの canary が期待どおり判定される | `selfCheck()` が空の一覧（食い違いなし）を返すことを見る |
| 合否が `not ok` の件数でなく終了符号で決まる | 同じ本文で `status` だけ 1 と 0 に変え、判定が変わることを見る |
| `stderr` 側の `not ok` も名前として拾う | `stderr` にだけ `not ok` を置いた四つ組を与える |
| 通る試験を `試験は通った` と読む | 一時ディレクトリに通る試験を書いて回す |

## この試験が赤いときの意味

**`npm run mutate` の数字は無効である。** 判定器が壊れている走行の score は読めない
（SPEC-007 の「走り出す前の自己点検」と同じ理由）。先にここを緑にすること。

## 走らせ方

`npm test` に含める。`out/test/*.test.js` と併せて `tools/*.test.mjs` を回す。
判定器の試験は編集器も束ねも要らないので、`npm run build:test` の成否に依らず走る。

## 覆わないもの

- 潰す表が正しいこと（`to` が意味のある壊し方であること）。
  **ただし `from` が実在することと、全行が読まれていることは検める**（受入 9）。
- 覆う範囲が十分であること。`mutate-check.mjs` の頭注の但し書きのとおり、
  潰せるのは表に並べた行だけである。
- 隔離実行（作業木を汚さずに潰すこと）。別の決定が扱う。

## 実測の記録

この受入を作った時点（2026-08-02、Node v22.22.3）に観測した事実を残す。直した欠陥が
どういう形で現れていたかを、後から読めるようにする。

| 与えた状況 | 直す前の判定 | 直した後の判定 |
|---|---|---|
| 実在しない試験ファイルを指す（終了符号 非ゼロ、`not ok` 零件） | `試験は通った` | `検査器の異常` |
| 既定 reporter が端末で `spec` になる（終了符号 1、`not ok` 零件） | `試験は通った` | `検査器の異常` |
| 親が `node --test` の中（`NODE_TEST_CONTEXT` が伝播して reporter 指定が覆る） | `試験は通った` | `試験が落ちた`（環境を断って正しく読む） |

| 表の読み飛ばし | 表の一行の鍵の順を入れ替える、あるいは行内に注釈を置くと、「55 行のうち 54 行しか読めていない」で落ちることを見る |
| 複数行の from | 逆引用符で数行を跨ぐ `from` の字面を古くすると、「表が指す行が実在しない」で落ちることを見る |
| 未コミットの警告 | 作業木に差分が在る状態で走らせると、走行の始めにそれを告げることを見る |
