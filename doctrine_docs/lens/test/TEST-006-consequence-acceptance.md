# 帰結の明細の受入

## 受入基準への対応

**`SPEC-006` の受入基準の各項に、番号で一対一に対応させる。**
受入 N を検める単体試験の名は `006-N.` で始まる（同じ受入を複数の角度から見るときは
`006-Nb.` `006-Nc.` と枝番を付ける）。

**単体試験を持たない受入は、下の表で「画面側」と宣言する。** 宣言も試験も無い受入は、
`src/test/mutation-table.test.ts` の門が落とす。

| 受入 | 受け持ち |
|---|---|
| 1 | 画面側（`npm run test:integration`。編集器のカーソルから起点が決まること） |
| 10 | 画面側（`npm run preview`。`<svg>` の数を実物の画面で数える） |
| 11 | 画面側（`npm run preview`。280px で溢れないことを実物で測る） |
| 12 | 画面側（`src/test/design.test.ts`。`DESIGN.md` を正本として CSS を走査する） |

以下は番号を持つ受入の一覧である。

| 確かめること | 手立て | 編集器 |
|---|---|---|
| 何も選ばずに起点が決まる | 印を持つファイルの範囲内の行を渡し、起点の解決が文書の id を返すことを見る | 不要 |
| 波が起点からの距離ごとに分かれ、同じ波は「後ろに N」の降順 | 見本のグラフで波と順を組み、期待の並びと突き合わせる | 不要 |
| 依存と影響の両方で結ばれた隣が一行としてだけ出る | 相互のペアを持つ見本を与え、行が一つであることを見る | 不要 |
| `!` と `~` が別の記号・別の一文で出る | 依存だけの隣と影響だけの隣を与え、記号と文が違うことを見る | 不要 |
| 主文が題名、id は副文 | 題名の取得が返した値が主文に入ることを、画面の実物で見る | 画面 |
| 出していない件数が脚注に出る | 起点に繋がらない文書を含む見本を与え、脚注の数を見る | 不要 |
| 起点が無いとき、文で断り、いま開いているものの名前を挙げる | 起点なしの状態を作り、画面の文字列を見る | 画面 |
| 循環は波に入らず、一行の文字列として出る | 循環を含む見本を与え、波の割り当てと文字列を見る | 不要 |
| 上流の所見の文が一字も変わらずに出る | 偽の CLI に既知の文を返させ、画面の文字列と突き合わせる | 画面 |
| 画面に `<svg>` が一つも無い | 実物の画面を開き、`document.querySelectorAll("svg").length` を見る | 画面 |
| 幅 280px でどの操作要素も外へ出ない | 実物の画面を 280px に狭め、各要素の矩形が可視域に収まることを測る | 画面 |
| `DESIGN.md` の段に無い値が CSS に無い | 器の CSS を走査し、余白・角丸・書体・太さが表の値だけであることを見る | 不要 |

| 脚注の検査の数 | 上流の `checks_run` の長さと画面の数が一致する。実装に定数が無いことを字面で見る |
| 行の status と後継 | 非現行の行に status が出て、`superseded_by` が在れば後継の id が併記される |
| status に色を当てない | `.row .status` に `--vscode-charts-` が当たっていないことを CSS の字面で見る |

| 起点自身の所見 | 起点に error を付けた木で、起点の欄に記号と所見が出て「壊れている 0」と言わないことを見る |
| 「外」の定義 | 行に出ている所見を「画面のどこにも出ていない」に数えないことを見る |
| 記号の和 | 記号ごとの件数の和が、直すことになる文書の数に一致することを見る |
| 排他に負けた事実 | `×` に負けた「足りない」が、事実ごとの行に数として出ることを見る |
| 強連結成分 | 一巡に書き下せない成分（`A↔B, B↔C`）で、全員が数えられ件数が負にならないことを見る |
| 辿る向き | 起点が前提にしている文書の件数が、「繋がらない」と別の行に出ることを見る |
| 範囲の不在と未取得 | `ranges` が `null` の回に記号 `?` が当たらないことを見る |
| 直の辺 | 迂回路を名乗る行が、直の辺も在ることを言うのを見る |

| 画面に出た語の定義 | 辞書に在る語が画面に出たときだけ脚注に定義が出ることを見る。カルクの表が混ざらないことも見る |

| 出ていない所見の行き先 | 行き先の在る所見の id が脚注に出て押せること、属さない所見が別の行で数えられることを見る |

| 現行は語らない | 上流が現行と呼ぶ status の行に status が出ず、そうでない行に出ることを、両方向で見る |
| 現行の集合の出所 | 現行を示す語が実装の字面に無いことを見る（`REQ-003` の門が既に走査している 28 語） |
| 数が語を支える | 要約の「非現行 u」が、status の出ている行の本数に一致することを見る |
| 判じられない回 | 登録簿が取れない見本を与え、全行に status が出て「非現行 u」が出ないことを見る |
| 空と未取得の違い | 空の登録簿（現行が一つも無い）と、取れなかった登録簿（`null`）で、出る数が違うことを見る |
| 使わない値を取らない | 登録簿の写しの各項が、実装のどこかで使われていることを見る |
| 前提の行き先 | 「起点 ← A ← B」で、推移は 2 件と数で言い、直は A だけを名で出すことを見る |
| 前提が無い回 | 起点に流れ込む辺が無いとき、その脚注も行き先も出ないことを見る（説明だけが浮かない） |

## 退行観点

- 件数だけを出して読み手に手が無い状態を「隠していない」と呼ばないこと（ADR-019）。
- 属するかどうかを検査名で判じないこと。`doc_id` と `refs` だけを見る。

- どれが承認語かを実装が判じないこと。この木の辞書には表が二つ在り、字面はどちらも
  三列である。見分ける規則は上流の `_termcheck` が持つ（ADR-018）。

- **「取れなかった」を「無い」へ均す変換を、単体試験の届かない層に置かないこと。**
  `src/panel/` は `tsconfig.test.json` の外なので、そこに置くと突然変異の門も
  素通しする（実測。生き残った一件がこれだった）。
- 「取れなかった」を「既定だった」に化けさせないこと。登録簿が取れない回に status を
  隠すと、**全行が現行だと言ったことになる**（ADR-021 決定 3・ADR-017）。
- 既定を明細の分布から決めないこと。起点ごとに既定が変わると、同じ文書が画面ごとに
  違って見える。
- 消した語の件数を要約から落とさないこと。件数の無い空白は意味が導けない（ADR-014）。

- 知らないことを断定しないこと。取れていない値を「無い」と言わない。
- 一つの数に性質の違う二つを畳まないこと。
- 記号の排他を数の規律に持ち込まないこと（ADR-017）。

- **記号を増やさないこと。** 五つを超えたら、その記号がどの上流の事実から出るのかを
  SPEC-006 に書けているかを問う。書けないなら足してはならない。
- **上流の所見の文を書き直さないこと。** 要約・言い換え・整形をしない。
  上流の文は直し方まで書いた完成した日本語である。
- **`!` と `~` を同じ扱いにしないこと。** 上流が別の端として持つものを混ぜない。
- **相互のペアを二行にしないこと。** 同じ事実を二度描く実装は、
  利用者に「これは異常なのか」と問わせる（実際に問わせた）。
- **良い状態を空白で表さないこと。** 「0 件」を数で言う。空の画面を出さない。
- **意匠の値を実装に持たないこと。** `DESIGN.md` に無い寸法・色を書かない。
- **深度・レンズ・地図を戻さないこと。** ADR-012 の決定である。
  戻すなら新しい ADR で覆す。

## 合否基準

上表の十二項がすべて通ること。一つでも落ちれば不合格とする。

編集器を要する四項は `npm run test:integration` と `npm run preview` が受け持つ。
残りの八項は単体試験が受け持ち、`npm run mutate` の表に載せて
「潰せば試験が落ちる」ことを実測で守る。

- **数を出して行き先を出さないこと。** 「逆向きに辿らない」は理由であって行き先ではない
  （`ADR-019`。`CHANGE-016` で当てていなかった箇所が見つかった）。
- **推移の全部を並べないこと。** 実測で最大 43 件は 280px で読めない。
  直の一歩だけを名で出し、押せばそこからまた一歩辿れる形にする。
