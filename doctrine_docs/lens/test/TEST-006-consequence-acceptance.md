# 帰結の明細の受入

## 受入基準への対応

SPEC-006 の受入基準の十二項に一対一で対応させる。

| 確かめること | 手立て | 編集器 |
|---|---|---|
| 何も選ばずに起点が決まる | 印を持つファイルの範囲内の行を渡し、起点の解決が文書の id を返すことを見る | 不要 |
| 波が起点からの距離ごとに分かれ、同じ波は「後ろに N」の降順 | 見本のグラフで波と順を組み、期待の並びと突き合わせる | 不要 |
| 依存と影響の両方で結ばれた隣が一行としてだけ出る | 相互のペアを持つ見本を与え、行が一つであることを見る | 不要 |
| `!` と `~` が別の記号・別の一文で出る | 依存だけの隣と影響だけの隣を与え、記号と文が違うことを見る | 不要 |
| 主文が題名、id は副文 | 題名の取得が返した値が主文に入ることを、画面の実物で見る | 画面 |
| 出していない件数が脚注に出る | 起点に繋がらない文書を含む見本を与え、脚注の数を見る | 不要 |
| 起点が無いとき、文で断り、いま開いているものの名前を挙げる | 起点なしの状態を作り、画面の文字列を見る | 画面 |
| 循環は波に入らず、一行の文字列として出る | 循環を含む見本を与え、波の割り当てと文字列を見る | 不要 |
| 上流の所見の文が一字も変わらずに出る | 偽の CLI に既知の文を返させ、画面の文字列と突き合わせる | 画面 |
| 画面に `<svg>` が一つも無い | 実物の画面を開き、`document.querySelectorAll("svg").length` を見る | 画面 |
| 幅 280px でどの操作要素も外へ出ない | 実物の画面を 280px に狭め、各要素の矩形が可視域に収まることを測る | 画面 |
| `DESIGN.md` の段に無い値が CSS に無い | 器の CSS を走査し、余白・角丸・書体・太さが表の値だけであることを見る | 不要 |

## 退行観点

- **記号を増やさないこと。** 五つを超えたら、その記号がどの上流の事実から出るのかを
  SPEC-006 に書けているかを問う。書けないなら足してはならない。
- **上流の所見の文を書き直さないこと。** 要約・言い換え・整形をしない。
  上流の文は直し方まで書いた完成した日本語である。
- **`!` と `~` を同じ扱いにしないこと。** 上流が別の端として持つものを混ぜない。
- **相互のペアを二行にしないこと。** 同じ事実を二度描く実装は、
  利用者に「これは異常なのか」と問わせる（実際に問わせた）。
- **良い状態を空白で表さないこと。** 「0 件」を数で言う。空の画面を出さない。
- **意匠の値を実装に持たないこと。** `DESIGN.md` に無い寸法・色を書かない。
- **深度・レンズ・地図を戻さないこと。** ADR-012 の決定である。
  戻すなら新しい ADR で覆す。

## 合否基準

上表の十二項がすべて通ること。一つでも落ちれば不合格とする。

編集器を要する四項は `npm run test:integration` と `npm run preview` が受け持つ。
残りの八項は単体試験が受け持ち、`npm run mutate` の表に載せて
「潰せば試験が落ちる」ことを実測で守る。
