# 追跡索引の橋渡しの受入

## 受入基準への対応

SPEC-004 の受入基準の六項に一対一で対応させる。

| 確かめること | 手立て |
|---|---|
| 上流と同じ範囲の組が返る | このリポジトリで取得を呼び、上流の CLI の出力と突き合わせる |
| 統治外に挙げたパスの範囲が落ちる | `out/` 配下の範囲が結果に無いことを見る |
| 宣言を消すと範囲が現れる | 宣言を空にした設定を与えて同じ入力を通す |
| 範囲が失敗しても明細が組める | 範囲の取得だけを失敗させ、明細が組めることを見る |
| 指紋の突き合わせが実装に無い | `src/` の字面を走査し、指紋を比べる処理の不在を確かめる |
| 所見を検査名で絞らない | **偽のプラグイン**に追跡と追跡以外を混ぜた報告を返させ、すべてが届くことを見る。実樹を読まない（ADR-014） |
| 走らせた検査の数が届く | 上流の `AUDIT_CHECKS` を実行時に読み、橋が伝えた `checks_run` と突き合わせる |

| 範囲の未取得と不在を区別する | 範囲の取得だけを失敗させ、記号 `?`（直す場所が無い）が当たらないことを見る |
| 所見の六項が届く | 偽のプラグインの報告で `severity`・`check`・`path`・`refs` が落ちないことを見る |

## 退行観点

- 取れなかった範囲を空配列に潰さないこと。潰すと呼び手が「無い」と断定し、
  全部の行が「直す場所が無い」に化ける（ADR-017）。

- 指紋の突き合わせをこちらで始めないこと。上流の所見をそのまま読む。
  始めれば、上流が判定を変えたときに画面だけが古びる（ADR-005 が却下した案）。
- 印なしのコードを不足として鳴らさないこと。上流が既知の限界としている（doctrine 側 ADR 054）。
- 統治外の宣言の照合を、上流と違う規則にしないこと。
  末尾 `/` は前置き、それ以外は完全一致。理由の無い項目は成立しない。
- 範囲の取得の失敗を、グラフの取得の失敗に巻き込まないこと。
  行の `file:line` が出ないことと、明細が出ないことは別である。
- 所見を橋の上で絞らないこと。絞ると、上流が下した判断が画面へ届かない
  （34 件のうち 23 件を捨てていた。ADR-012 で改めた）。
- **この確かめを木の健康状態に依らせないこと。** 「追跡以外の所見が一件来た」で
  「絞っていない」を代弁させてはならない。木が緑になった日に、橋が正しいまま
  試験が赤くなる（ADR-014 が名指した破れ）。
- 検査の数を実装に定数で持たないこと。上流が増やしたとき追随しない側が正しくなる。

## 合否基準

上表の六項がすべて通ること。
統治外の宣言の試験は、宣言が有る場合と無い場合の両方で行い、
片方だけで通しても合格としない。
