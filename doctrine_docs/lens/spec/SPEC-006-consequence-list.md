# 帰結の明細

答える問いは一つだけである。

> これを変えたら、何を、どの順で直すことになるか。

俯瞰・構造・分類には答えない。答えないことを画面に書く。

## 入出力

### 入力

| 何 | 出所 | 使い方 |
|---|---|---|
| 起点 | 編集器で開いている位置 | 印が囲む範囲（`doctrine:begin`）から文書の id を引く。統治木の `.md` を開いているならその id |
| 節点と辺 | 上流 `dep-graph.py --classify-edges --json` | 波の距離と、各行の一文の材料 |
| 波及集合 | 上の辺を `depends_on` の逆向きに辿る | `!` の行。`--dependents ID --transitive` と同じ集合を、既に取ってある辺から引く（起点はカーソルで動くので、動くたびに子プロセスを起こさない） |
| 影響集合 | 上の辺を `impacts` の向きに辿る | `~` の行。出所は同じ |
| 足りないもの | 上流 `dep-graph.py --reverse-orphans` | `+` の行 |
| 所見 | 上流 `docs-audit.py --json` の `findings`（検査名で絞らない） | `×` の行と、脚注の「起点の外に所見 N 件」 |
| 走らせた検査 | 上流 `docs-audit.py --json` の `checks_run` | 脚注の検査の数。**数をこちらが持たない** |
| コード範囲 | 上流 `trace-index.py --format json` | 各行の子の行。零件なら `?` |
| 題名 | 上流 `dep-graph.py --json` の節点の `title` | 行の主文。id は副文へ落とす |

**上流の語彙をこちらが持たない。** 型の一覧も、検査の名前の一覧も、
`REQ→SPEC→IMPL→TEST` のような並びの表も持たない（REQ-003）。
並び順は「`depends_on` ∪ `impacts` の辺での最長距離」だけで決める。

最短距離ではない。`起点 → C → B` と `起点 → B` の両方があるとき、最短で並べると
B が第 1 波に出る。だが B は C 経由でも起点に依存しているので、C より先に B を
直すと前提が二度変わる。順を答える画面が、間違った順を答えることになる。

最長距離は循環があると定まらない。そこで循環（強連結成分）を一つの塊に畳む。
畳んだ図は必ず非循環なので、最長距離が全域で定まる。

### 出力

上から下へ読む一本の明細。次の四つを、この順で持つ。

1. **起点** — 記号（行と同じ規則）、題名（主文）、id・パス・状態・更新日（副文）、
   **起点自身に付いた所見**（行にならないので、ここに出さないと画面から消える）
2. **要約** — 四行。**数量の関係が画面から導ける形にする**（ADR-017）。

   ```
   直すことになる N 文書 ・ コード M か所
   × a ・ + b ・ ? c ・ ! d ・ ~ e          ← 五つの和が N に一致する
   既に壊れている p ・ 足りない q ・ 範囲が無い r ・ 非現行 u
   循環 s 本（t 文書）
   ```

   二行目は**記号ごと**、三行目は**事実ごと**である。記号は重い順に排他なので、
   `×` に負けた「足りない」は二行目の数から消える。**排他は一行にどれを出すかの
   規律であって、数の規律ではない。** 循環は文書の内数ではないので四行目に分ける。

   **どの数も、その事実の出所が取れていなければ出ない**（ADR-023）。
   所見が取れなければ `p` が消え、逆孤児が取れなければ `q` が、範囲が取れなければ
   `r` と一行目の「コード M か所」が消える。**0 と書くと「一つも無い」ことになる。**
   取れなかったことは、部分失敗の通知が別に言っている。

   **なぜ二行目と三行目が食い違うのかは、脚注で言う。** 要約の行に括弧で足すと、
   280px で要約が六行になり、数そのものが読みにくくなる（`DESIGN.md` 9-4）。
   **食い違っている回だけ出す**——一致している画面に置くと説明だけが浮く。

   `u`（非現行）は記号を争わない。記号は五つとも上流の別の事実から出ており、
   status はそのどれでもない。**この数は、行から消した語を支えるために在る**（ADR-021）。
   行に status が出るのは非現行のときだけなので、`u` は「status が出ている行の本数」に一致する。
   **上流の登録簿が取れず既定を判じられない回は、`u` を出さない**——
   代わりに全行に status を出す。数が出ないことと 0 は別である。
3. **波** — 第 1 波から順に。各波の見出しは名前ではなく**文**である
   （「第 2 波　第 1 波が済むまで確定しない」）。右端に件数を、**単位の語を付けて**置く
   （「2 文書」）。行の右端の数（「後ろに N」）と同じ位置に出るので、
   裸の数を二種類そこへ置くと、どちらがどちらか読めない
4. **脚注** — 隠した件数を**性質ごとに分けて**書く。上流の名前と走らせた検査の数と時刻。記号の語彙

   ```
   起点が前提にしている N 文書は出していない（この画面は逆向きに辿らない）。直に前提にしている M 件: ADR-012 · REQ-001
   帰結にも前提にも繋がらない M 文書は出していない
   起点に繋がらない P 文書に所見が付いている（開けば起点になる）: REQ-001 · TEST-002
   この画面の問いに属さない所見が K 件（どの文書にも紐づかない）
   行には最も重い記号だけが出るので、記号ごとの数と事実ごとの数は食い違う
   ```

   **数を出したら行き先も出す。行き先が無いなら、無いと言う**（ADR-019）。
   件数だけを出して読み手に手が無い状態を、「隠していない」と呼ばない。
   行き先は文書の id で、押せる。押すとその文書が開き、開けば起点になる。
   属するかどうかは `doc_id`（と `refs`）で判じる。**検査名を実装が持たない。**

   **画面に出た語の定義**を、木の用語辞書から引いて並べる（ADR-018）。
   出す語は「画面に実際に出た文字列と辞書の承認語を突き合わせて」決める。
   **語の一覧も、どれが承認語かの規則も、実装が持たない。**

   **一つの数に性質の違う二つを畳まない。** 「繋がらない」と一語で書くと、
   起点が前提にしているものまで「影響なし」と読まれる。実測で、48 文書の木の
   起点 `SPEC-005` では 43 件のうち 11 件が「前提」だった（ADR-017）。

   検査の数は上流 `docs-audit.py --json` の `checks_run` の長さである。
   **「全検査」のように数を代弁する語を数量の位置に置かない**（ADR-014）。

各行の形:

```
[ 記号 ][ 題名 ................ ][ id ][ status ][ 後ろに N ]
                                         ↑ 非現行のときだけ
          一文（なぜこの行が居るか）
          後継の id（superseded_by が在るときだけ）
          コード範囲（押すとその行へ跳ぶ）
```

`status` を行に出すのは、非現行が現行と交互に混ざるためである。実測で
`REQ-002` を起点に置くと 21 行のうち 4 件が非現行（`61a3775` の木で実測）で、
撤回して非現行になった文書が「直すことになるもの」の一覧に並ぶ（ADR-014）。

**現行のときは出さない**（ADR-021）。70 節点を順に起点に置いて出た 273 行のうち
非現行は 48 行（17.6%）であり、残る 225 行は読み飛ばすべき語を一つずつ持っていた。
混ざっていることが分かればよく、現行だと言う必要は無い。

**どの status を現行と呼ぶかは、この実装が決めない。** 上流の登録簿が返す
現行の集合と突き合わせる。上流はこの規則について
「他の切片はこれを使え。素の比較を書くな」と明記している（REQ-003）。

## 制約

- **`<svg>` を一要素も持たない。** 節点も辺も座標も持たない。
- **記号は五つに固定する。** 重い順に排他で `× > + > ? > ! > ~`。
  各記号はちょうど一つの上流の事実から出る。増やすときは、この仕様と `DESIGN.md` を直す。

  | 記号 | 意味 | 出所 |
  |---|---|---|
  | `×` | 既に壊れている | `docs-audit` の severity が error か warn の所見が、その文書に付いている |
  | `+` | 足りない | `--reverse-orphans` に載る |
  | `?` | 直す場所が無い | 帰結だが、結ばれたコード範囲が零件 |
  | `!` | 直す | `--dependents 起点 --transitive` に載る |
  | `~` | 見直す | `--impacts 起点` にだけ載る |

- **`!` と `~` を別の記号・別の文にする。** 上流は依存と影響を別の端として持ち、
  混ぜてはならないと定めている。方向を矢頭で運ばず、記号と文で運ぶ。
- **相互のペアを和で畳む。** `depends_on` ∪ `impacts` の集合として扱い、
  同じ事実を二度描かない。
- **自己循環を描かない。** 自分自身への辺は波の距離に数えない。
- **上流が書いた所見を、六項ともそのまま出す。** `check` / `severity` / `doc_id` /
  `path` / `refs` / `message`。書き直さない。要約しない。**どれかに潰さない**——
  `message` だけにすると `error` と `advisory` が同じ見え方になる。
- **知らないことを断定しない。** コード範囲が取れなかった回に「直す場所が無い」と
  出してはならない。取れていないことと、無いことは別である（ADR-017）。
- **迂回路だけを名乗らない。** 波は最長距離で決まるので、直の辺を持つ文書が
  後の波へ回る。その行に「X を経由して依存している」とだけ書くと、
  **存在する直の辺を無いことにする。** 両方を言う。
- **畳んだら必ず件数を書く。** 「起点に繋がらない N 文書は出していない」。
  隠すことは抽象ではない。
- **数を出したら行き先も出す。行き先が無いなら「無い」と言う**（ADR-019）。
  「出していない」とだけ書くと、読み手は「探せばどこかで出る」と読む。
  **前提も同じである。** 「逆向きに辿らない」は理由であって行き先ではない。
  推移の件数は数で言い、**直の一歩は名で言う**——押せばそこからまた一歩辿れる。
  実測で推移は最大 43 件（280px で読めない）、直は 92% の起点で 8 件以下である。
- **説明の無い数を置かない。** 行の右端の数が何を数えたものかを脚注で言う。
  型番が読めないのと同じ理由で、説明の無い数も読めない。
  数が一つも無いときは、その脚注も出さない（説明だけが浮く）。
- **数量の位置に、数を代弁する語を置かない。** 「全部」「すべて」を数の代わりにしない。
  数は上流が返した数か、こちらが数えた数である（ADR-014）。
- **非現行を隠さない。** 波の距離は非現行を経由して定まっていることがあるので、
  落とすと順序が変わる。出したうえで status を言う。
- **既定は語らず、外れたものだけを語る**（ADR-021）。ただし、語らなくてよいのは
  **要約にその件数が出ている属性だけ**である。件数の出ない属性を黙って落とすと、
  空白の意味が画面から導けない。
- **危うい変換を、試験の届かない層に置かない。** 「取れなかった（`null`）」を
  「無い（空）」へ均す仕事は、必ず単体試験が回せる層でやる。
  実測で、この変換を `src/panel/` に置いたところ**どの門も捕まえなかった**——
  そこは `tsconfig.test.json` の外である。模型へ移したら三つの試験が捕まえた（ADR-021）。
- **取れていない数を、その場に出さない**（ADR-023）。0 は「測って零だった」であり、
  取れていないことではない。**数が出せないなら、その数を出さない。**
  取れなかったことは、部分失敗の通知が別に言う。
- **取れていない事実を、記号の数と比べない。** `null !== 0` を食い違いと読むと、
  「記号は最も重い一つしか出ないから食い違う」という**誤った理由**が付く。
- **既定を判じられない回は、隠さない。** 上流の登録簿が取れなければ、
  どれが現行かをこちらは知らない。そのときは全行に status を出す。
  **隠す根拠が取れていないのに隠すのは、確かめていないことを言うのと同じである**（ADR-017）。
- **既定を明細の分布から決めない。** 「この画面で最も多い値」を既定にすると、
  起点を変えるたびに既定が変わり、同じ文書が画面ごとに違って見える。
  そして分布はこの画面が答えない問いである（NONGOAL-001）。
- **良い状態を空白で表さない。** 「壊れている 0 ・ 足りない 0 ・ 循環 0」と数で言う。
- **明細は必ず `file:line` で終わる。** 「要求から実装まで辿る」がそこで着地する。
- **起点を利用者に選ばせない。** 編集器で開いている位置から決める。
  選ぶ操作を画面に置かない。
- **語の意味を画面が書かない。** 木の用語辞書が正本である。辞書に無い語を
  画面が説明したくなったら、辞書へ足す（ADR-018）。
- **意匠の値を実装に持たない。** 寸法・色・書体・動きは `DESIGN.md` が正本である（ADR-013）。
- **書体の段を、族ごとに検める。** 比例の 13px と等幅の 12px は「隣り合う段」ではない。
  混ぜて検めると、**等幅で比例の段を使っても通る**（実測でそうなっていた。ADR-027）。
  **等幅は一段（12px）である**——`ADR-013` 決定 2 の「二段」は `ADR-027` が置き換えた。
- **深度を持たない。** この画面に段は無い。降りる操作も上がる操作も無い。

## エラー時挙動

| 事象 | 挙動 |
|---|---|
| 起点が無い（印の無いファイルを開いている） | 空の絵を出さず、**文で断る**。いま開いているものの名前を挙げ、なぜ起点にならないかを言う。木そのものの所見は起点に関わらず出す |
| 起点の文書がグラフに無い | 起点が無いものとして扱い、その旨を言う |
| 波及集合が空（誰もこの文書に依存していない） | 「直すものは無い」と数で言う。空の一覧を出さない |
| 循環に入っている文書がある | 波が決まらないので別枠に落とし、**循環を一行の文字列で書き下す**（`A → B → A`）。上流の `dep_cycle` の所見の文を添える |
| 上流の一部が取れない（登録簿・範囲・所見のいずれか） | 取れたところまでを出し、取れなかったものの名前と**理由の詳細**を出す。恒久的な設定の誤りと一時的な失敗を区別して伝える |
| 登録簿が取れない（現行の集合が分からない） | **全行に status を出す。** 要約の「非現行 u」は出さない。取れなかったことは上の行が既に伝えている |
| 所見が取れない | `×` を当てない。「既に壊れている p」を出さない。行に出す所見も無い |
| 逆孤児が取れない | `+` を当てない。「足りない q」を出さない |
| 範囲が取れない | `?` を当てない。「範囲が無い r」と「コード M か所」を出さない。**カーソルからは起点を引けないので、「起点が無い」ではなく「まだ分からない」と言う** |
| 走らせた検査の一覧が取れない | 時刻は出すが、検査の数は出さない。「0 検査」と言わない |
| 一度も監査していない | 帯に食い違いの数を出さない。「食い違い 0」と言わない |
| 題名が取れない | id を主文へ落とす。取れなかったことを脚注に書く |
| 節点が指す文書やコード範囲が既に消えている | 開けなかったことを必ず告げる。押しても何も起きない状態を残さない |

## 受入基準

1. 印が囲む範囲の中にカーソルがある状態で画面を開くと、**利用者が何も選ばずに**
   その範囲が指す文書が起点になる。
2. 帰結が、起点からの距離ごとに波へ分かれる。同じ波の中は「後ろに N」の降順に並ぶ。
3. `depends_on` と `impacts` の両方で結ばれた隣が、**一行としてだけ**出る
   （同じ事実が二行にならない）。
4. `!` の行と `~` の行が、別の記号と別の一文で出る。
5. 各行の主文が**題名**であり、id は副文に落ちている。
6. 出していないものの件数が脚注に出る。
7. 起点が無いとき、空の絵ではなく文が出て、いま開いているものの名前が挙がる。
8. 循環に入った文書は波に入らず、循環が一行の文字列として出る。
9. 上流の所見の文が、一字も変えずに出る。
10. 画面に `<svg>` 要素が一つも無い。
11. 幅 280px で、どの操作要素も画面の外へ出ない。明細の面が潰れない。
12. `DESIGN.md` の段に無い寸法・色が CSS に書かれていない。
13. 脚注の検査の数が、上流 `docs-audit.py --json` の `checks_run` の長さと一致する。
    実装がその数を定数で持たない。
14. 非現行の行に status が出て、`superseded_by` が在れば後継の id が併記される。
    **現行の行には status が出ない。** status に彩度のある色が当たっていない。

15. 起点自身に所見が付いていれば、起点の欄に記号と所見が出る。
    起点が壊れている木で「壊れている 0」と出ない。
16. 「画面のどこにも出していない所見」の件数が、実際に画面のどこにも出ていない件数と一致する。
    行に出ている所見をその数に含めない。
17. 記号ごとの件数の和が、直すことになる文書の数に一致する。
    記号に負けた事実（`×` に負けた「足りない」）も、事実ごとの行に数として出る。
18. 強連結成分の全員が数えられる。一巡に書き下せない要素が、行にも循環にも出ずに
    「届かない」件数へ化けない。件数は負にならない。
19. 起点が前提にしている文書の件数が、「繋がらない」と別の行で出る。
20. コード範囲が取れなかった回に、記号 `?` が当たらない。


21. 画面に出た語の定義が脚注に出る。出ていない語は出ない。辞書が取れなければ出さないだけで、明細は出る。


22. 出ていない所見が、行き先の在るものと無いものに分かれて出る。行き先の id が押せる。


23. どの status を現行と呼ぶかを実装が持たない。上流の登録簿が返した集合と突き合わせる。
24. 要約の「非現行 u」が、status の出ている行の本数に一致する。
    記号ごとと事実ごとが食い違う回だけ、その理由が脚注に出る。一致する回は出ない。
25. 登録簿が取れない回に、全行に status が出る。「非現行 u」は出ない
    （現行だと決めつけて隠さない）。**この判定が単体試験の届く層に在る。**
26. 上流から取っておいて実装のどこからも使わない値が、登録簿の写しに残っていない。
27. 迂回路だけを名乗る行が無い。直の辺も在るなら、両方を言う。
28. 取れていない事実の数を、要約が 0 と断定しない。取れていない数は、その場に出ない。
    取れていない事実を記号の数と比べて、誤った理由の脚注を出さない。
29. 検査の一覧が取れない回に「0 検査を走らせた」と言わない。取れていないと言う。
30. 範囲が取れていない回の案内が「起点が無い」ではない。
    **既に印を持つファイルを開いている利用者へ、「開け」と言わない。**
31. 上流が status を言っていない節点を「非現行」と数えない。
    要約の数と、status を出している行の本数が、そこでも一致する。
32. 起点が循環に落ちても、畳んだ件数の総和が節点の数に届く。
    起点を二重に引かない。
33. 前提の数を出したら、**直に前提にしているものの id も押せる形で出す**。
    推移の全部は並べない——直を押せば、そこからまた一歩辿れる。
    前提が無ければ、その脚注も行き先も出さない。
34. 写しの門が、**撮る前に前の走行の写しを消す**。撮り直さない写しを残さない。
    消した枚数を数で言う。
35. 起点が循環に落ちているとき、**成分の別の一員から来た行を「直の前提」と呼ばない**。
    直かどうかは、起点からの距離ではなく**辺の相手**で決まる。
36. 所見の跳び先が、**統治木を基準に**開く。範囲の跳び先は作業フォルダを基準に開く。
    上流は二つの座標系で相対パスを返すので、**どちらの基準かを一緒に運ぶ**。
37. 前提として名で出した文書を、同じ画面が「起点に繋がらない」と言わない。
    前提に付いた所見は、**別の行き先として件数と id を出す**。
38. 行の中の釦に焦点が在るとき、鍵盤の Enter と Space が**その釦を押す**。
    行の動作を代わりに起こさない。
39. 所見の六項（`check`・`severity`・`doc_id`・`path`・`refs`・`message`）が
    **画面に出る**。写す層が持っているだけでは足りない。
