# レンズ文法

## 入出力

入力は SPEC-002 が返す節点と辺の集合、およびレンズの値。出力は各節点の色と、描くか否かの判定。

レンズは四つのダイヤルの値の組である。ダイヤルの一覧の正本は ICD-001 にある。

### 色

節点の色を決める基準を一つ選ぶ。選べる基準は次のとおり。

| 基準 | 色の割り当て |
|---|---|
| 型 | 上流の節点が持つ `type` の値ごとに色を配る。既定 |
| status | 上流の節点が持つ `status` の値ごとに色を配る |
| ドメイン | 上流の節点が持つ `domain` の値ごとに色を配る |
| owner | 上流の節点が持つ `owner` の値ごとに色を配る |

L3 の節点はコード範囲であり、上流の節点の項を持たない。
L3 では色の基準が効かず、指紋が食い違う範囲だけを別の色で示す。

色の割り当ての順は次で決める。上流の登録簿がその基準の並びを持つなら、その並びを先に使う
（型なら型の登録順、status なら status の語彙の順）。登録簿に無い値は、残りを整列した順で後ろに続ける。
この順に固定の並びから色を配る。

登録簿の並びを先に使うのは、文書が一つ増えただけで既存の値の色が入れ替わるのを防ぐためである。
値の一覧をこのドメインが持たない点は変わらない。並びの正本は上流の登録簿にある。
登録簿が読めないときは全ての値を整列した順で配る。

### 絞り

描く節点を絞る条件を重ねて指定する。条件は互いに積で効く。

| 条件 | 効き方 |
|---|---|
| 現行のみ | 上流の節点が持つ `status` が現行を示す値の節点だけを描く |
| ドメイン | 選んだドメインに属する節点だけを描く |
| 型 | 選んだ型の節点だけを描く |

「現行を示す値」の判定は上流に委ねる。このドメインが status の語彙を持たない。

### 配置

| 方式 | 内容 |
|---|---|
| 地図 | 矩形として格子に並べる。矩形の大きさは属する節点の数で決まる |
| レーン | 型ごとの列に並べる。列の並び順は上流の型の登録順に従う |
| 詳細 | 焦点の文書を中央に、依存する先と依存される元を左右に並べる |
| 一覧 | 上から順に一列に並べる。行数の多い範囲ほど背を高くする |

深度ごとに使える方式と、その深度の既定は次のとおり。

| 深度 | 使える方式 | 既定 |
|---|---|---|
| L0 | 地図 | 地図 |
| L1 | レーン・地図 | レーン |
| L2 | 詳細 | 詳細 |
| L3 | 一覧 | 一覧 |

使える方式が深度ごとに一つだけなら、配置はダイヤルではなく深度の従属物になる。
L1 に二つ置くのは、配置を独立したダイヤルとして成り立たせるためである。

効かない組み合わせを選んだときは、その深度の既定の方式に落とす。落とすだけで、
覚えている値は書き換えない。深度を戻せば元の方式が再び効く。これにより
「深度を変えても配置の値が変わらない」（REQ-002）と「深度ごとに使える方式が違う」を両立させる。

### 深度

SPEC-002 が定める四つの段。

## 制約

- 四つのダイヤルは互いに独立である。一つを変えても他の三つの値は変わらない。
- 色の基準・絞りの条件・配置の方式のいずれも、値の一覧をこのドメインが持たない。
  上流の節点が実際に持つ値から集める。
- 絞りで全ての節点が消えたとき、空である旨を示す。絞りを勝手に緩めない。
- レンズの値の組は名前を付けて保存でき、保存した組を選ぶと同じ表示に戻る。
- 保存したレンズは作業フォルダごとに保つ。

## エラー時挙動

| 事象 | 挙動 |
|---|---|
| 色の基準が上流の節点に無い項を指す | その節点を「値なし」の色で描く。落とさない |
| 絞りが指すドメインや型がグラフに無い | 節点が無いものとして扱い、空である旨を示す |
| 効かない深度と配置の組み合わせ | その深度の既定の方式に落とす。異常として扱わない |
| 保存したレンズが読めない | 既定のレンズで開き、読めなかった旨を示す |

## 受入基準

1. 四つのダイヤルのうち一つを変えたとき、残る三つの値が変わらない。
2. 上流が未知の `type` の値を返したとき、その節点にも色が付く。
   またそのとき、登録簿が知る型に配られた色が変わらない。
3. 「現行のみ」を選ぶと、現行でない節点が描かれない。
4. 絞りで全ての節点が消えたとき、空である旨が示され、絞りの値が保たれる。
5. レンズに名前を付けて保存し、別のレンズへ移ったのち保存した名前を選ぶと、四つの値が保存時と一致する。
6. 効かない深度と配置の組み合わせを選んでも例外が出ず、既定の方式で描かれる。

## 実装の指紋

この仕様を実装している範囲は、コード側で `doctrine:begin SPEC-003` と
`doctrine:end SPEC-003` の対に囲んである。範囲の中身が変われば指紋が変わり、
監査が `trace_stale` を警告として挙げる。実装を直したら
doctrine プラグインの `trace-index.py` で取り直す。
