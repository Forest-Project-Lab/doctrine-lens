# 潰しの検査器の合否

`tools/mutate-check.mjs` が、潰した一行に対して「試験が捕まえたか」を判ずる規則である。
判ずる根拠は試験processの終了符号であり、吐かれた行の照合ではない（ADR-015）。

## 入出力

### 入力

| 何 | 出所 | 使い方 |
|---|---|---|
| 型検査の終了符号 | `npx tsc -p tsconfig.test.json` | 非ゼロなら潰し方が不正と判ずる |
| 四つ組 `(status, signal, stdout, stderr)` | `node --test-reporter=tap --test <束ね>` の子process | 合否の唯一の根拠 |
| `failed` | `stdout` と `stderr` を繋いだ文字列に `^not ok \d+ - (.+)$` を当てた一致 | **人へ見せる補助のみ。** 合否には使わない |
| 対象の commit | `git rev-parse HEAD` | 報告に刻む |
| Node の版 | `process.version` | 報告に刻む |

reporter は `tap` で固定する。既定に委ねない。既定は吐き出す先が端末か否かと Node の版で
変わり、変わると判定の根拠が動く。

### 投影

走行の最後に、次を刷る。判定が何の上に載っていたかを後から誰でも読めるようにする。

- 判定ごとの一行（捕まえた／守られていない／潰し方が不正）
- 守られていない直しの一覧と、潰し方が不正な行の一覧
- Node の版・reporter（固定値 `tap`）・試験コマンドの全文・対象の commit

## 判定

| 状況 | 判定 |
|---|---|
| 型検査が非ゼロ | `型検査が落ちた` |
| `signal` が非 null | `検査器の異常` |
| `status` が 0 かつ `failed` が空 | `試験は通った` |
| `status` が 0 かつ `failed` が非空 | `検査器の異常` |
| `status` が非ゼロかつ `failed` が非空 | `試験が落ちた` |
| `status` が非ゼロかつ `failed` が空 | `検査器の異常` |

最後の行が要である。非ゼロで `not ok` が無いのは、reporter の差・束ねの読み込み失敗・
timeout・足場の故障のいずれかである。**これを `試験は通った` に寄せてはならない**
（寄せると、守られている直しを「守られていない」と報告し、baseline では赤い木を緑と読む）。

## 制約

1. 合否は `status` と `signal` だけで決める。`failed` の件数で決めてはならない。
2. reporter を実行側が明示する。既定 reporter に判定を委ねない。
3. `検査器の異常` を握りつぶして走り続けてはならない。判定器が壊れている走行の数字は読めない。
4. 自己点検（下節）を通らない走行では、表の件数も score も刷らない。
5. 潰しは一件ずつ当て、一件ごとに元へ戻す。同時に二箇所を潰さない。
6. この道具は遅いので `npm run check` には入れない（頭注のとおり）。

## エラー時挙動

| 何が起きたか | どうするか | 終了符号 |
|---|---|---|
| 自己点検の canary が期待と違う判定になる | baseline へ進まず、理由を刷って止める | 2 |
| baseline が `試験は通った` でない | 先に全件を緑にせよと刷って止める | 2 |
| 潰す対象の行が見つからない | その一行を「潰し方が不正」に積み、次へ進む | 最後に 1 |
| 一行の判定が `検査器の異常` | **直ちに止める。**元へ戻し、`status`・`signal`・繋いだ文字列の先頭を刷る | 2 |
| 守られていない直しが在る | 一覧を刷る | 1 |
| 潰し方が不正な行が在る | 一覧を刷る | 1 |
| すべて捕まえた | 件数を刷る | 0 |

`検査器の異常` だけが走行を途中で止める。それ以外は最後まで走らせ、終わりに非ゼロで報せる。

## 走り出す前の自己点検

score を出す資格を、走る前に検める。一時ディレクトリ（利用者のリポジトリの外）に
canary を二つ書き、上の判定を通す。

| canary | 期待する判定 |
|---|---|
| 必ず落ちる試験一件 | `試験が落ちた`（かつ `failed` が一件） |
| 必ず通る試験一件 | `試験は通った` |

どちらかが期待と違えば、baseline へ進まず終える。判定器が自分を検められない状態で
数字を出さないことが、この節の目的である。

## 受入基準

1. 既定 reporter が何であれ、意図的に落ちる試験を `試験は通った` と読まない。
2. 束ねが存在しない・読み込めないとき、`試験は通った` ではなく `検査器の異常` になる。
3. `signal` で死んだ走行が `検査器の異常` になる。
4. `status` が 0 なのに `not ok` が在る矛盾が `検査器の異常` になる。
5. 自己点検の二つの canary が期待どおり判定される。
6. 自己点検が失敗した走行では、表の件数も score も刷られない。
7. 報告に Node の版・reporter・試験コマンド・対象 commit が刻まれる。
8. `検査器の異常` が起きた走行は非ゼロで終わる。

9. **表を読む門が、読めた行数と表の行数の一致を検める。**
   読み飛ばした行は検められないので、読み飛ばしを黙って許さない。

   実測で、表を読む正規表現が `from: (.+)` だったため**複数行のテンプレート
   リテラルを跨げず、55 行のうち 2 行を黙って読み飛ばしていた。**
   その 2 行は字面が古びても咎められず、走行の途中で「対象不明」として初めて出た
   （20 分後）。**門が読めていない範囲は、門が緑でも守られていない**（ADR-017）。

10. 走行の始めに、作業木に未コミットの変更が在れば、それを告げる。
    この道具は commit から隔離木を立てるので、**検めているのは手元の版ではない。**
    頭注に書いてあっても走行中には読まれない。

## 覆わないもの

潰す表が正しいこと、覆う範囲が十分であることは、この仕様の対象ではない。
自己点検が検めるのは判定器だけである（ADR-015 の保証限界）。

ただし**表が読めていること**は覆う（受入 9）。
「表の行が正しいか」は覆わないが、「表の行が読まれているか」は覆う。
読まれていない行は、正しいかどうか以前に検められていない。

## 実装の指紋

この仕様を実装している範囲は、コード側で `doctrine:begin SPEC-007` と
`doctrine:end SPEC-007` の対に囲んである。範囲の中身が変われば指紋が変わり、
監査が `trace_stale` を警告として挙げる。実装を直したら
doctrine プラグインの `trace-index.py` で取り直す。

| 範囲 | 何 |
|---|---|
| `tools/mutate-verdict.mjs` | 四つ組の取得・判定・自己点検 |
| `tools/mutate-check.mjs` | 走らせるもの・報告・異常での停止 |
