# doctrine CLI への橋渡し

## 入出力

### 統治木の解決

入力は作業フォルダの一覧。出力は見る統治木一つ、または不在を示す値。

一つの作業フォルダについての解決は上流の登録簿に合わせる。`doctrine_docs` が在れば統治木とする。
`docs` は `_system` を直下に持つ場合だけ統治木とする。

作業フォルダが複数のときは、統治木を持つものを全て候補として集め、そのうち一つを選ぶ（ADR-006）。
選び方は、利用者が明示に選んだフォルダを先に、無ければ候補を整列した順の先頭とする。
覚えたフォルダが候補から消えていたら先頭へ落ちる。候補が空なら不在を返す。

設定 `doctrineLens.docsRoot` が作業フォルダの外を指す値のときは、統治木が無いものとして扱う（ADR-010）。
黙って外を読まない。

### 起動と設定の scope

拡張機能はどの作業フォルダでも起動する（ADR-011）。統治木が無ければ上流の CLI を一つも呼ばず、
状態の帯に理由を出して終わる。統治木が根直下に無い構成でも設定が効くようにするためである。

実行体を選ぶ設定（`pythonPath`・`pluginPath`）は作業フォルダから上書きさせない（ADR-010）。
上書きできると、リポジトリを開いて信頼しただけで任意の実行体が走る。

### 経路の突き合わせ

上流は作業フォルダからの相対・`/` 区切りで返す。編集器は環境ごとの区切りで持つ。
突き合わせは一箇所に集める。区切りを `/` に揃え、Windows と macOS では大小文字を区別しない。
区別する環境で潰すと、大小違いの別ファイルが同じに見える。

### プラグイン実体の解決

入力は無い。出力は doctrine プラグインの実体パス、または不在を示す値。

解決は既存の `tools/doctrine-path.mjs` と同じ順に従う。導入台帳の `installPath` を先に見て、
無ければキャッシュ配下の最も新しい版のうち `.orphaned_at` を持たないものを選ぶ。

### 登録簿の取得

入力はプラグインの実体パス。出力は型の登録順・現行を示す status の値・status の語彙の全体・投影の型の四つ。

上流の `_registry` をその場で読んで得る。読んだ値を保存しない。
この取得があるため、このドメインは型と status の語彙を自身の中に持たずに済む。

```
<python> -c "<_registry を読んで JSON を出す短い問い合わせ>"
```

`_registry` は標準ライブラリだけを使い、読み込みに副作用を持たない。

### グラフの取得

入力は統治木の絶対パス。出力は上流が出す `classify-edges` の JSON をそのまま写した値。

実行する命令は次の一つだけである。

```
<python> <plugin>/scripts/dep-graph.py --root <統治木> --classify-edges --json
```

受け取る形は上流が定める。このドメインは `nodes` と `edges` の各項を読むが、
知らない項が増えても落とさず素通しする。

## 制約

- 型・status・置き場所・依存の可否を、この橋渡しの中で判定しない。判定済みの結果だけを読む。
  取得を上流の CLI に委ねる決定は ADR-001 にある。
- 上流の命令は読み取り専用のものだけを呼ぶ。統治木へ書き込む命令を呼ばない。
- 実行は逐次でなく並行してよいが、同じ統治木に対する取得は同時に一つに束ねる。
- 取得は二つの拍を持つ（ADR-008）。速い拍は登録簿・グラフ・範囲、遅い拍はそれに監査を足す。
  監査を飛ばした回は、前回の判定と、それを取った時刻をそのまま保つ。判定の時刻を画面に持つ。
- 使う `python` は設定 `doctrineLens.pythonPath` から取る。既定は `python3`。
- 標準出力だけを JSON として読む。標準エラーは診断のために保つが、解析の対象にしない。

## エラー時挙動

設定そのものが受け付けられない場合は、取得の失敗と分けて伝える（取り直しても直らない）。
実行体の在処を指す設定（`pythonPath`・`pluginPath`）は、絶対パス・`~/` から始まる値・
区切りを含まない命令名の三つだけを受ける。二つの設定で規律を分けてはならない。
片方だけ塞いでも、もう片方から同じことができる（ADR-010）。
待ち時間の設定（`timeoutMs`・`auditDebounceMs`）も同じく丸める。
待ち時間は使う直前に丸める。負だと子プロセスの起動が同期的に例外を投げ、
32bit を超えると実行環境が 1 ミリ秒へ潰す（あらゆる取得が数ミリ秒で「時間切れ」になり、
しかも案内は設定した値をそのまま刷るので嘘をつく）。


| 事象 | 挙動 |
|---|---|
| 統治木が無い | 地図を出さず、統治木が無い旨と初期化の手順を画面に示す。異常として扱わない |
| プラグインが無い | 導入の手順を画面に示す。異常として扱わない |
| `python` が起動しない | 設定 `doctrineLens.pythonPath` の確認を促す。原因の標準エラーを添える |
| 終了コードが 0 でない | 標準エラーを添えて失敗を示す。前回取得できた地図が在ればそれを保ち、消さない |
| 標準出力が JSON として読めない | 失敗を示し、先頭の一部を診断に添える。前回の地図を保つ |
| 取得が既定の時間を超える | 実行を打ち切り、超過を示す。前回の地図を保つ |
| 登録簿が読めない | 語彙に依る表示（現行の絞り・レーンの並び）を止め、他の表示は続ける。異常として扱わない |

いずれの場合も例外を画面の外へ出さない。取得の失敗で拡張機能が停止してはならない。

## 二つの拍のあいだで引き継ぐもの

監査を飛ばした回は、**判定そのもの**を引き継ぐ（ADR-008・ADR-017）。

引き継ぐのは次の四つで、**必ず同時に動かす**。

| 引き継ぐもの | なぜ |
|---|---|
| 判定を取った時刻 | 古い判定に新しい時刻が付くと「いま確かめた」と嘘をつく |
| 指紋が食い違う文書の id | 帯と見出しが使う |
| **上流が返した所見そのもの** | これを落とすと、保存のたびに画面が「壊れている 0」と言う |
| **上流が走らせた検査の名** | これを落とすと、脚注が「0 検査を走らせた時刻」になる |

**判定から導いたものだけを引き継がない。** 以前は id だけを引き継いでいて、
所見そのものは落ちていた。時刻だけが残るので、画面は起きていないことを述べていた。

## 受入基準

1. 統治木を持たないフォルダで取得を呼ぶと、不在を示す結果が返り、例外が投げられない。
2. 統治木を持つフォルダで取得を呼ぶと、`nodes` と `edges` を持つ値が返る。
3. 上流の出力に未知の項を足しても、取得は成功し、既知の項の値が変わらない。
4. 終了コードが 0 でないとき、直前に成功した取得の結果が保たれる。
5. 実装のどこにも型の一覧・status の語彙・置き場所の対応表が書かれていない。
6. 登録簿の取得が、上流の `_registry` が持つ型の一覧と同じ並びを返す。
7. 作業フォルダが複数で、統治木が二つ目以降に在るときも解決できる。
8. 覚えたフォルダが候補から消えたとき、例外を出さず先頭へ落ちる。
9. 経路の突き合わせが Windows の区切りと大小文字を吸収する。
10. 速い拍で取り直したとき、前回の判定と判定の時刻が保たれる。
