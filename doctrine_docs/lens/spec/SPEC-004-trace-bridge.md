# 追跡索引への橋渡し

## 入出力

### 範囲の取得

入力は作業フォルダと統治木の絶対パス。出力は上流が出す `trace-index/1` の JSON を写した値。

```
<python> <plugin>/scripts/trace-index.py --root <作業フォルダ> --docs-root <統治木> --format json
```

返る `ranges` の各項は、文書の id・ファイルのパス・始まりの行・終わりの行・範囲の指紋を持つ。
行の番号は 1 から数える。

この問い合わせの入口は、上流 ICD 002 が `trace-index-api` として宣言している
（v0.10.0、commit `8cd29bd`。書式の詳細な正本は上流 SPEC 026）。宣言によれば
`ranges` の各項はちょうど五項 `{id, path, begin_line, end_line, fingerprint}` であり、
`root` には名前だけが載る。この橋が写す形はその宣言と同じである。

### 所見の取得

入力は作業フォルダの絶対パス。出力は上流が出す `docs-audit/1` の JSON を写した値。

```
<python> <plugin>/scripts/docs-audit.py --root-from <作業フォルダ> --json --fail-on never
```

**所見は絞らずに、そのまま呼び手へ渡す**（ADR-012 で改めた）。
あわせて、上流が**実際に走らせた検査の一覧**（`checks_run`）も渡す（ADR-014）。

以前は検査名が `trace` で始まるものだけを通していた。34 件のうち 11 件である。
残る 23 件は上流が既に下した判断で、それを橋の上で捨てていた。捨てた結果、
画面は事実しか言えず、判断は読み手に残った。利用者の
「依存されているから何？」は、その帰結である。

追跡に関わるものだけが要る呼び手（帯・見出し）は、受け取ってから
`traceFindings` を通す。絞るのは呼び手の仕事であって、橋の仕事ではない。

**所見は六項をそのまま渡す。** `check` / `severity` / `doc_id` / `path` / `refs` / `message`。
どれかに潰さない。潰すと `error` と `advisory` が同じ見え方になる（ADR-017）。

**範囲が取れなかったときは、空ではなく「取れていない」を返す。**
空配列で返すと、呼び手は「本当に範囲が無い」と区別が付かず、
全部の行に「直す場所が無い」を当ててしまう。実測でそうなった。

**検査の数を実装が持たない。** 上流の報告の `checks_run` の長さをそのまま運ぶ。
定数で持つと、上流が検査を増やしたときに追随しない側が正しいことになる（REQ-003）。
画面はこの数を脚注に出す（`SPEC-006`）。

### 事実と判定を分ける

範囲の在処は `trace-index.py` から取り、指紋の食い違いの判定は `docs-audit.py` の
所見から取る。**このドメインは指紋を突き合わせない。**

理由は二つある。第一に、指紋を記録する節の書式と突き合わせの規則は上流が定めるものであり、
写せば REQ-003 の破れになる。第二に、`trace-index.py` は `--fail-on` を持たず、判定を返さない。
判定を返すのは監査だけである。

### 統治外の宣言の適用

`trace-index.py` は統治木の設定を読まない。ただし上流 0.8.0 から **git に訊く**ので、
`.gitignore` された場所（生成物の `out/`・`dist/` など）の範囲は返らない。

以前は `.gitignore` と同じ内容を `trace_exempt` へ二重に書いていた。
上流が答えたのでその二行は落とした（ADR-020）。`trace_exempt` は
「git には入れるが統治の対象にしない」ためのものとして残る。
そのため、このドメインが `<統治木>/_system/.context-config.json` の `trace_exempt` を読み、
そこに挙がったパスの範囲を落とす。

照合の規則は上流と揃える。末尾が `/` のパスは前置きの一致、それ以外は完全一致とする。
理由の無い項目は宣言として成立しないものとして読み飛ばす。

これは上流の照合規則をこちら側に写す唯一の箇所である。`trace-index.py` が
絞り込んだ範囲を返す手段を持たないため、他に方法が無い。
上流がその手段を備えたら、この写しを捨ててそちらへ寄せる。

## 制約

- 呼ぶのは読み取り専用の命令だけである。
- 範囲の取得と所見の取得は、グラフの取得と同じ束ねの中で行う。三つを別々に走らせない。
- 範囲の取得に失敗しても、グラフの取得が成功していれば明細は描く。行の `file:line` だけが消える。
- 所見の取得に失敗しても、範囲が取れていれば明細は描く。`×` の記号だけが出なくなる。
- 行の番号は上流が返した値をそのまま使う。数え直さない。

## エラー時挙動

| 事象 | 挙動 |
|---|---|
| 範囲の取得が失敗する | 取れなかったことを名前と理由つきで出す。明細そのものは今までどおり出る |
| 所見の取得が失敗する | 食い違いの表示を止める。範囲の表示は続ける |
| 設定が読めない・壊れている | 統治外の宣言が無いものとして扱う。全ての範囲を返す |
| 範囲が指すファイルが無い | その範囲を選んでも開けない旨を示す。他の範囲は開ける |
| 範囲の行が実ファイルの行数を超える | ファイルの末尾へ寄せて開く。異常として扱わない |
| 文書に結ばれた範囲が一つも無い | 覆いが無い旨を示す。異常として扱わない |

## 受入基準

1. 範囲の取得が、上流の `trace-index.py` が返す範囲と同じ組を返す。
2. `trace_exempt` に挙げたパスの配下の範囲が、取得の結果に含まれない。
3. `trace_exempt` の項目を消すと、その配下の範囲が結果に現れる。
4. 範囲の取得が失敗しても、グラフの取得が成功していれば明細が組める。
5. 指紋の食い違いの判定が、実装のどこにも書かれていない（上流の所見をそのまま読む）。
6. 上流が返した所見が、検査名で絞られずに呼び手へ届く。
   **確かめ方は木の健康状態に依らない**（ADR-014）。偽のプラグインに
   追跡と追跡以外を混ぜた報告を返させ、すべてが届くことを見る。
   この木の所見が 0 件になっても判定が変わらないこと。
7. 上流が走らせた検査の一覧が呼び手へ届き、その長さが上流の `AUDIT_CHECKS` と一致する。
   実装がその数を定数で持たない。

`doctrine:end SPEC-004` の対に囲んである。範囲の中身が変われば指紋が変わり、
監査が `trace_stale` を警告として挙げる。実装を直したら
doctrine プラグインの `trace-index.py` で取り直す。
