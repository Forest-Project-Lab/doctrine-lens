# 追跡索引への橋渡し

## 入出力

### 範囲の取得

入力は作業フォルダと統治木の絶対パス。出力は上流が出す `trace-index/1` の JSON を写した値。

```
<python> <plugin>/scripts/trace-index.py --root <作業フォルダ> --docs-root <統治木> --format json
```

返る `ranges` の各項は、文書の id・ファイルのパス・始まりの行・終わりの行・範囲の指紋を持つ。
行の番号は 1 から数える。

### 所見の取得

入力は作業フォルダの絶対パス。出力は上流が出す `docs-audit/1` の JSON を写した値。

```
<python> <plugin>/scripts/docs-audit.py --root-from <作業フォルダ> --json --fail-on never
```

このスライスで読むのは `findings` のうち検査名が `trace` で始まるものだけである。
残りの検査の表示は、このスライスの対象外である。

### 事実と判定を分ける

範囲の在処は `trace-index.py` から取り、指紋の食い違いの判定は `docs-audit.py` の
所見から取る。**このドメインは指紋を突き合わせない。**

理由は二つある。第一に、指紋を記録する節の書式と突き合わせの規則は上流が定めるものであり、
写せば REQ-003 の破れになる。第二に、`trace-index.py` は `--fail-on` を持たず、判定を返さない。
判定を返すのは監査だけである。

### 統治外の宣言の適用

`trace-index.py` は統治木の設定を読まない。生成物（`out/`・`dist/`）に印が写った範囲まで返す。
そのため、このドメインが `<統治木>/_system/.context-config.json` の `trace_exempt` を読み、
そこに挙がったパスの範囲を落とす。

照合の規則は上流と揃える。末尾が `/` のパスは前置きの一致、それ以外は完全一致とする。
理由の無い項目は宣言として成立しないものとして読み飛ばす。

これは上流の照合規則をこちら側に写す唯一の箇所である。`trace-index.py` が
絞り込んだ範囲を返す手段を持たないため、他に方法が無い。
上流がその手段を備えたら、この写しを捨ててそちらへ寄せる。

## 制約

- 呼ぶのは読み取り専用の命令だけである。
- 範囲の取得と所見の取得は、グラフの取得と同じ束ねの中で行う。三つを別々に走らせない。
- 範囲の取得に失敗しても、グラフの取得が成功していれば地図は描く。L3 だけが使えなくなる。
- 所見の取得に失敗しても、範囲が取れていれば L3 は描く。食い違いの表示だけが止まる。
- 行の番号は上流が返した値をそのまま使う。数え直さない。

## エラー時挙動

| 事象 | 挙動 |
|---|---|
| 範囲の取得が失敗する | L3 へ降りられない旨を示す。L0 から L2 は今までどおり使える |
| 所見の取得が失敗する | 食い違いの表示を止める。範囲の表示は続ける |
| 設定が読めない・壊れている | 統治外の宣言が無いものとして扱う。全ての範囲を返す |
| 範囲が指すファイルが無い | その範囲を選んでも開けない旨を示す。他の範囲は開ける |
| 範囲の行が実ファイルの行数を超える | ファイルの末尾へ寄せて開く。異常として扱わない |
| 文書に結ばれた範囲が一つも無い | 覆いが無い旨を示す。異常として扱わない |

## 受入基準

1. 範囲の取得が、上流の `trace-index.py` が返す範囲と同じ組を返す。
2. `trace_exempt` に挙げたパスの配下の範囲が、取得の結果に含まれない。
3. `trace_exempt` の項目を消すと、その配下の範囲が結果に現れる。
4. 範囲の取得が失敗しても、グラフの取得が成功していれば地図が描ける。
5. 指紋の食い違いの判定が、実装のどこにも書かれていない（上流の所見をそのまま読む）。
6. 所見のうち検査名が `trace` で始まらないものを、このスライスは読まない。

## 実装の指紋

この仕様を実装している範囲は、コード側で `doctrine:begin SPEC-004` と
`doctrine:end SPEC-004` の対に囲んである。範囲の中身が変われば指紋が変わり、
監査が `trace_stale` を警告として挙げる。実装を直したら
doctrine プラグインの `trace-index.py` で取り直す。
