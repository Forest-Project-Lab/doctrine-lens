# 描画は SVG を手で書き、作図ライブラリを持たない

## 背景

地図の描画に何を使うかを決める。webview の中で節点と辺を描き、選択と移動に応じる必要がある。

## 却下した選択肢

**D3 や Cytoscape などの作図ライブラリを積む。** 力学配置や当たり判定を自前で書かずに済む。
しかし webview には内容セキュリティ方針が効き、外部からの読み込みができないため、
いずれにせよ同梱する必要がある。同梱すれば拡張機能の大きさが増える。
また力学配置は反復のたびに座標が揺れるため、SPEC-002 が課す決定性を満たさない。

**Canvas に描く。** 節点が数千を超えても速い。しかし当たり判定と読み上げの対応を自前で書くことになり、
選択できる要素という性質を持たせにくい。統治木の文書数は数百の規模であり、速さは問題にならない。

## 決定

SVG を手で組み立てて描く。作図ライブラリを持たない。配置は決定的な計算で求める。

## 帰結

- 節点は要素であるため、キーボードで選べる。読み上げの対応も要素の属性で足りる。
- 配置の計算をこのドメインが持つ。力学配置は使えないが、SPEC-002 が課す決定性は自然に満たす。
- 節点の数が数千を超えると描画が重くなる。その規模に達したら Canvas への切り替えを検討する。
  現時点で先回りしない。
- 依存が増えないため、拡張機能の大きさは小さいままになる。
