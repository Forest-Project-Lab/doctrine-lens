# 取れていない数を、その場に出さない

## 背景

`ADR-017` は「画面は確かめたことだけを言う」と決め、記号の側をこう直した。

```ts
rangeCount: rangesKnown ? ranges.length : null,   // 取れていなければ ? を当てない
```

**同じ組み立ての中で、数の側は直っていなかった。** 再現した。

```
範囲が取れた（P に 1 件）  : コード 1 か所 / 範囲が無い 1 / 記号 nowhere,fix
範囲が取れなかった（null） : コード 0 か所 / 範囲が無い 2 / 記号 fix,fix
```

**記号は正しい。数だけが嘘をつく。**

門とは独立に走査をかけたところ（`CHANGE-010` の一周の最後）、四つの観点のうち
**二つが独立に同じ系統**を挙げ、反証を三視点で当てても落ちなかった。
数えたら**六箇所**あった。

## 決定

### 1. 取れていない数は、その場に出さない

`0` は「測って零だった」である。**取れていないことではない。**

数が出せないなら、**その数を出さない。** 空白にするのではなく、
その項目ごと画面から落とす。

```
全部取れた     : 2 文書 · コード 1 か所
                 壊れている 0 · 足りない 0 · 範囲が無い 1 · 非現行 0
範囲が取れない : 2 文書
                 壊れている 0 · 足りない 0 · 非現行 0
```

**`ADR-014`「良い状態を空白で表さない」とはぶつからない。**
`ADR-014` が禁じるのは「測ったのに空白にすること」である。
測っていないものは、そもそも数ではない。

| | どうするか |
|---|---|
| 測って零 | **`0` と書く**（`ADR-014`） |
| 測っていない | **その項目を出さない**（この決定） |
| 測っていないのに `0` と書く | **禁じる** |

### 2. 取れなかったことは、一度だけ言う

各数の場所で「取れていない」と繰り返さない。
部分失敗の通知が既に「範囲が取れなかった・理由はこれ」と言っている（`SPEC-005`）。

**同じ事実を二箇所で言わない。** 画面が長くなるだけで、読み手の手は増えない。

### 3. 取れていない事実を、記号の数と比べない

要約の二行目（記号ごと）と三行目（事実ごと）が食い違う理由は、
脚注が「行には最も重い記号だけが出る」と言う。

`null !== 0` を食い違いと読むと、**取れていないことを排他のせいにする**——
**誤った理由**が画面に出る。比べる前に、取れているかを見る。

### 4. 「取れていない」を、判断の層で `null` のまま運ぶ

上流の取得が失敗した値は、**取得の層から画面の層まで `null` のまま**運ぶ。
途中で空へ潰さない。潰した層より下は、もう区別できない。

実測で、潰していた箇所は次のとおりだった。

| 場所 | 何を「無い」に化けさせていたか |
|---|---|
| `consequence.ts` `facts.noRange`・`codeRanges` | 範囲が取れない回に「コード 0 か所・範囲が無い N」 |
| `graph.ts` `reverseOrphans` | 逆孤児が取れない回に `+` が永久に出ない |
| `graph.ts` `checksRun` | 検査の一覧が取れない回に「0 検査を走らせた」 |
| `cadence.ts` `staleIds` | 一度も監査していない回に、帯が「食い違い無し」 |
| `lensPanel.ts` `findings ?? []` | 所見が取れない回に「壊れている 0」 |
| `lensPanel.ts` 起点の解決 | 範囲が取れない回に「起点が無い。印を持つファイルを開け」 |
| `registry.ts` | 形を検めず、項を欠いた値が空集合に化ける |

### 5. 「起点が無い」と「まだ分からない」を、別の文で言う

カーソルから起点を引くには範囲が要る。範囲が取れていない回に
「起点が無い。印を持つファイルか、木の中の `.md` を開け」と案内すると、
**既に開いている利用者へ嘘をつく。**

```
コード範囲が取れていないので、a.ts のカーソルからは文書を引けない。
これは「起点が無い」ではなく「まだ分からない」である。
```

## 却下した選択肢

### 却下 1 — 取れていない数の位置に「—」を置く

数の代わりに記号を置けば、位置は保たれる。却下した。

**「—」の意味を画面が説明しなければならない。** 説明を足すより、消す（`DESIGN.md` 9-4）。
そして 280px では、意味の無い記号が横幅を食う。

### 却下 2 — 取れていない項目ごとに「取れていない」と書く

各数の場所で理由を言えば親切である。却下した。

**同じ事実を四箇所で言うことになる**（範囲・所見・逆孤児・検査）。
部分失敗の通知が一度言えばよい（決定 2）。

### 却下 3 — 取れなかった回は画面を出さない

数が信じられないなら、明細ごと止めればよい。却下した。

**取れたところまでは正しい。** `SPEC-005` が「取れたところまでを出す」と決めている。
一つ落ちたら全部止めるのは、上流の部分失敗を全失敗として扱うことである。

## 帰結

- 六箇所が `null` を保つ。潰す層が無くなる。
- 要約の数は、その事実が測れた回にだけ出る。
- 潰しの表が 55 → 69 行になり、**六箇所とも「潰せば試験が落ちる」ことを実測で守る。**

## この決定が及ばないところ

- **記号には及ばない。** 記号は既に `ADR-017` が直している。
- **文書の数（`documents`）には及ばない。** グラフが取れなければ画面そのものが出ない。
- **上流が「零だ」と返した値には及ばない。** それは測った零である。`0` と書く。
