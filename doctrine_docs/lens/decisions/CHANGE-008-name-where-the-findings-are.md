# 出していない所見に、行き先を与える

## 変更内容

いまの脚注は件数だけを言う。

```
この画面のどこにも出していない所見が 4 件
```

**「畳んだら必ず件数を書く」は満たしているが、そこから何を開けばよいかを言っていない。**
`ADR-017` が「次の変更で扱う」と明記した課題である。

### 実測で分かったこと — 二種類ある

出ていない所見は、**性質の違う二つ**が混ざっている。必要な答えが違う。

| 種類 | 何 | 読み手が知りたいこと |
|---|---|---|
| **文書に属さない** | 上流の 5 検査（`guard_liveness_gap`・`unregistered_document`・`near_duplicate`・`glossary_seed_drift`・`memory_shadow`）は `doc_id` を空で挙げる | **どの起点を開いても出ない。** 明細に置き場が無い |
| **起点に繋がらない文書に付く** | 起点 `SPEC-005` のとき、`REQ-001` に付いた所見 | **どの文書を開けば出るか** |

実測（この木、人工の所見を足して確かめた）:

```
起点 SPEC-005: 出ていない所見 1 件（文書に属さない guard_liveness_gap）
起点 REQ-001 : 出ていない所見 0 件（同じ所見が行に出る）
```

### 直し方

**前者に行き先を与えない。** そこは明細の問いの外である。
「この画面の問いに属さない所見が N 件」と、**属さないことを言う**に留める。
`ADR-012` が予定した三枚目「木そのものの点検表」の担当である。

**後者には行き先を与える。** 行き先はその文書の id である。

```
起点に繋がらない 2 文書に所見が付いている: REQ-001 · TEST-002
この画面の問いに属さない所見が 1 件（どの文書にも紐づかない）
```

id は押せる。押すとその文書が開き、**開いた瞬間にそれが起点になる**
（起点はカーソルから決まる。ADR-012）。**新しい操作子を作らない。**

## 理由

`SPEC-006` の制約はこう書いてある。

> **畳んだら必ず件数を書く。** 隠すことは抽象ではない。

数を書くことは、隠さないことの**必要条件であって十分条件ではない**。
「4 件ある」と言われた読み手が次にできることが無ければ、
**数は「気になるが手が出ない」を生むだけである。**

そして二つを一つの数に畳んでいるのは、`ADR-017` 決定 1 が禁じた形そのものである。

> **一つの数に、性質の違う二つを畳まない。**

`CHANGE-006` で「繋がらない」を三つに割ったのと同じ誤りが、所見の側に残っていた。

## 要求元

`REQ-002`「一つの画面は一つの問いだけに答える」。
**画面は増やさない。操作子も置かない。** 脚注に id を並べ、押せるようにするだけである。

`REQ-004`「コードを読んでいるときに、その根拠の文書へ行ける」の延長。
行き先が在るものには行き先を出す。

## 見えている難所

**「文書に属さない」の判定を、こちらが検査名で持ってはならない。**
上流の 5 検査の名前を実装に書くと `REQ-003` の破れになる。
**`doc_id` が空かどうか**だけで分ける（上流が返す値で判じる）。

`refs` にだけ id を持つ所見が在る。その場合は「文書に属する」側へ入れる
（`findingsFor` が既に `doc_id` と `refs` の両方で引いている）。
