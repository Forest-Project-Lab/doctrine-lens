# 門が、その門が捕まえるはずの唯一のファイルを見ていなかった

## 何が起きているか

六つの観点で独立に走査をかけ、47 件が挙がり、反証を当てて 40 件が残った。
そのうち高が三つで、**三つとも実物で再現できた。**

### 1. 数字を含む名を、門の正規表現が読み落としていた

`CHANGE-022` は「部品の表に載っているのに印を持たないファイル」を捕まえる門を据えた。
その門の読み取りがこうだった。

```
/`(src\/[a-zA-Z/.]+\.ts)`/g
```

**文字クラスに数字が無い。** 実測。

| 式 | 拾える件数 |
|---|---|
| 逆引用符の中をそのまま取る（`[^`]+`） | **26** |
| 門の式（`[a-zA-Z/.]`） | **25** |
| 差 | **`src/l10n.ts` ちょうど一件** |

そして `grep` で印を持つファイルを数えると 25 件。
**表に在って印を持たないファイルは、`src/l10n.ts` ただ一つだった。**
門が見ていなかった一件が、門が捕まえるはずの唯一の欠陥だった。

`IMPL-001` の本文も「7＋18＝25」と書いていた。表は 26 を名指している。
**足し算が合わないこと自体が、一件抜けている印だった。**
`CHANGE-022` も「25 のファイルを名指す」と書いており、
**数える側が門と同じ式で数えていた**ので、どこからも見えなかった。

`src/l10n.ts` は利用者に見える文字列を全部持つ（案内文・要約・脚注の雛形）。
何行書き換えても指紋が動かず、`trace_stale` が鳴らない状態だった。

### 2. 所見の跳び先が、一度も開けていなかった

上流は**二つの座標系**で相対パスを返す。実測した。

| 出所 | path の例 | 基準 |
|---|---|---|
| `trace-index` の範囲 | `src/doctrine/audit.ts` | 作業フォルダ |
| `docs-audit` の所見 | `lens/decisions/CHANGE-022-….md` | **統治木** |

`session.toUri` は両方を作業フォルダに継いでいた。
所見の path を押すと `<作業フォルダ>/lens/decisions/…` を開こうとして、
そんなファイルは無いので「見つからない」を出す。**所見の道は一度も開けていなかった。**

### 3. 循環の中の起点が、持っていない前提を名指していた

行の理由をこう決めていた。

```
at === 1 ? { kind: "depends-directly" } : { kind: "depends-through", through: hit.from }
```

`at` は**起点が属する強連結成分からの距離**であって、起点からの距離ではない。
起点が循環に落ちていると、成分の**別の一員**から来た行まで距離 1 になる。

実測（模型に直に与えた）。

```
起点 SPEC-001。SPEC-001 ↔ SPEC-002 は循環。SPEC-003 は SPEC-002 だけを depends_on に持つ。
  直す前: 行 SPEC-003: reason={"kind":"depends-directly"}
  直した後: 行 SPEC-003: reason={"kind":"depends-through","through":"SPEC-002"}
```

`Reason` の型注釈は「どの理由も、**直前の相手**を名で持つ。持たないと、
三段先の行に『起点が影響すると宣言している』と書くことになる」と自分で書いていた。
**その注釈が要求していた形を、実装が満たしていなかった。**

## 変更内容

1. **門の読み取りを、逆引用符の中をそのまま取る形へ。** 文字クラスで名を絞らない。
2. **`src/l10n.ts` を印で囲む。** `IMPL-001` の「7＋18＝25」を「8＋18＝26」へ。
   `CHANGE-022` の「25 のファイル」に訂正を添える。
3. **跳び先に座標系を持たせる。** `openRange` の項に `base: "workspace" | "docs"` を足し、
   `toUri` は呼び手が言った基準に継ぐ。
4. **既定を置かない。** `toUri` にも `openRange` にも既定の座標系を持たせない。
   型が「言え」と要求する（`ADR-021`——既定は語らない）。
5. **直かどうかを、距離ではなく相手で判じる。** `hit.from === origin.id`。
6. **受入 35・36 を `SPEC-006` へ足し、`006-35`・`006-36` を書く。**
   潰しの表にも一行足す。

## 却下する見込みのもの

**`src/l10n.ts` を表から外す。** 印を打たずに済ませる道はこれである。却下する。
利用者に見える文字列を全部持つファイルを「部品ではない」と言うことになる。

**跳び先の座標系を、パスの形で当てる**（`.md` で終われば統治木、など）。却下する。
統治木の中にも `.ts` は在りうるし、上流が形を変えれば黙って壊れる。
**運ぶ側が言う。**

**`at === 1` を残し、循環のときだけ別扱いにする。** 却下する。
条件が二つになると、どちらが正本か読めなくなる。
**相手で判じれば、循環でもそうでなくても同じ規則で足りる。**

## 見えている難所

**門の走査先が、門の届く範囲である。** これで三度目である
（`CHANGE-013` は `src/integration/` を見落とし、`CHANGE-019` がそれを見つけ、
今回は文字クラスが一件を落とした）。
**「何件を検めたか」を門が言わない限り、見落としは見えない。**
いまの門は件数の下限（`> 15`）しか持たない。25 でも 26 でも通る。

## 理由（要求元）

`ADR-024`（発火していない門を、緑と呼ばない）。`ADR-019`（数を出したら行き先も出す）。
六観点の独立した走査で挙がり、三件とも実物で再現した。
