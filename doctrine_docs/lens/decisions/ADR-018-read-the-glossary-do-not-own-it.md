# 語の意味は木の辞書から引く。実装が語彙を持たない

## 背景

役割別に画面を読ませたところ、初学者・データサイエンティスト・営業の三役が
**「この語が分からない」**で止まった。`depends_on`・逆孤児・波・指紋・帰結。

ところが実測すると、**答えの多くは同じ木の中に在る。**

```console
$ grep -oP '^\| \K[^ |]+' doctrine_docs/_system/glossary.md
… 正本 投影 ビュー 刻印 現行 履歴 廃止 置換 アーカイブ 要求 依存 参照
孤児 逆孤児 ガード リンタ 用語チェッカー 起点 帰結 波 明細 記号 …
```

`GLOSSARY-001` は用語辞書の正本であり、`canonical_for: ['glossary']` を持つ。
**lens はこれを一度も読んでいない**（実装からの参照 0 件）。

そして、画面が出す次の 6 語は辞書に無い。

```
指紋・循環・所見・検査・統治木・範囲
```

**「指紋」は画面に最も多く出る語なのに、辞書に一行も無い。**
辞書は「刻印」（ビューが記す参照時点）を定義しているが、
指紋（印が囲む範囲の内容の sha256）は別の概念である。

## 決定

### 1. 語の意味は木の辞書から引く。実装が語彙を持たない

画面に出た語の定義を脚注に出す。**定義は木の `GLOSSARY-001` から引く。**

`REQ-003`「統治の規則を二重定義しない」に照らして、これは**二重定義ではない**。
語彙をこちらが持つのではなく、**上流の正本を出しているだけ**である。

実装が語の一覧を持たないために、次の形にする。

- 辞書の場所は `canonical_for` に `glossary` を含む節点から引く。
  **ファイル名も id も実装に書かない。**
- どの語を出すかは、**画面に実際に出た文字列と辞書の承認語を突き合わせて決める。**
  「出す語の一覧」を実装に書かない。
- 辞書が取れなくても画面を止めない。語の定義を出さないだけである。

### 2. 辞書に無い語は、辞書へ足す。画面の側で説明しない

画面が出す語が辞書に無いとき、**画面に説明を書いてはならない。**
書けば正本が二つになる。辞書へ足す。

辞書自身が「承認語を増やす、または意味を変えるときは、ADR で決め、この表を更新する」
と要求しているので、この ADR がその決定である。

足す 6 語は **指紋・循環・所見・検査・統治木・範囲**である。

**意味と禁じる語は、ここに書かない。** 書けば正本が二つになる——それは
この ADR が決定 2 で禁じたことそのものである。正本は `GLOSSARY-001`
（`doctrine_docs/_system/glossary.md`）に在る。この ADR が残すのは
「どの語を、いつ、なぜ足したか」だけである。

（初版はこの位置に表を写していた。`CHANGE-023` で消した。
自分の決定を自分の文書が破っていたのを、リンタが見つけた。）

### 3. 生の項名を、日本語の側では承認語で書く

行の一文は `depends_on` という**上流の項名**をそのまま出していた。
辞書は「依存」を承認語とし、`depends_on` を括弧に置いている。

**日本語の側は承認語で書く。** 英語の原文は項名を括弧に落とす
（英語の読み手には項名そのものが手掛かりになるため）。

## 却下した選択肢

### 却下 1 — 語の定義を l10n に書く

`src/l10n.ts` に「波とは…」と書けば、辞書を読む実装が要らない。却下した。

**正本が二つになる。** 辞書を直した人の変更が画面に届かず、
画面を直した人の変更が辞書に届かない。`REQ-003` が名指した失敗の型である。

なお実測すると、承認語（起点・帰結・波・明細・記号）は
`src/test/bridge.test.ts` の 28 語走査（型名 20 + status 語 8）の対象外なので、
**書いても門は落ちない。落ちないことを理由に書いてよいわけではない。**

### 却下 2 — 全部の語の定義を常に出す

辞書の 27 語を毎回脚注に並べる。却下した。

`DESIGN.md` 9 節「説明を足したくなったら、まず消すものを探す」に反する。
280px の紙面で 27 行の語釈は、明細そのものを押し出す。
**画面に出た語だけ**を出す。

### 却下 3 — 語を押すと定義が出る操作子を置く

却下した。`REQ-002`「切り替え操作子を置かない」に反する。
脚注に並べるだけにする。

### 却下 4 — 上流の `_registry` に語彙を足してもらう

`doctrine#153` で型の説明を頼んでいるので、語の説明も上流に頼めばよい。却下した。

**用語辞書はこの木の文書であって、上流の関心事ではない。**
木ごとに語彙が違うのが正しい（`GLOSSARY-001` は `canonical_for: ['glossary']` を
持つ木の正本である）。上流に頼むのは筋が違う。

## 帰結

- 初学者の「波って何？」「逆孤児って何？」に、画面がその場で答える。
- 辞書を直せば画面が追随する。**画面を直すために辞書を直すことになる**（正しい向き）。
- 実装が語彙を持たないので、`REQ-003` の門を通る。
- 辞書が取れない環境でも、明細は今までどおり出る。

## この決定が及ばないところ

- **型（SPEC・ADR・REQ…）の説明には及ばない。** これは上流に概念が無く、
  木の辞書にも無い（`doctrine#153`）。上流が動くまで出せない。
- **検査名（`trace_stale` など）の説明には及ばない。** 上流の `AUDIT_CHECKS` は
  名前だけである。所見の `message` が既に直し方まで書いているので、
  検査名の語釈を前に置くと同じことを二度言う（`ADR-012` の判断を維持）。
