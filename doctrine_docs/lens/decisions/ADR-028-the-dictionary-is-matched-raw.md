# 辞書は素の部分一致で照合される

## 背景

`ADR-018` で「辞書を読め、持つな」と決め、上流の用語チェッカーに判定を委ねた。
委ねた先がどう照合するかを、私は読まずに辞書を書いた。

上流の `_termcheck` は**素の部分一致**である。頭注がその理由を書いている——
日本語には語の切れ目が無いので、境界で切る照合ができない。

`CHANGE-023` で門を初めて正しく走らせたとき、**165 件の禁止同義語**が出た。
そのうち**真の違反は 24 件**で、残り 141 件は次の形だった。

| 形 | 例 |
|---|---|
| 禁じた語が、別の語の一部 | `親切` ⊃ `親`、`すり抜ける` ⊃ `抜け`、`DECIDED-001` ⊃ `CI`、`webview` ⊃ `view` |
| 禁じた語が、この木で別の正当な意味を持つ | `出力`（関数が返す値／`標準出力`）、`本体`（拡張機能の Node 側） |
| 禁じた語が、上流の構造語彙に含まれる | 必須節 `影響するテスト` ⊃ `テスト`、`エラー時挙動` ⊃ `エラー` |
| 禁じた語が、外から引いた文の中に在る | 『ドメイン駆動設計をはじめよう』の訳文の `領域` |

上流はこの形を一度踏んでいる——ADR の必須節 `却下した選択肢` のために
`選択肢` を手で例外に足した。ただし**登録簿から導いていない**ので、
三つのうち二つ（`影響するテスト`・`エラー時挙動`）が素通しだった。

## 却下した選択肢

**辞書を捨てる。** 141 件が偽陽性なら、辞書そのものが割に合わない、という読み方。
却下した。**真の違反 24 件は実在した**——`ゲート`・`波及先`・`原本` は
どれも承認語が在るのに別の語で書いていた。辞書が無ければ、それも見えない。

**上流の照合を語の境界で切る形に変える。** 却下した。日本語に境界は無い。
`ゲート` を `ゲート` として切る規則は、`ゲートウェイ` を通し、
`門ゲート` を通す。上流の頭注が既にこの検討を書いている。

**偽陽性を一件ずつ例外に登録する。** 却下した。`親切` のために `親切` を、
`すり抜ける` のために `すり抜ける` を登録し始めると、辞書は例外の一覧になる。
**規則の側が間違っているときに、例外で塞いではならない。**

**門を助言のままにする。** 却下した。実測で、この助言は一度も読まれずに
241 件溜まった。`ADR-024`——発火していない門を、緑と呼ばない。

## 決定

### 1. 禁じるのは、この木で別の意味を持たない語だけ

**別の正当な意味がこの木に実在する語は、機械の照合から外す。**
外すときは、別の意味と件数を `CHANGE-023` の表に残す。
「読みにくいから」では外さない。

外した 8 語——`出力`・`本体`・`警告`・`コア`・`指摘`・`選択`・`親`・`漏れ`／`抜け`。
残した 73 語——`ゲート`・`波及先`・`原本`・`退役`・`doctrine 側` ほか。
どれもこの木に別の意味を持たない。

### 2. 外した語は、消さずに人への案内へ移す

丸括弧だけの欄は語として登録されない（上流の `_PARENS_ONLY_RE`）。
そこへ書けば、**機械は照合せず、人は読める。**

```
| 投影 | … | レンダリング結果（投影の意味で「出力」と書かない。
             関数や過程が返す値の意味の「出力」は使ってよい） |
```

**規律を捨てるのではなく、規律の担い手を機械から人へ移す。**
どちらが担うかは、語に別の意味が在るかどうかで決まる。

### 3. 外から引いた文は、一字も変えない

引用は辞書の管轄の外に在る。**こちらの承認語で言い換えれば、それは引用ではない。**
照合に掛かるなら、整形の枠（コードフェンス）へ移して出所を添える。
枠に入れた文は上流がマスクするので、引用のまま門を通る。

### 4. 上流が名を定める節は、固有名として登録する

上流の登録簿が定める必須節の名は、上流が正本である。
こちらの承認語で言い換えると `MISSING_SECTION` が落とす。
**言い換えられないものは、固有名の行に置く**（意味欄に「固有名」と書く）。

これは `ADR-018` の「辞書を二重定義しない」と衝突しない。
固有名の行は**名だけ**を登録し、意味も同義語も書かない。

### 5. 辞書を写して持たない。これは自分にも当たる

`ADR-018` 決定 2 は「画面に説明を書いてはならない」と決めた。
その同じ文書が、足した 6 語の表を丸ごと写して持っていた。
**決定を書いた文書が、その決定を破っていた。**

`ADR` は「どの語を、いつ、なぜ足したか」を残す。
意味と禁じる語は `GLOSSARY-001` に一度だけ在る。

### 6. 禁止語を論じる文書は、その語を等幅に入れる

`CHANGE-023` を書いた直後、それ自身が 6 件の `BANNED_SYNONYM` で落ちた。
`ゲート`→`門` と書けば `ゲート` が地の文に在る。等幅（インラインコード）は
上流がマスクするので、**語について語ることができる。**

## 帰結

- 辞書は**素の部分一致で当たる前提**で書くことになる。書く前に、その語が
  この木の別の文脈に出ないかを一度数える。
- 上流の構造語彙（必須節の名・型コード）と、こちらの禁止語が衝突しうる。
  衝突は上流の登録簿から導いて外すべきだが、いまは手で固有名に置く。
  上流へ問題として出した。
- **`npm run docs:lint` が `npm run check` と CI の両方に在る**（`CHANGE-023`）。
  辞書を直したら、この門が即座に判じる。
- 語を外す判断は、件数と別の意味を伴わなければならない。
  外した記録は `CHANGE-023` の表に残る。**次に誰かが「厳しすぎる」と
  思ったとき、何が根拠で外したかを読める。**
