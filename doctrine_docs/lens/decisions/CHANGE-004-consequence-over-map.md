# 地図をやめ、帰結の明細にする

## 変更内容

この製品の入口を、**節点と辺の地図**から、**起点からの帰結を順に並べた一枚の明細**へ
置き換える。深度（L0〜L3）とレンズ（色・絞り・配置・深度の四つのダイヤル）を廃する。

答える問いを一つに絞る。

> これを変えたら、何を、どの順で直すことになるか。

俯瞰・構造・分類には答えない。答えないことを画面に明記する。

### 何が消えるか

| 消えるもの | いまの行数 |
|---|---|
| 配置の計算（地図・レーン・詳細・一覧の座標） | `src/model/layout.ts` 324 |
| レンズ（四つのダイヤル・色の割り当て） | `src/model/lens.ts` 190 |
| 深度と場面の組み立て | `src/model/depth.ts` 415 |
| SVG の描画・拡大縮小・平行移動・凡例・パンくず | `src/webview/main.ts` の大半 |

### 何が生まれるか

| 生まれるもの | 何をするか |
|---|---|
| 題名の取得 | 上流の frontmatter パーサを呼び、id ではなく題名を出せるようにする |
| 帰結の組み立て | 起点からの波（第 1 波・第 2 波…）と、五つの記号と、並び順を決める純粋な関数 |
| 明細の画面 | 左寄せの行だけ。SVG を一要素も持たない |
| 意匠の正本 | `DESIGN.md`。寸法・色・書体・動きの値をそこにだけ持つ |

### 何が変わらないか

上流の CLI との橋（`src/doctrine/` の七つ）は一行も捨てない。
コード側の面（見出しと帯）はそのまま残す。この製品で唯一「効いている」画面である。

## 理由

利用者から次の指摘を受けた。

> 正直分かりづらい／グラフの線が重なりすぎてわかりづらい／内容が、REQ1 とか型番で
> わからない／依存されているから何？　依存しあっているものは異常？など／
> 逆に疑問が増えるばかりだった／本質的に解決しないといけないことがわかってない気がする

四つの批判それぞれについて、原因を実測で特定した。

**① 線が重なる。** 密度の問題ではない。実測 39 節点 33 辺、密度 0.022 は、
研究（Ghoniem 2004）が「この規模なら節点リンク図が必ず読める」と結論している側にある。
原因は**縦横どちらの軸も意味を持たないこと**である。列は上流の登録簿の登録順で、
依存の流れ（REQ→SPEC→IMPL→TEST）の途中に ADR・CHANGE・IMPACT が割り込む。
行は id の辞書順。結果、辺の 52%（17/33）が二列以上を飛び、交差 31、
無関係な箱を貫く辺が 24 本中 14 本になる。行の順を 6000 回最適化しても交差は 24 までしか減らない。

**② 型番でわからない。** 上流 `dep-graph.py` が `title` を返さない。
題名は全 39 文書の frontmatter に在り、上流のパーサを呼べば 171ms で取れる。
取りに行っていなかった。加えて、箱は 156×46px・中央揃えで、
題名の中央値 14 字・最長 28 字の日本語は物理的に入らない。
**箱をやめて行にしない限り、題名は出せない。**

**③ 依存されているから何？** 一本の灰色の矢印が、事実（宣言された辺）と、
判定（これは異常か）と、時制（いつの話か）の三つを同時に背負っている。
上流は依存（`depends_on`）と影響（`impacts`）を別の端として持ち「混ぜるな」と定めているのに、
画面は同じ線で描いていた。詳細欄が出すのは動詞の無い id の羅列だった。

**④ 依存しあっているのは異常？ 疑問が増える。** これは読み違いではない。
**画面がそう主張していたのを正しく読んだ結果である。** 実測で 33 辺のうち 18 辺が
9 対の相互ペアであり、その中身は全部「同じ一つの事実を両端から二回書いたもの」だった
（`REQ-001 impacts SPEC-002` と `SPEC-002 depends_on REQ-001`）。
和で畳めば 33 辺は 24 事実になる。ところが実装は `BIDIRECTIONAL_GAP` という仕掛けで
往復の二本を法線方向へ振り分け、**わざわざ必ず二本に見せていた**。
そして本物の循環は 0 件である。上流の `dep_cycle` がそう返しているが、
その答えは `src/doctrine/audit.ts` の四行（`check.startsWith("trace")`）で捨てられていた。

**上流は 34 種の検査を毎回走らせているのに、実装はそのうち 11 種しか受け取っていない。**
「何が問題か・なぜか・どれくらい重いか」という判定の層を捨てて、位相だけを描いていた。
判定を出さない可視化は、読み手に判断を押し付ける。疑問が増えるのは当然の帰結である。

## 要求元

利用者（2026-07-29）。あわせて、その場で示された二つの読み物を判断の基準に採る。

- Rich Hickey "Simple Made Easy"（simple = 撚りが無い／easy = 手近）
- 『ドメイン駆動設計をはじめよう』§3.3.3（一つの領域に一つのモデルという固定観念を持たない）

**REQ-002 は後者を出所に挙げながら、出所と正反対の結論を出していた。**
出所は「課題ごとに別のモデルを作ってよい」「世界地図に地下鉄の駅は不要」と言うのに、
要求文は「一枚の地図を四つのダイヤルで切り替える」「画面は増やさない」と書いていた。

**降ろす順序に不変条件がある。** 実測で `SPEC-002` には現行の依存元
（`IMPL-001`・`SPEC-003`・`TEST-002`）が、`SPEC-003` には（`IMPL-001`・`TEST-003`）が残る。
先に後継（SPEC-006）を立て、依存元を張り替えてからでなければ降ろせない。
`ADR-002〜005` と `TEST-002/003` には現行の依存元が無く、張り替えは要らない。

正確な列挙は IMPACT-004 に置く。

## 実施の記録（段 14）

2026-07-29 に一周を終えた。見積との差は次のとおり。

| 区分 | 見積 | 実測 |
|---|---|---|
| 降ろした文書 | 8 | 8（SPEC-002・SPEC-003・TEST-002・TEST-003・ADR-002〜005） |
| 書き直した文書 | 6 | 9（見積の 6 に SPEC-004・SPEC-005・TEST-004・TEST-005 が加わった） |
| 新しく作った文書 | 4 | 4（ADR-012・ADR-013・SPEC-006・TEST-006） |
| 消えた実装 | 約 2,100 行 | 2,003 行（`layout.ts` 324・`lens.ts` 190・`depth.ts` 415・webview 1,074） |
| 新しい実装 | — | `titles.ts` 137・`consequence.ts` 493・`view.ts` 209・`main.ts` 174 |

見積が外したのは **SPEC-004 と SPEC-005**である。「上流との橋は残る」と見積もったが、
橋の中身のうち「所見を `trace` で始まる検査だけに絞る」という一節は、
まさに ADR-012 が問題にした「判断を橋の上で捨てる」振る舞いだった。
残ると思っていた層に、変える理由がそのまま埋まっていた。

### 門の実測

| 門 | 結果 |
|---|---|
| 単体 | 167 件すべて通る |
| 突然変異 | 表の 38 件すべてを試験が捕まえる |
| 写し（画面） | 誤り 0・食い違い 0。720 / 480 / 280px の三つで溢れ無し |
| 統合（実際の編集器） | 9 件すべて通る |
| 監査 | error 0・warn 0・advisory 1（`guard_liveness_gap`。開発環境の hooks 配線で、製品の外） |
| 梱包 | 12 ファイル・53.69 KB |

突然変異の表は、最初の走行で **1 件が素通り**した
（「解析が全件落ちても成功として返す」）。その一件のために、
上流のパーサを `UnicodeDecodeError` へ追い込む試験を足してから 38/38 にしている。

意匠の門も、最初は `DESIGN.md` の「`500` を使わない」という**禁止の文**から
500 を許可値として拾っていた。凡庸な太さを入れても素通りした。
許す値は表にだけ書く形へ直してある。

写しを目で見て、門が見ていなかった二つを直した。

1. **読み幅を `72ch` で書いていた。** `ch` はその要素自身の字の大きさを基準にするので、
   11px の脚注は 500px、13px の波は 600px、20px の起点は 900px で切れる。
   節ごとに右端がずれ、区切りの罫の長さが揃わなかった。読み幅を一つの px 値に固定し、
   `ch`・`em`・`rem` で書けないことを試験にした。
2. **右端に、意味の違う裸の数が二種類あった。** 波の見出しの件数と、行の
   「後ろに N」が同じ位置に出ていた。件数に単位の語を付け（「2 文書」）、
   行の数の意味を脚注で言う形にした。**説明の無い数は、読めない型番と同じである。**
