# 最初のスライスを深度 L0 から L2 に限る

## 背景

作れるものは三つある。深度の階層を持つ地図、文書とコードの行き来、監査の所見の表示である。
どれから作るかを決める。

## 却下した選択肢

**文書とコードの行き来から作る。** 上流の `trace-index.py` を読み、コードの範囲と文書を結ぶ。
日々の役に立つ度合いは最も高い。しかし単体では全体像が出ず、既存の要求追跡の道具と同じ土俵に降りる。
またこの機能は地図の上に一層として自然に載るため、後から足せる。

**監査の所見の表示から作る。** 上流の `docs-audit.py` の所見を編集器の診断へ移す。
webview が要らず最も安い。しかし全体像の絵が出ず、いま SessionEnd で走らせている監査との差が小さい。

## 決定

最初のスライスは深度 L0 から L2 の地図に限る。L3 と監査の所見は後のスライスへ送る。

## 帰結

- 「地図は描くものではなく導出されるもの」という主張が、最初のスライスで確かめられる。
- 描画の土台とレンズ文法がここで立つため、L3 と所見はその上の一層として足せる。
- 逆順に作ると、地図を作る段で情報の並べ方をやり直すことになる。その手戻りを避けられる。
- 最初のスライスの時点では、上流の `trace-index.py` と `docs-audit.py` を呼ばない。
  ICD-001 のデータ契約にはこの二つも記すが、使い始めるのは後のスライスである。
