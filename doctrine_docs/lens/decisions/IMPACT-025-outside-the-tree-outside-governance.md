# 木の外に在る文書の影響

## 影響する文書

| 文書 | 何を直したか |
|---|---|
| `GLOSSARY-001` | `view` を機械の照合から人への案内へ移す（`ADR-028` 決定 1） |
| `ADR-025` | 写して持っていた辞書の 4 行を消し、語の名だけ残して正本を指す |
| `CHANGE-025`・`IMPACT-025` | 新設（この二つ） |
| `README.md`（ビュー） | `波及先`→`帰結`。正本は `CHANGE-023` で直したのに写しが古びていた |
| `CHANGELOG.md` | `退役`→`非現行` |

## 影響する実装

| ファイル | 変更 |
|---|---|
| `tools/check-root-terms.mjs` | 新設。根の五つを `term-check.py` に掛け、`[ERROR]` が在れば 1、対象が消えていれば 2 |
| `package.json` | `docs:terms` を足し、`check` の連なりへ入れる |
| `.github/workflows/check.yml` | 「根の文書の用語」の段 |

`src/` は一行も動かない。

## 影響するテスト

単体試験は増えない。**新しい門は `npm run docs:terms` そのものである。**

疑ってから信じた（`ADR-024` 決定 5）。

| 故意に壊したもの | 期待 | 実測 |
|---|---|---|
| `DESIGN.md` に禁止語を一語書く | 赤 | **`ゲート` を名指して rc=1** |
| 一覧の対象を実在しない名にする | 「対象が無い」で止まる | **rc=2** |
| 何もしない | 緑 | **rc=0**（5 件が辞書と合う） |

**通ったことと、見ていないことを分ける。** 対象が消えた回に 0 を返すと、
`CHANGE-023` で踏んだ穴（知らない引数で 0）と同じ形になる。

## 実測

| 何 | 前 | 後 |
|---|---|---|
| 根の文書に辞書が当たる経路 | **0** | **2** |
| 根の文書の `[ERROR]` | **3** | **0** |
| 日本語の地の文で単独の `view` | **0 件**（数え直した） | 0 件 |
| `view` の別の意味 | `webview` 18・`doc-review` 3・`preview` 1・`view.ts` ほか | 同じ |
| 辞書を写して持つ文書 | **1**（`ADR-025`） | **0** |
| `check` の段 | 6 | **7** |

**写しが実際に壊れていた証拠**——`ADR-025` の写しは
`| 上流 | … | 本体、親、コア、上流 |` になっていた。`doctrine 側` を木から
一括で消したときの巻き添えである。辞書の側は同じ巡で直したが、写しは残った。

## 工数見積

**事後に立てた見積は置かない**（`ADR-017`）。上流の CI と自分の CI を
段ごとに突き合わせて見つけ、同じ巡で直した。実際に動いた量はこの PR の差分が示す。

## 順序の不変条件

**上流の CI と自分の CI を、段ごとに突き合わせる。** 見つけ方はこれだった。
「上流に在る門を、こちらは持っているか」を一つずつ問う。
`code-audit.py` は対象 0（`plugin/scripts` と `scripts/` を見る道具で、
こちらにはどちらも無い）、`dep-graph.py` は頭注が `問い合わせ専用の道具であり、ゲートではない` と言っている。
**残ったのが根の文書の用語だった。**

**外した語は、別の意味の件数を先に数える。** `view` を外したのは
「英語だから」ではなく、**日本語の地の文に一件も無く、別の意味が 30 件在る**からである。
