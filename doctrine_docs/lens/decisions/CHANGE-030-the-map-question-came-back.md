# 地図の問いが戻ってきた — 製品を変えずに応えた

## 何が起きているか

上流 issue 204 で「目的・責務・入出力・保証から実装へ降りる、目的別の画面」の構想
（呼び名は System View）が事前分析として出された。骨子は三冊の規範文書
（JAXA JERG-2-610C・STPA 手引き・CAST 手引き）である。

これは ADR-012 が捨てた地図の復活ではない。**別の問いへの別の画面**の構想であり、
事前分析自身が「現行 Lens の地図を復活させる形では作らない」と結論している。

両リポジトリのエージェントが協議し、所有者が確定した合意台帳 v3.1 が正本である
（issue 204 のコメント、2026-08-03）。要点は五つ。

1. 現行製品・REQ-000・NONGOAL-001 は**検証の間、変更しない**。
2. 検証は本リポジトリの実験ブランチ `experiment/system-map` で行い、
   `main` にも製品コードにも混ぜない。
3. 表示製品は読み取り専用のまま。意味の確認・昇格という**書き込みを持つ画面は
   Lens ではない**。
4. 検証の門は三層（機械・人間・観測）。人間試験が未実施の間は「合格」ではなく
   `UNASSESSED` であり、製品統合へ進まない。
5. 上流は追跡索引の入口を上流 ICD 002 に `trace-index-api` として宣言した
   （上流 PR 205）。**こちらが既に読んでいた形が、宣言済みの契約になった。**

## 変更内容

- `SPEC-004` — 追跡索引の問い合わせの入口が上流 ICD 002 の宣言
  `trace-index-api` になったことを書き足した。呼び方も返る形も変わっていない。
  **黙って読んでいた契約が、名指しできる契約になった**だけである。
- `.gitignore` — `Reference_material/`（規範文書の抽出物）を足した。
  規範文書は再配布条件を確認するまでコミットしない（台帳 v3-11′）。
  外部に正本があるものは写さず、出所を参照する。
- `ADR-029` — 判断の正本を新規に置いた。

## 直さなかったもの

- `NONGOAL-001` は一字も変えない。「図を描かない」の理由（実測した失敗）は
  導出された位相図についてのものであり、構想の当否はまだ検証されていない。
  書き換えてよいのは、検証が門を通過し、理由ごと書き換えられるときだけである。
- 画面・模型・橋のコードは一行も変えない。

## 理由（要求元）

上流 issue 204 の協議と、所有者の確定（2026-08-03 のコメント）。所有者は
Phase 0 の開始条件に「lens 側の決定記録 PR 完了」と「SPEC-004 から
上流 ICD 002 `trace-index-api` への参照追随」を挙げた。

（`SPEC-004`）、統治木の外の一行（`.gitignore`）。実装・試験・受入は動かない。
詳細は `IMPACT-030`。
