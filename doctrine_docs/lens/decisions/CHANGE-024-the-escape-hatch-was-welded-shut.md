# 門が示した逃げ道を、門が塞いでいた

## 何が起きているか

`npm run docs:measured` は、文書が挙げる「`<id>` を起点に置くと `<N>` 行」を
測り直す門である。合わないとき、こう言って終わる。

```
数を直すか、刻印を添えて「いつの木か」を書くこと（ADR-021 決定 5）。
```

**その刻印を、道具は読んでいなかった。** いつも作業木で測っていた。

三つの文書は既に刻印を持っていた（`61a3775` の木）。それでも
`CHANGE-023` で統治文書を三つ足した瞬間、木が 21 行から 22 行に育ち、
三件とも赤くなった。**言われたとおりにしてあるのに、赤い。**

## なぜ効くか

刻印の意味は「**いつの木についての数か**」である。木は文書を足すたびに育つので、
「いまの木で何行か」を凍らせることはできない。凍らせられるのは
「**その木で何行だったか**」であり、これは永久に変わらない。

道具が刻印を読めば、問いが変わる——「いまも 21 行か」ではなく
「**書いた時点で 21 行だったか**」。後者は測れて、しかも意味がある。

## 変更内容

1. 主張の前後 120／200 字から「`` `<sha>` の木 ``」を拾う。
2. 刻印が在れば `git archive <sha>` で一時の場所へ展開し、**その木で測る**。
3. 刻印が無ければ、これまでどおり作業木で測る。
4. 木ごとに一度だけ組む（同じ刻印の三件で、展開は一回）。
5. 終わったら一時の場所を消す。

## 覆わないもの

**刻印が本当にその木で測ったものかは、確かめられない。**
別の commit を刻んでも、そこで同じ数が出れば通る（実測で `a19fd0c` を
刻むと通った——その木でも 21 行だったため）。

門が確かめるのは「**刻んだ木で、その数が真か**」である。
「どの木で実際に測ったか」は書き手しか知らない。ここは書き手の誠実さに委ねる。
**確かめられないことを、確かめたと言わない**（`ADR-017`）。

## 却下する見込みのもの

**刻印つきの主張を測らずに素通しする。** 却下する。
それは逃げ道ではなく穴である。刻印が「もう測らなくてよい」の意味になると、
最初から嘘だった数が永久に残る。

**木が育つたびに数を書き換える。** 却下する。統治文書を一つ足すたびに
三つの文書を書き換えることになり、履歴が数の追随で埋まる。
そもそも `ADR-021` 決定 5 が刻印を決めたのは、これを避けるためだった。

## 見えている難所

**展開は git の履歴に依る。** 刻印が指す commit がこの複製に無ければ測れない。
浅い複製の CI では失敗しうる。CI の `actions/checkout` は既定で浅いので、
この門が刻印つきの主張を測るなら深さが要る——**次の走行で確かめる**
（確かめる前に「大丈夫」と書かない）。

## 理由（要求元）

`ADR-024`（発火していない門を、緑と呼ばない）の対。
**逃げ道を示して塞ぐ門は、発火しているのに直せない。**
`CHANGE-023` で統治文書を三つ足したときに露見した。
