# 意匠の値の正本を DESIGN.md に置き、実装は値を持たない

## 背景

利用者から「デザインが凡庸で悪い」と言われた。実測すると、凡庸さは好みの問題ではなく
**体系が一つも無いこと**として測れた。

`src/panel/html.ts` の STYLE を数えた結果:

| 何 | 実測 |
|---|---|
| 余白 | `6px 12px` / `8px 12px` / `12px 14px` / `3px 10px` / `2px 6px` / `5px` の六種。**4px 格子に一つも乗らない**。gap は七種 |
| 角丸 | 3px（枠）・2px（凡例の色片）・5px（節点）の三種 |
| 書体 | 八段あるが全域が本文の 0.8〜1.05 倍。**画面最大の文字が本文の 5% 増し** |
| 太さ | `600` が一箇所（しかも無効化した要素）。他は全部 `400` |
| 深さ | `box-shadow` / `text-shadow` / `gradient` / `blur` が **0**。面は二段、罫は一種で、道具立て・地図・検分欄・凡例が**全部同じ 1px の同色線で等価に区切られている** |
| 動き | `transition` / `animation` が **0** |

色はさらに悪い。固定 10 色の並びを型に配っていたが、`fill-opacity 0.22` を通した
実描画で **ΔE\*ab = 2.23** ——弁別閾（約 2.3）以下で、**物理的に見分けられない**。
暗い主題では 8 型すべてが L\* 18.7〜21.8 の 3.1 幅に潰れる。
そして VS Code は `charts.red` / `charts.yellow` などの主題追従のトークンを持っているのに、
一つも使っていなかった。

値が一回きりの思いつきで置かれ、正本がどこにも無い。これが「凡庸」の中身である。

## 却下した選択肢

**画面の CSS を丁寧に直す。** 値を揃えても、次に誰かが一行足したときに同じことが起きる。
正本が無い限り、体系は必ず崩れる。実際、六巡の監査でこの層は一度も指摘されなかった
（どの門も見ていない層だった）。

**既存の設計体系をそのまま採る（Linear や Raycast の DESIGN.md を置く）。**
値が固定の hex なので、VS Code の webview では成立しない。主題は利用者が選ぶ。
明るい主題で読めなくなるか、編集器から浮くかのどちらかになる。

**CSS-in-JS や設計トークンの仕組みを入れる。** 依存が増える。この製品は依存を増やさない
方針を採っており（ADR-002 の目的）、その目的は SVG を捨てることでより強く達成される。
仕組みではなく**規律**で解く。

## 決定

**`DESIGN.md` をリポジトリの根に置き、画面のあらゆる寸法・色・書体・動きの正本とする。**

形式は [awesome-design-md](https://github.com/VoltAgent/awesome-design-md) の九節に従う。
Linear・Raycast・Sentry の設計体系から**規律を採り、値は採らない**。

定めるのは次である（全文は `DESIGN.md`）。

1. **値は VS Code の主題の変数から取る。** 固定の hex を実装に持たない。
2. **有限の段しか持たない。** 余白は `4/8/12/16/24/32` の六段、角丸は `4/8` の二段、
   書体は四段、等幅は二段、太さは `400` と `600` の二種。
   **この表に無い値を書いたら、それは誤りである。**
3. **高さは影ではなく面の段で表す。** `box-shadow` / `text-shadow` / `gradient` /
   `blur` を一つも書かない（Raycast「色の段から高さを生成」）。
4. **彩度のある色は、上流が異常だと言ったものにだけ使う。** 二色だけ
   （`charts.red` = 壊れている、`charts.yellow` = 足りない）。
   型もドメインも色で表さない。三色目を導入しない。
   `!`（直す）と `~`（見直す）に色を当てない——それらは異常ではないので、
   色を当てると「波及している＝悪い」という嘘になる。
5. **基準の幅は 280px。** VS Code の側帯の最小幅で成立することを最初の受入条件とする。
   幅が広がっても列を増やさない。横に巻かない。
6. **この文書と実装が食い違ったら、実装を直す。**

## 帰結

- **`DESIGN.md` は統治木の外に置く。** 製品の意匠の正本であって、統治の対象ではない。
  `_system/.md-intake` に「非文書」として登録する。
  ただし**この ADR がその存在と権威を定める**ので、統治から切り離されてはいない。
- **凡例が消える。** 色が型を表さなくなるため、色と型の対応表が要らなくなる。
- **色のダイヤルが消える。** 色に選択の余地が無くなる。
- **主題への追従が構造として保証される。** 固定 hex を書かないので、
  明るい主題・暗い主題・高コントラスト主題のいずれでも壊れない。
- **意匠に門を効かせられる。** 「`DESIGN.md` の段に無い値が CSS に書かれていないか」は
  字面で検められる。試験にする。
- **Sentry の設計体系に状態色が無いことを確認した上での決定である。**
  重大度の色は既製の体系から降ってこない。自分で決めて明記する必要がある。
  だから上の第 4 項を ADR に書いた。
