# 捨てた概念の名乗りを外すことの影響

## 影響する文書

`ICD-001` を直したら、**上流の追随の検査が 12 件発火した。**
一件ずつ中身を読んで、**直すもの**と**そのままでよいもの**に分けた。

| 文書 | 何を直したか |
|---|---|
| `ICD-001` | `canonical_for` から二つ外す。公開する用語を入れ替える。入力の用途から「地図の描画」「深度 L3」を外す |
| `SPEC-001` | エラー時挙動の表に**「地図」が 4 箇所**。「レーンの並び」も 1 箇所 |
| `REQ-003` | 受入 2 に「新しい型の文書が**地図**に現れる」 |
| `REQ-004` | 「**地図**を開いていなくてよい」ほか 3 箇所 |
| `IMPL-001` | 「直前に成功した**地図**を消さない」ほか 2 箇所 |
| `SPEC-006` | 受入 11「**地図**の面が潰れない」 |
| `SPEC-004`・`SPEC-005`・`TEST-001`・`TEST-004`・`TEST-005` | 中身に古びは無い。`updated` だけ上げた |
| `README.md` | 刻印を打ち直した（内容を検めたうえで） |

**合計 11 箇所が、生きた文で捨てた語を使っていた。**

## そのままにしたもの

| 文書 | なぜ残すか |
|---|---|
| `REQ-001`・`REQ-002` | 「**以前はこう書いてあった**（`ADR-012` で改めた）」——**変異の記録**である |
| `TEST-006` | 「深度・レンズ・地図を**戻さないこと**」——退行観点として正しい言及 |
| `CHANGE-001`〜`004`・`IMPACT-002`・`IMPACT-004` | 一巡の記録。履歴を書き換えない |

**機械が挙げた 12 件を、一件ずつ人が読んで分けた。**
これが `ADR-005`（事実と判定を分ける）の実地である——
**機械は「確かめよ」と言い、確かめるのは人の仕事だった。**

## 影響する実装

**無い。** 文書だけである。

## 影響する門

**無い。** `canonical_for` の名乗りが生きているかは、機械では判じられない（`CHANGE-017` で実測した）。

## 実測

| 何 | 前 | 後 |
|---|---|---|
| `ICD-001` の `canonical_for` | 3 トピック（うち **2 つは捨てた概念**） | **1 トピック**（`upstream-json-contracts`） |
| 生きた文に残る捨てた語 | **11 箇所** | **0** |
| 監査 | error 0 / warn 0 / advisory 1 | **error 0 / warn 0 / advisory 1** |
| 追随の検査の発火 | — | 12 件 → 一件ずつ裁いて 0 |

## 順序の不変条件

**`ICD-001` を先に直す。** それが `updated` を進め、依る文書へ追随の検査が連鎖する。
逆順にやると、連鎖が起きないので**古びを見つけられない。**

**一件ずつ中身を読む。** `updated` を機械的に上げると、
**`SPEC-001` の「地図」4 箇所を見落とす。** 刻印を打ち直すのは「確かめた」の宣言である。
