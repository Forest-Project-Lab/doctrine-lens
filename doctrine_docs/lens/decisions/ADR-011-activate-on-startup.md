# 起動条件に onStartupFinished を足す

## 背景

起動条件は `workspaceContains:doctrine_docs/_system/**` と `workspaceContains:docs/_system/**`
の二つだけだった。編集器は `**` で始まらないこの形を作業フォルダの直下に固定して探すため、
統治木が下位のディレクトリに在ると一致しない。

公開前監査が実機で確かめた事象は二つある。

- 設定 `doctrineLens.docsRoot` で下位の統治木を指した利用者の環境では、拡張機能が起きない。
  状態の帯も見出しも余白の帯も出ない。原因を示すはずの帯そのものが出ないので沈黙する。
- 統治木を持たない作業フォルダでは、初回の導入者に何も出ない。
  「統治木を敷け」という唯一の案内も出ない。命令パレットを自力で探した者だけが次へ進める。

どちらも「地図を開かなくてもコード側の面が効く」という README の主張と食い違う。

## 却下した選択肢

**`workspaceContains:**/doctrine_docs/_system/**` を足す。** 下位の統治木を拾える。
しかし統治木を持たない作業フォルダでは相変わらず起きない。
上の二つの事象のうち一方しか解けない。
加えて `**` で始まる形は作業フォルダ全体の走査を伴い、大きなリポジトリでは開くのが遅くなる。

**README の記述を実体に合わせて下げる。** 「まず地図を開け」と書けば嘘ではなくなる。
しかしコード側の面（見出し・余白の帯・状態の帯）を地図と独立に効かせるために
`LensSession` を切り出した意味が失われる。実装の設計のほうを捨てることになる。

## 決定

起動条件に `onStartupFinished` を足す。既存の二つは残す
（統治木が根直下に在る通常の場合は、そちらのほうが早く起きるため）。

## 帰結

- どの作業フォルダでも起動するので、状態の帯が常に出る。
  統治木が無いこと・プラグインが無いことが、地図を開かずに分かる。
- 起きたあとに走るのは統治木の解決だけである。統治木が無ければ上流の CLI を一つも呼ばない
  （`LensSession.refresh` が候補ゼロで戻る）。窓を開く費用はほぼ増えない。
- 統治木が下位のディレクトリに在っても、`docsRoot` の設定が効くようになる。
- `onStartupFinished` は編集器の起動が済んでから走るので、起動そのものは遅くしない。
- 試験が manifest に `onStartupFinished` が在ることを守る。
