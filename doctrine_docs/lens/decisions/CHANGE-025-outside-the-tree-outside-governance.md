# 統治木の外に在る根の文書に、辞書が一度も当たっていなかった

## 何が起きているか

`CHANGE-023` で `docs-linter --batch` を門に結び、統治木の 241 件を 0 にした。
**その門は `doctrine_docs/` の中しか走らない。**

根に在る五つの文書——`README.md`・`AGENTS.md`・`CLAUDE.md`・`DESIGN.md`・
`CHANGELOG.md`——は木の外なので、辞書が一度も当たっていなかった。

上流は自分の CI に同じ段を持っている。

```yaml
- name: Term-check root docs (README, CONTRIBUTING, plugin/README, CLAUDE, AGENTS)
  run: term-check.py README.md CONTRIBUTING.md plugin/README.md CLAUDE.md AGENTS.md
```

こちらには無かった。掛けてみたところ **3 件**出た。

| 文書 | 違反 |
|---|---|
| `README.md` | `波及先`→`帰結`（`SPEC-006` の表を写した箇所。正本は `CHANGE-023` で直したが、写しは古びたまま） |
| `CHANGELOG.md` | `退役`→`非現行` |
| `README.md` | `view`（英語の地の文。下に書く） |

## 「木の外に在るものは、統治の外に在る」——四度目

同じ形をこれで四度見つけた。

| 回 | 何が外に在ったか |
|---|---|
| `CHANGE-017` | `ICD-001` の `canonical_for` は辺ではないので、監査が辿らない |
| `CHANGE-018` | `.preview/shots/` は `.gitignore` の中なので、古びても誰も咎めない |
| `CHANGE-022` | `IMPL-001` の表は名前を並べるだけで、指紋ではない |
| **`CHANGE-025`** | **根の文書は `doctrine_docs/` の外なので、辞書が当たらない** |

**繋がっていないものと、git の外に在るものは、統治の外に在る。**

## `view` は英語の地の文だった

`README.md` は日本語 6% の英語文書である（`doctrine:view` の刻印つきビュー）。
そこに出る `view`・`review`・`views` は普通の英単語であり、
辞書が言う「`画面` の意味で `view` と書く」ではない。

木の中も数え直した。**日本語の地の文で単独の `view` を書いた箇所は一つも無い。**
在るのは `webview`・`preview`・`doc-review`・`view.ts`・`review`（記号の名）だけである。

`ADR-028` 決定 1 の基準——**この木にその語の別の意味が実在するときだけ外す**——に
当てて外した。件数はゼロではなく、**別の意味が 30 件、その意味は一件も無い**。

## 写しが二つ在れば、二つとも壊れる

`ADR-025` も辞書の 4 行を写して持っていた（`ADR-018` に続いて二つ目）。
枠の中なので機械は咎めないが、**実際に壊れた**——`doctrine 側` を木から
一括で消したとき、辞書の右列とこの写しの両方が巻き添えで書き換わり、
`| 上流 | … | 本体、親、コア、上流 |` という、上流が上流を禁じる行になっていた。

辞書の側は `CHANGE-023` の途中で気づいて直したが、写しは残った。
**写しは、壊れても気づかれない。** `ADR-018` と同じ形へ直した——
語の名だけを残し、正本を指す。

## 変更内容

1. **`tools/check-root-terms.mjs` を作り、`npm run check` と CI に入れる。**
   根の五つを `term-check.py` に掛け、`[ERROR]` が一件でも在れば非ゼロ。
2. **名指した対象が無い回を、通ったことにしない。** 対象が消えていたら 2 で止まる。
3. **真の違反 2 件を直す**（`README.md` の `波及先`、`CHANGELOG.md` の `退役`）。
4. **`view` を機械の照合から人への案内へ移す**（`ADR-028` 決定 1）。
5. **`ADR-025` の写した表を消す**（`ADR-018` と同じ直し方）。

## 却下する見込みのもの

**根の文書を統治木へ入れる。** 却下する。`README.md` は**ビュー**であり、
体系の外から体系を説明する文書である（刻印がそう名乗っている）。
木へ入れると、投影と手書きのビューの区別が消える。

**`docs:lint` の走査先を根まで広げる。** 却下する。上流の `--batch` は
統治木を解決してから走る。走査先を広げるには上流を変えるか、
こちらで別の道具を持つかであり、後者の方が小さい。

## 見えている難所

**対象の一覧を手で持つことになる。** 根に `.md` を足したとき、
この一覧に足し忘れれば、また外に置かれる。
一覧に無いファイルを見つけて咎める形も考えたが、生成物
（`node_modules/` の中など）と区別する規則が要る。いまは**消えたときに 2 で止まる**
方向だけを機械にした——**足し忘れは人が見る。**

## 理由（要求元）

`REQ-003`（規則を二つ持たない）。`ADR-028`（辞書は素の部分一致で照合される）。
`CHANGE-023` の直後に、上流の CI と自分の CI を段ごとに突き合わせて見つけた。
