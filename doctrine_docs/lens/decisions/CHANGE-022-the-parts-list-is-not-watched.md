# 部品の表が名指す実装 7 ファイルを、誰も見張っていない

## 何が起きているか

`IMPL-001`（拡張機能の部品の配置）は「対象部品」の表で **25 のファイルを名指す**。
（**26 だった。** この巡で据えた門の正規表現が数字を含む名を読み落としており、
数える側も同じ式で数えていた。`CHANGE-027` で直した。）
そのうち **7 つが印（`doctrine:begin`）を持たない**。

```
src/extension.ts        201 行
src/panel/html.ts       257 行
src/panel/lensPanel.ts  329 行
src/session.ts          495 行
src/shared/protocol.ts  164 行
src/statusbar.ts         88 行
src/test/manifest.test.ts 213 行
                       ────
                       1747 行
```

**`IMPL-001` は指紋を一つも持たない。** だからこの 7 ファイルをどれだけ書き換えても
`trace_stale` は鳴らず、`IMPL-001` を消しても `trace_missing_impl` は鳴らない。

## 「印なしを鳴らさない」とは別の話である

`NONGOAL-001` はこう決めている。

> **印なしのコードを不足として鳴らさない。**
> 印は任意であり、**印が無いことが欠陥かどうかは原理的に判じられない。**

**この決定は正しい。** 任意のコードについて「印が無い＝欠陥」とは言えない。
だから上流の `trace_unmarked_backlog` を閉じたままにしているのも正しい。

**だがこの 7 つは任意のコードではない。** `IMPL-001` が「これが実装である」と
**名指している**。名指したものが見張られていないのは、印の話ではなく**文書の話**である。

| | 何を言うか | いま |
|---|---|---|
| `NONGOAL-001` | 印なしのコードを咎めない | **守られている** |
| `IMPL-001` | この 25 ファイルが実装である | **7 つが見張られていない** |

## `CHANGE-017` と同じ形である

`ICD-001` は「深度とダイヤルの正本」を名乗りながら、それを決めた文書と繋がっていなかった。
**名乗りは辺を作らない。** ここも同じ——**表の名指しは指紋を作らない。**

## 変更内容

1. `IMPL-001` に「実装の指紋」の節を作り、**7 ファイルに印を打つ**。
2. **表の 25 と、印を持つファイルが一致すること**を門にする。
   表に足したのに印を忘れる／印を打ったのに表に載せ忘れる、の両方を捕まえる。
3. `src/test/manifest.test.ts` は試験である。**表から落とす**か、
   試験も部品として数えるかを決める——**いまは表に載っているので、載っている以上は見張る。**

## 見えている難所

**印は範囲を囲む。** ファイル全体を囲むと、**どの一文字が変わっても `trace_stale` が鳴る。**
それは「見張っている」というより「うるさい」に近い。

`src/doctrine/` の既存の印はファイル全体を囲んでいる（`SPEC-001` の 9 ファイル）。
**同じ形に揃える。** 揃えない理由が見つかったら、そのとき決める。

**`html.ts` は CSS を含む。** 意匠の値は `DESIGN.md` が正本であり、
`DESIGN.md` を直せば `html.ts` も変わる——**そのとき `IMPL-001` の指紋が鳴る。**
それは正しい（意匠を変えたら部品の配置も見直す）が、**鳴りすぎないかを実測してから決める。**

## 理由（要求元）

`REQ-001`「いま触れているものから、直すことになるものを順に辿る」——
**部品の表が名指すものが辿れないなら、表が嘘をついている。**

## 影響の初期見積

| 区分 | 見積 |
|---|---|
| 書き直す文書 | `IMPL-001`（指紋の節を新設） |
| 新しく作る文書 | `IMPACT-022` |
| 触る実装 | 7 ファイルに印を打つ（中身は触らない） |
| 触る門 | 表と印の突き合わせを一つ足す |

## 実施の記録

2026-08-03 に一周を終えた。

| 何 | 前 | 後 |
|---|---|---|
| `IMPL-001` の指紋 | **0 本** | **7 本** |
| 表が名指すのに印の無い実装 | **7 件（1747 行）** | **0** |

**中身は一字も触っていない。** 先頭と末尾に印を打っただけである。
**門を足していないのに、上流の `trace_stale` が 7 ファイルを見張るようになった**——
印は上流の仕掛けであり、打てば働く。

### 門が、自分自身を誤検出した

「`doctrine:begin IMPL-001` を含むか」で数えたら、**この門の注釈がその文字列を含んでいた。**

```
IMPL-001 の印を持つのに、部品の表に載っていない実装が在る
  + 'src/test/mutation-table.test.ts'
```

行頭で判じる形へ直した。`CHANGE-013` の「括弧の数で本体を切って、正規表現リテラルに
騙された」と同じ形である——**新しい門の最初の判定は、疑ってから信じる**（`ADR-024` 決定 5）。

### `src/test/manifest.test.ts` を表から落とさなかった

表に載っている以上は見張る、と決めた。**載っているのに見張らないのが、この変更が直した形**である。
落とすなら、それは別の判断（部品の表に試験を載せるか）であり、この一周では触らない。
