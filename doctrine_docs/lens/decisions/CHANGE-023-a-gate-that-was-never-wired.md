# 上流に在る門を、どの経路にも結んでいなかった

## 何が起きているか

上流には門が二つ在る。

| 門 | 何を見るか | 手元での呼ばれ方 |
|---|---|---|
| `docs-audit.py` | 文書と文書の**間**（参照・孤児・指紋の古び） | `npm run docs:check`。CI に在る |
| `docs-linter.py --batch` | 文書**一件の中**（禁止同義語・必須節・許可 status） | **どこにも無かった** |

`npm run check` にも `.github/workflows/check.yml` にも、リンタのバッチは無い。
Hook としては登録されているが、上流の頭注が
「予防: 何も予防しない。決して decision/permissionDecision/deny を出さない」
と明記している——**PostToolUse のリンタは助言であって、門ではない。**

初めて正しく呼んだところ、**85 文書に 241 件の ERROR** が出た。

| 検査 | 件数 |
|---|---|
| `BANNED_SYNONYM` | 165 |
| `MISSING_SECTION` | 58 |
| `BAD_STATUS` | 18 |

## 引数を間違えたまま「緑」と読んでいた

正しくない呼び方をしていた。

```
$ docs-linter.py --batch --root doctrine_docs
docs-linter --batch: 統治木が無い(--root)。点検対象なし。
$ echo $?
0
```

**`--batch` の次の語がそのまま統治木の場所になる。** `--root` という文字列が
場所として渡り、そんな場所は無いので「点検対象なし」で 0 を返していた。
`0` を見て緑と読んでいた。`ADR-024`（発火していない門を、緑と呼ばない）が
言ったことを、私はその隣でやっていた。

## 何が出たか

### 1. 上流の必須節名と、こちらの禁止語が板挟みになる

上流の登録簿が定める必須節の名に、こちらの辞書が禁じた語が入っていた。

| 必須節（上流の正本） | こちらが禁じていた語 | 上流の手当て |
|---|---|---|
| `却下した選択肢`（ADR） | `選択` | **在る**（`選択肢` を手で例外に） |
| `影響するテスト`（IMPACT） | `テスト` | **無い** |
| `エラー時挙動`（SPEC） | `エラー` | **無い** |

節名を書くと `BANNED_SYNONYM` が落とし、書かないと `MISSING_SECTION` が落とす。
**同じ道具の二つの ERROR が互いを打ち消す。** 上流はこの形を一度踏んで
`選択肢` を例外に足しているが、**登録簿から導かず手で並べている**ので、
三つのうち二つが素通しになっていた。上流へ問題として出した。

### 2. 「辞書を読め、持つな」と決めた文書が、辞書を持っていた

`ADR-018` は決定 2 で「画面に説明を書いてはならない。書けば正本が二つになる」
と決めている。その同じ文書が、**足した 6 語の表を丸ごと写して持っていた**
（意味の欄も、禁じる語の欄も）。写しは辞書と一字ずつずれていた。

リンタが見つけたのは「禁止語が本文に在る」という形だが、正体は
**自分の決定を自分の文書が破っていた**ことである。表を消し、
語の名だけを残して正本を指す形へ直した。

### 3. 辞書が普通の日本語を禁じていた

165 件の禁止同義語のうち、**真の違反は 24 件だった**。残りは、
禁じた語がこの木で別の正当な意味を持つために起きていた。

| 禁じていた語 | 承認語 | この木での別の意味 | 件数 |
|---|---|---|---|
| `出力` | 投影 | 関数や過程が返す値。`標準出力`。`出力先` | 37 |
| `本体` | 上流 | 拡張機能の Node 側（webview の対）。関数の本体 | 24 |
| `警告` | 所見 | 所見の**重さ**の語（辞書自身が括弧で認めていた） | 11 |
| `コア` | 上流 | DDD のコアドメイン。上流の共有コア（`_config.py` ほか） | 7 |
| `指摘` | 所見 | 利用者が言ったこと | 6 |
| `選択` | 起点 | 選択欄・選択の余地 | 5 |
| `親` | 上流 | 親 process（`親切` にも当たる） | 5 |
| `漏れ`・`抜け` | 逆孤児 | 「渡し漏れ」「すり抜ける」 | 4 |

照合は**素の部分一致**である。日本語に語の切れ目が無いので、
`親切`・`すり抜ける`・`DECIDED-001`（⊃ `CI`）・`webview`（⊃ `view`）が
すべて違反として挙がる。**別の意味を持つ語を素の部分一致で禁じると、
門は鳴りっぱなしになり、鳴りっぱなしの門は結ばれない。**

### 4. 辞書が自分と矛盾していた

`CI` を「門の禁止同義語」に置きながら、同じ文書の下で
「定着した借用語（…`CI`…）」と書いていた。地の文の 18 箇所はすべて
**門を走らせる場**の意味で、門そのものではない。禁止が誤りだった。

## 変更内容

1. **`docs:lint` を作り、`npm run check` と CI に入れる。**
   引数は `--batch .` である（`--root` は取らない）。
2. **辞書を直す。**
   - `CI` を禁止から外す（借用語との矛盾）。
   - 別の意味を持つ 8 語を、機械の照合から人への案内へ移す
     （丸括弧だけの欄は語として登録されない）。
   - `非現行` を承認語に足す（`退役` の行き先。本文と実装で既に使っていた）。
   - 固有名を 4 件足す（`webview`・`標準エラー`・上流の必須節名 2 件）。
3. **真の違反 24 件を直す**（`ゲート`→`門`、`波及先`→`帰結`、`原本`→`正本`、
   `自己ループ`→`自己循環`、`退役`→`非現行`、`テスト`→`試験` ほか）。
4. **`ADR-018` の写した表を消す。**
5. **`status: accepted` の CHANGE 18 件を `current` へ。**
   `accepted` は ADR だけに許される。上流の CHANGE はすべて `current`。
6. **節の名を上流の正本に揃える**（`この変更でやること`→`変更内容`、
   `要求元`→`理由（要求元）`、`影響する門`→`影響するテスト`）。
7. **`工数見積` を欠いた IMPACT 11 件に、実測を置く。**
   事後に見積は書かない（`ADR-017`）。実際に動いた量を git から測って置く。

## 却下する見込みのもの

**辞書を捨てる。** 241 件が出たのは辞書が細かすぎるからだ、という読み方はできる。
却下する。**真の違反 24 件は実在した**——`ゲート`・`波及先`・`原本` は
どれも承認語が在るのに別の語で書いていた。捨てれば、それも見えなくなる。

**リンタを助言のままにする。** 却下する。助言は読まれない。
実測で、この助言は**一度も読まれずに 241 件溜まった**。

## 見えている難所

**辞書を緩めることと、門を通すために辞書を削ることは、外から見て同じに見える。**
分ける基準を決めた——**この木にその語の別の意味が実在するときだけ外す。**
`ゲート`・`波及先`・`原本`・`退役`・`doctrine 側` は別の意味を持たないので、
禁止のまま残した。外した 8 語は、上の表に別の意味と件数を書いてある。

## 理由（要求元）

`REQ-003`（規則を二つ持たない）。`ADR-024`（発火していない門を、緑と呼ばない）。
上流の v0.10.0 を取り込んだ際に、新しい版で門を当て直していて見つけた。
