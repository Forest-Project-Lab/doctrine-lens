# 撮り直さない写しが、消えずに残る

## 何が起きているか

写しの門は `.preview/shots/` に撮る。**古い写しを消さない。**

```
01-L0.png                4.8 日前   ← 地図時代（CHANGE-004 で捨てた）
02-L1.png                4.8 日前
03-L1-status.png         4.8 日前
04-L1-filter.png         4.8 日前   ← ダイヤルの「絞り」。NONGOAL-001 が捨てた
05-L2.png                4.8 日前
06-L3.png                4.8 日前
07-up-L2.png             4.8 日前
08-up-L1.png             4.8 日前
09-up-L0.png             4.8 日前
01-list.png              0.2 日前   ← いまの段
…
```

**9 枚が地図時代の残骸である。** 深度の段（L0〜L3）とダイヤルの絞りを撮ったもので、
`ADR-012` と `NONGOAL-001` がその概念を捨てて以来、**撮り直されないまま消されてもいない。**

## `ICD-001` と同じ形である

同じ日に見つけた `CHANGE-017` と、**構造が同じ**である。

| | `ICD-001` | 写しの残骸 |
|---|---|---|
| 何が残ったか | 捨てた概念の**名乗り** | 捨てた画面の**写し** |
| なぜ残ったか | `CHANGE-004` の影響の一覧に入れなかった | 道具が消さない |
| なぜ誰も咎めないか | `canonical_for` は辺ではない | **`.preview/` は `.gitignore` の中に在る** |

**git の外に在るものは、統治の外に在る。**

## なぜ効くか

**利用者に見せる写しを、ここから採っている。** `media/consequence.png` と
`media/narrow.png` は `.preview/shots/` からの複製である。

残骸が混ざっていると、**捨てた画面を「いまの画面」として配る**道が開いている。
実際、`CHANGE-010` で撮り直すまで `README` の写真は四版ぶん古びていた。

## 変更内容

1. **撮る前に、その走行で撮らない写しを消す。** 道具が自分の出力先を掃除する。
2. 消したことを**数で言う**（「古い写し 9 枚を消した」）。黙って消さない。
3. **消す範囲を自分の出力先に限る。** `.preview/shots/` の外へ手を出さない。

## 見えている難所

**「撮らなかった」と「消し忘れた」を区別する。** 走行が途中で落ちた回に、
撮れた分まで消すと原因が読めなくなる。**撮り始める前に一度だけ消す**——
落ちた回は「途中まで撮れた」状態が残り、そこから読める。

## 却下する見込みのもの

- **`.preview/` を追跡下に入れる。** 写しは生成物であり、正本ではない。
  二進の差分を履歴に積む理由が無い。
- **古い写しを検査で咎める。** 生成物に対する検査は、生成し直せば消える問題を
  門にすることになる。**消せばよい。**

## 理由（要求元）

`ADR-017`「画面は確かめたことだけを言う」——
**撮っていない画面の写しを、撮った写しと同じ場所に置かない。**

## 実施の記録

2026-08-03 に一周を終えた。

```
前の走行の写し 18 枚を消した。
写しを /workspaces/doctrine_lens/.preview/shots に書いた。誤り 0・食い違い 0。
```

**18 → 9 枚。** 地図時代の 9 枚が消えた。
古い写しを一枚置いて走らせ、消えることも確かめた。

受入 34 は**画面側**が受け持つ（`npm run preview` が走行の前後で入れ替わりを見る）。
`CHANGE-011` で作った門が「試験も宣言も無い受入が在る」と落としたので、宣言を足した。
**自分で作った門が、自分の書き忘れを捕まえた。**
