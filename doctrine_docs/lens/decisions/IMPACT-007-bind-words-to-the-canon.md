## 実装で分かった難所

**この木の辞書には表が二つ在り、字面はどちらも三列である。**

```
| 承認語 | 唯一の意味 | 禁止する同義語 |
| 使わない（カルク） | 直す | なぞった英語 |
```

自前で解こうとすると、**カルクの表まで承認語として拾う**（実測で 42 件になった。真は 33 件）。
見分けるには見出しの語（「承認語」「カルク」）を実装が持つことになり、
`REQ-003` の破れになる——実際、単体試験がそれを捕まえた。

```
not ok - 実装に日本語の表示文字列が残っていない
  + 'src/doctrine/glossary.ts: 唯一の意味'
```

**上流の `_termcheck.load_glossary` が既にこの表を解いている**（見出しで判じている）。
承認語の判定を上流へ返し、こちらは「上流が承認語だと言った語の意味を拾う」だけにした。
実測で 33 件ちょうど、カルクは混ざらない。

**これが `REQ-003` の正しい形である。** 規則を書き写すのではなく、規則を持つ側に訊く。

## 順序の不変条件

**辞書へ語を足すのを先にする。** 画面が語を出す仕組みだけ入れても、
辞書に無い語（指紋・循環・所見・検査・統治木・範囲）は出ない。

`ADR-018` を先に書く。辞書自身が「承認語を増やすときは ADR で決めて表を更新する」
と要求している。
