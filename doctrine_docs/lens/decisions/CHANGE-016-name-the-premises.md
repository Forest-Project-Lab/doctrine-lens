# 前提の数だけを出して、行き先を出していない

## 何が起きているか

`ADR-019` はこう決めている。

> **数を出したら行き先も出す。行き先が無いなら、無いと言う。**
> 件数だけを出して読み手に手が無い状態を、「隠していない」と呼ばない。

**前提の脚注が、その規律を破っている。**

```
起点が前提にしている 39 文書は出していない（この画面は逆向きに辿らない）
```

**数が在って、行き先が無い。** 「逆向きに辿らない」は**理由**であって行き先ではない。

`CHANGE-008`／`ADR-019` は所見の脚注にこの規律を当てたが、
**同じ脚注の並びに在る前提には当てていなかった。**

## 利用者が同じ場所で詰まっていた

この欠陥は、利用者の問いから出た。

> このプロダクトはなにか。……**そうなるまでの変異は何か。**
> 時系列と、意思決定、何を解決しようとしているのかが分からない。

`SPEC-006` の**変異**——なぜこの形になったか——は、前提の 39 文書の中に在る
（`ADR-012` 地図をやめる・`ADR-013` 意匠の正本・`REQ-001`・`REQ-002` …）。

**辿れる場所に在るのに、画面が名を出していない。**

## 実測

| 何 | 実測 |
|---|---|
| 前提を持つ起点 | 52 / 85 |
| 前提（推移）の最大 | **43**（`TEST-006`）／中央 6 |
| **直の前提**の最大 | **7**（`SPEC-006`）／中央 1 |
| 直の前提を持つ文書 | 47 |

**推移の 43 は画面に並べられない。直の 7 なら並べられる。**

`SPEC-006` の直の前提はこうである。

```
ADR-012 ADR-013 REQ-001 REQ-002 SPEC-001 SPEC-004 SPEC-005
```

**これが「そうなるまでの変異」の入口である。**

## 変更内容

1. **直の前提の id を、押せる形で脚注に出す。** 所見の行き先と同じ扱いにする。
2. **推移の数はそのまま数で言う。** 「39 文書」は隠さない。並べるのは直の 7 だけである。
3. 「逆向きに辿らない」の一文は残す。**理由と行き先の両方を出す。**

## 見えている難所

**画面が答える問いは増やさない**（`REQ-002`）。前提を**行として出さない**——
脚注に id を並べるだけである。行にすると「直すことになるもの」と混ざる。

**推移の全部を並べない。** 43 件は 280px で読めない。
`ADR-019` が求めるのは「手が在ること」であって「全部並べること」ではない。
直の前提を押せば、そこからまた直の前提を辿れる。**一歩ずつ辿れれば手は在る。**

## 却下する見込みのもの

- **逆向きの明細を作る。** `REQ-002` は「問いが増えたら別の画面を作る」と定めるが、
  **いま要るのは入口であって画面ではない。** 別の画面は測ってから決める。
- **CHANGELOG へ誘導する。** 時系列は `CHANGELOG.md` に在る（13 版・27 本の決定を参照）。
  だが `CHANGELOG` は**体系外のビュー**であり、木の中から辿る先ではない。

## 理由（要求元）

`ADR-019`「数を出したら行き先も出す」——自分で決めた規律の、当てていなかった箇所。

### 見積が外したこと — 「直の前提は最大 7」は誤りだった

最初にそう測ったが、**`depends_on` の辺だけを見ていた**。
`impacts` で指してくる `CHANGE` を落としており、正しくは**最大 31**である。

```
SPEC-006 の直の前提 31:
  ADR-012 ADR-013 ADR-014 ADR-017 ADR-018 ADR-019 ADR-021 ADR-022 ADR-023
  CHANGE-005 … CHANGE-016  IMPACT-005 … IMPACT-012  REQ-001 REQ-002
  SPEC-001 SPEC-004 SPEC-005
```

**この 31 件が「そうなるまでの変異」そのものである。** 利用者が求めていたのはこれで、
`depends_on` だけを見ていたら半分しか出せなかった。

### 実装してから、280px で測って決めた

31 件を並べると **248px**（脚注全体 616px のうち）。縦に伸びるだけで横には溢れない。
中央は 1 件なので、ふつうの起点では一行しか増えない。

**測る前に「多すぎる」と決めていたら、行き先を出さないままだった。**

### 新しい決定を立てていない

`ADR-019`「数を出したら行き先も出す」を、**当てていなかった箇所に当てただけ**である。
`CHANGE-008` でこの規律を所見に当てたとき、**同じ脚注の並びに在る前提を見落としていた。**
