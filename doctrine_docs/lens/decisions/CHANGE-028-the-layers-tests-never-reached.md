# 単体試験が一度も届いていない層に、欠陥が住んでいた

## 何が起きているか

`CHANGE-027` で高 3 件を直したあと、残る所見を**実物で走らせて**確かめた。
22 件のうち **21 件が再現した**（一件は誤りで、代わりに別の食い違いが出た）。

再現したもののうち、**重いもの三つは同じ場所に住んでいた**——
`tsconfig.test.json` の外である。

```
"include": ["src/doctrine/**/*.ts", "src/model/**/*.ts", "src/test/**/*.ts"]
```

`src/session.ts` と `src/panel/` と `src/webview/` は `vscode` や DOM を取り込むので、
ここに入らない。**入らない＝単体の門が一度も届かない。**
`TEST-006` の退行観点は「危うい変換を試験の届かない層に置かない」と書いていたが、
**層そのものに門が無いことは書いていなかった。**

### 1. 木を切り替えた直後、前の木の地図が配られる

`#forget()` は `#store` を捨てるが `#state.snapshot` に触れない。
失敗の経路（作業フォルダ無し・木無し・プラグイン無し）はどれも `EMPTY_STATE` を撒く。
**成功の経路だけが撒いていなかった。**

実測（偽の `vscode` を差して本物の `session.ts` を束ねた）。

```
[2] choose('/w/beta') の直後（beta の取得は未着地）
  candidate.folder  = /w/beta
  snapshot.docsRoot = /w/alpha/doctrine_docs   ← 前の木
  ranges            = ["src/alpha.ts"]          ← 前の木
  toRelativePath('/w/beta/src/alpha.ts') → 'src/alpha.ts'
  → rangeAtLine が {"id":"ALPHA-001"} を返す
```

**新しい木のファイルの行に、前の木の id が起点として当たった。**
`#forget()` の注釈が「別のプロジェクトのコードに誤った印が付く」と名指しで
禁じている当のことが、この窓（上流の CLI 五〜六本ぶん）で起きていた。

### 2. 明細が焦点を取ると、起点が消える

起点は `vscode.window.activeTextEditor` 一本から決まっていた。
明細（webview）が焦点を取ると編集器の側では `undefined` になる。
**焦点が外れたことと「起点が無い」ことは別である**（`ADR-023`）。

結果、明細を触ろうとした瞬間に明細が消えた。
脚注の行き先も循環の行も、押すために焦点を取ると押す対象ごと描き直された。

### 3. 行の中の釦へ、鍵盤で一度も届かなかった

行の `keydown` が泡立ちを止めておらず、しかも `preventDefault()` が
**釦の素の活性化（Enter→click）まで潰していた。**

実測（実物の画面で）。

| 焦点 | 押した鍵 | 送られたもの |
|---|---|---|
| 行 | Enter | `openDocument` ✓ |
| 範囲の札 | Enter | **`openDocument`**（`openRange` ではない） |
| 範囲の札 | Space | **`openDocument`** |
| 範囲の札 | 鼠で click | `openRange` ✓ |

**鍵盤だけの利用者は、範囲にも所見の跳び先にも一度も到達できなかった。**
写しの門は「行が開ける」だけを見ていたので、これを咎めなかった。

### 4. 同じ画面が、同じ文書を二通りに言う

前提は行にならないので必ず「画面に出ていない所見」の側へ落ちる。
だが `findingsElsewhereAt` はそれを除いていなかった。

```
「起点が前提にしている 1 文書は出していない…直に前提にしている 1 件:」 → A
「起点に繋がらない 1 文書に所見が付いている（開けば起点になる）」      → A
```

同じ脚注の並びで、**同じ A が「前提」とも「繋がらない」とも出た。**
`unreached` は初めから前提を引いている——**一つの画面で「繋がらない」の定義が
二通りになっていた。**

### 5. 所見の六項のうち、二つが画面に出ていない

`SPEC-006` と `SPEC-004` は「六項ともそのまま出す。どれかに潰さない」と書く。
実際に出ていたのは**四項**だった——`doc_id` は写す層が落とし、
`refs` は画面が描いていなかった。

一件の所見は `doc_id` でも `refs` でも行に並ぶ。`doc_id` が無いと、
**読み手はその所見が実際どの文書に付いたのかを判じられない。**

### 6. 影響の側では、直の辺の註が落ちる

`ADR-017` は「迂回路だけを名乗って、存在する直の辺を無いことにしない」と決めた。
実装は `depends-through` だけを見ていたので、**影響の側では註が落ちた。**
実測でこの木に **30 行・25 起点**あった。

### 7. 実測の門が、字面を一字一句で縛っていた

`docs:measured` は「`<id>` を起点に置くと `<N>` 行」だけを拾っていた。
`CHANGE-020` の「`ADR-008`（取得を二つの拍に分ける）を起点に置くと、明細は 0 行である」
（`40dd24f` の木）を一度も見ていなかった。**その主張は、いまの木では偽になっている**——
書いた時点は 0 行、いまは 13 行である（同じ変更が `ADR-008` に辺を足したため）。
刻印を添えたので、門は `40dd24f` の木で測って通す。

## 変更内容

1. **試験の届かない層に門を作る。** `tools/session.test.mjs` と `tools/panel.test.mjs`。
   手は写しの門と同じ——esbuild で束ね、編集器の面だけを `tools/fake/` へ差し替える。
   **束ねる元は `src/` の実物**なので、実装を直せば門も一緒に動く。
2. **`#forget()` が状態からも捨てる。** 読み手が見るのは `#state` だけである。
3. **直前の編集器を覚える。** 閉じられていれば捨てる。
4. **行の `keydown` が、中の釦に焦点が在る回は何もしない。**
5. **前提を「繋がらない」に混ぜない。** 除いた分は `findingsOnPremisesAt` として
   件数と id を別の行に出す（`ADR-014`・`ADR-019`——畳んだら必ず数と行き先を言う）。
6. **`doc_id` を写し、`doc_id` と `refs` を画面に描く。**
7. **影響の側でも直の辺を名乗る。**
8. **実測の門の字面を緩め、零件を止め、下限を置く。**
   `CHANGE-020` の主張に刻印（`40dd24f`）を添える。
9. **受入 37・38・39 を `SPEC-006` へ。** 潰しの表に二行。

## 却下する見込みのもの

**`tsconfig.test.json` を広げて `src/panel/` を入れる。** 却下する。
`vscode` を取り込む層は編集器が無いと動かない。偽物を差すのは同じことだが、
**どこで差したかが `tools/` に見える形のほうが正直である**——
`tsconfig` に入れると「単体試験が届いている層」に見えて、実は偽物で動いている。

**起点を利用者に選ばせる。** 焦点の問題は「選ばせれば消える」。却下する。
`ADR-012` の決定である。**いま開いている場所から決まる**ことが、この製品の問いそのものである。

**`doc_id` を画面から省いたまま、`SPEC` の側を四項へ書き換える。** 却下する。
一件の所見が複数行に並ぶ以上、**どの文書に付いたのか**は読み手に要る。

## 見えている難所

**偽物は本物ではない。** `tools/fake/vscode.mjs` は `session.ts` と `lensPanel.ts` が
触る面だけを持つ。触る面が増えれば、偽物が黙って古びる。
いまの手当ては「束ねが落ちれば気づく」だけである——
**面が増えたのに偽物が対応していない回は、束ねが通ってしまうこともある。**
`npm run test:integration` が実物の編集器で回るので、そこが最後の砦である。

**実物の画面の門は、見本に在るものしか検められない。**
所見の跳び先（`.finding .at`）の鍵盤は、見本に所見が一件も無いので検めていない。
受入 38 は範囲の札でだけ検めている。

## 理由（要求元）

`ADR-024`（発火していない門を、緑と呼ばない）。`ADR-023`（取れていない数を出さない）。
`ADR-019`（数を出したら行き先も出す）。
六観点の走査が挙げ、22 件を実物で走らせて 21 件が再現した。
