# 作業フォルダが複数のときは統治木を持つものを選び、覚える

## 背景

いまの実装は作業フォルダの一つ目だけを見る。統治木が二つ目のフォルダに在ると、
拡張機能は「統治木が無い」と告げて何も出さない。利用者から見れば、
在るものが見えない状態である。

一つの窓に複数のフォルダを開く使い方は珍しくない。
複数のフォルダがそれぞれ統治木を持つこともある。

## 却下した選択肢

**全ての統治木を一枚の地図に混ぜる。** 一度に全体が見える。
しかし別々の統治木は別々の登録簿・別々のドメイン空間を持つ。
同じ `SPEC-001` が二つの木に在りうる。混ぜれば id が衝突し、
どちらの木の話かを読み手が判じられなくなる。上流も木を跨いだ問い合わせを持たない。

**一つ目のフォルダだけを見る（現状）。** 実装が最も簡単である。
しかし「在るのに見えない」を放置することになる。

**開いている文書のあるフォルダに追随する。** 文書を切り替えるたびに地図が移る。
賢く見えるが、地図を見ながら別のフォルダのファイルを開いただけで地図が飛ぶ。
読み手が意図していない移動である。

## 決定

統治木を持つ作業フォルダを全て候補として集め、そのうち一つを選んで使う。
選び方は次の順とする。

1. 利用者が明示に選んだフォルダ（作業フォルダごとに覚える）。
2. 覚えが無ければ、候補を整列した順の先頭。

候補が二つ以上あるときは、いま見ている木がどれかを状態の帯に出し、
命令で切り替えられるようにする。

## 帰結

- 統治木が二つ目以降のフォルダに在っても見える。
- 一度に見る木は一つだけである。id の衝突は起きない。
- 候補が一つのときは、利用者に選ばせない。選択は必要になったときだけ現れる。
- 選んだ木は覚えるので、窓を開き直しても戻らない。
- 全ての木を一度に見たい要求が出たら、この決定を置換する新しい ADR が要る。
