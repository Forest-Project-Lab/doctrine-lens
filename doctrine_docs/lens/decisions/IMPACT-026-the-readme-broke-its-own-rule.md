# 刻印なしで古びた数の影響

## 影響する文書

| 文書 | 何を直したか |
|---|---|
| `README.md`（ビュー） | 拍の所要を刻印つきの表へ。地図時代の節点数を「〜だった」へ。古びていた事実を残す |
| `CHANGE-026`・`IMPACT-026` | 新設（この二つ） |

**正本は動かない。** `ADR-008`（拍を二つに分ける）も `ADR-021` 決定 5 も、
決めたことは変わらない。**ビューが正本に追いついた**だけである。

## 影響する実装

| ファイル | 変更 |
|---|---|
| `tools/measure-tree.mjs` | 拍の所要を測る段を足す。五つの部品と二つの拍、三回の中央値。名札を中身に合わせる |

`src/` は一行も動かない。

## 影響するテスト

単体試験は増えない。**この道具は門ではない**——所要は機械ごとに違うので、
CI の走行機の速さで赤くしない（`CHANGE-026` の却下した選択肢）。

道具の正しさは、**名札が中身と合っているか**で確かめた。

| 確かめたこと | 実測 |
|---|---|
| `fetchSnapshot` が dep-graph だけか | **違う。** 登録簿・範囲・所見・逆孤児・辞書までを一度に取る |
| 名札を直したあとの数 | 速い拍 2022 ms・遅い拍 3516 ms（部品の和 3202 ms より小さい。並べて走らせるため） |
| 引数の順 | `fetchFindings` と `fetchGlossary` の呼び方を最初に間違え、走らせて落ちた。直した |

## 実測

`21131e4` の木・106 文書・三回の中央値。

| 部品 | 45 文書のとき | 106 文書のいま | 倍率 |
|---|---|---|---|
| 登録簿 | 21 ms | 17 ms | 0.8 |
| 辞書 | —（測っていなかった） | 37 ms | — |
| `trace-index` | 645 ms | 604 ms | 0.9 |
| `docs-audit` | 543 ms | **2544 ms** | **4.7** |
| 一巡 | 約 1.9 s | 速い 2022 ms・遅い 3516 ms | — |

**監査だけが木の大きさに効く。** これは `ADR-008` が拍を二つに分けた理由そのもので、
**その根拠となる数を、いままで持っていなかった。**

| 何 | 前 | 後 |
|---|---|---|
| README の刻印の無い測定 | **2 箇所** | **0** |
| 拍の所要の出所 | 手 | `tools/measure-tree.mjs` |
| 名札と中身の食い違い | 1 | 0 |

## 工数見積

**事後に立てた見積は置かない**（`ADR-017`）。`CHANGE-025` で README を
触ったついでに他の数を見て回り、同じ巡で直した。

## 順序の不変条件

**道具を先に作り、数は道具から取る。** 手で測って README に書くと、
次に木が育ったときにまた古びる。今回古びていたのは、
**前回それを手でやったから**である。

**名札を確かめてから数を出す。** `fetchSnapshot` を `dep-graph` と名乗ったまま
出していたら、「dep-graph が 3.5 秒」という嘘を刻印つきで凍らせるところだった。
**刻印は数を凍らせるが、名札の誤りは凍らせても誤りのままである。**
