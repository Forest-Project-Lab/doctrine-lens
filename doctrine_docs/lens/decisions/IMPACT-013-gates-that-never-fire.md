# 発火していない門を塞ぐことの影響

## 影響する文書

| 文書 | 何を直したか |
|---|---|
| `TEST-007` | 受入に「主張を一つも持たない試験が無い」。退行観点に零件の主張と常に真の条件 |
| `ADR-024` | 新設 |
| `IMPACT-013` | 新設（この文書） |

`SPEC-006`・`SPEC-007` の受入は増やしていない。**画面の振る舞いは変えていない**——
変えたのは門の側だけである。

## 影響する実装

**無い。** 門だけを直した。

## 影響する門

| 門 | 何を変えたか |
|---|---|
| `tools/shoot-preview.mjs` | 通知の状態を読み、`07-notice` が「出たこと」を主張する。段を一つ足して「空の通知で消えること」も見る |
| `src/test/paths.test.ts` | 零件の主張をやめ、`null` のときに何を期待するかを書く |
| `src/test/cadence.test.ts` | 常に真の条件（`staleIds.size >= 0`）を落とす |
| `src/test/mutation-table.test.ts` | 「主張を一つも持たない試験が無い」を足す |

## 実測

| 何 | 前 | 後 |
|---|---|---|
| 発火していない門 | 3 | **0** |
| 写しの段 | 7 | **8** |
| 単体試験 | 227 | **228** |
| 主張を一つも持たない試験 | 0（門で固定） | **0** |

## 順序の不変条件

**探し方を先に検める。** 「主張を持たない試験」を括弧の数で探したら、
正規表現リテラルの `{` に騙されて三本を誤って挙げた。
**門を作るときに門が嘘をついた。** 数え方を変えて 0 件になることを確かめてから門にした。

**壊して確かめる。** 三つとも、故意に壊して赤くなることを見た。
`07-notice` は通知の描画を殺して `exit=1`、`mutation-table` は主張の無い試験を一本足して赤。
