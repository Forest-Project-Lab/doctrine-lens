# 走査が挙げた残りを、一件ずつ測ってから直した

## 何が起きているか

`CHANGE-027`（高 3 件）と `CHANGE-028`（層に門が無い 7 件）で直した残り、
**12 件**を片づける。どれも**実物で走らせて再現してから**直した。

## 門の側（緑を名乗っていたもの）

### 1. 用語の門が、点検器の内部故障を「辞書と合う」と読む

上流の `term-check.py` は頭注が
「常に終了コード 0（リンタの一機能として Hook 連鎖を壊さない）」と明記しており、
内部例外を握り潰して `term-check: internal error: …` を標準出力に一行出す。

こちらの門は `[ERROR]` の行しか見ていなかった。
**辞書を一度も引けなかった回が、緑になっていた。**

### 2. 脚注の正の向きが、一度も検められていない

`footHeaviest`（記号と事実の数が食い違う理由）と `footUnattached`（属さない所見の件数）は、
どちらも**否定形の試験しか無かった**。実測——積む行を丸ごと落としても、
落ちた試験は 0 件だった。

### 3. 受入 34（写しの掃除）に、検め手が無い

撮る前に消すところまでは働くが、**走行のあとに置き場を一度も読み返していなかった。**
「撮り直さない写しが残っていない」は、残っていないことを見て初めて言える。

### 4. 写しの門の題名が、製品の経路を通らない

題名・更新・後継だけが python の一行スクリプトで frontmatter を直に読んでおり、
製品が通す `docMetaFrom`（上流が節点に載せた値を読む）を迂回していた。

**いま測ると 112/112 で完全に一致する。**だが一致していることを誰も見ていない——
上流が節点に載せる値と frontmatter の生の値がずれた回に、写しは気づけない。

### 5. `design.test` が長形を見ず、零件を「一つ」と読む

- 余白の照合が `padding|margin|…` の短形だけで、`margin-left: 7px` に当たらない。
- 角丸も同様（`border-top-left-radius`）。
- 読み幅の照合が `if (widths.length === 1)` に包まれており、
  **CSS から `max-width` が消えた回に何も検めずに通る。**
- **`line-height` をどの門も見ていなかった。**

## 文書の側（正本が実装より古い）

### 6. 「上流の CLI が七本」は、実際 11 本

python の身代わりを `pythonPath` に渡して子プロセスを数えた（実測）。

| 拍 | 本数 | 中身 |
|---|---|---|
| 速い | **5** | `dep-graph --classify-edges`・登録簿の問い合わせ・`trace-index`・`dep-graph --reverse-orphans`・辞書の問い合わせ |
| 遅い | **6** | 上の五本＋`docs-audit` |
| 合計 | **11** | 一回の保存で両方が張られる |

五箇所（`SPEC-005`・`session.ts`・`extension.ts`・`trace.ts`・`trace.test.ts`）が
「七本」と書いていた。

### 7. `ICD` が「入力は四つ」と名乗るが、実装は六つ取る

表に `dep-graph --reverse-orphans` と辞書の問い合わせが無かった。
`CHANGE-017` は死んだ名乗りを外したが、**数はそのままだった。**

### 8. `SPEC-001` の三箇所が実装より古い

- 登録簿の出力を「四つ」と書くが、実測は三つ（`projectionTypes` は `CHANGE-010` で
  捨てており、`src/` の参照は **0 件**）。
- 「実行する命令は次の一つだけ」と書くが、`dep-graph.py` は二回起きる。
- 速い拍の列挙が三つ（実測は五つ）。

## 実装の側

### 9. `checksRun` の `[]` が「0 検査」と刷る

上流が `checks_run` を返さない回、橋が**空配列へ潰していた**。
空配列は長さ 0 という数である——画面は
「上流の監査を HH:MM に走らせた／**0 検査**」と刷った（`ADR-023` の破れ）。

裏返しに「どの検査が走ったか分からない」の脚注は**一度も到達できなかった。**

### 10. 生産者の居ない枝と、書いて読まない持ち物

`partialName` の `"titles"` の枝には送り手が一人も居ない
（題名の欠けは脚注で告げる設計に移った。`ADR-020`）。
引数が `string` だったので型も咎めなかった。
`#ready` は書くだけで、読み手がどこにも無かった。

### 11. 注釈の数が古びていた

「実測で推移は最大 43 件、直は最大 7 件」。
測り直すと**推移 68・直 41**（`fca08db` の木・112 節点）。
`7` は `CHANGE-016` 自身が「誤りだった」と記録した数である——
**訂正が実装の注釈まで届いていなかった。**

### 12. 引数を要る命令が、黙って返る

三つの命令はパレットから伏せてあるが、`keybindings.json` に割り当てると
引数無しで呼ばれる。**押したのに何も起きず、理由がどこにも出なかった。**

### 13. 帯に、直し方が一つも出ない

失敗の帯は上流の生の標準エラー（空のことも在る）だけを tooltip に置いていた。
案内（`pythonPath` を確かめよ・待ち時間を上げよ）は明細にしか無く、
**明細を開いていない利用者には届かなかった。**

## 変更内容

1. 用語の門が `term-check: internal error` を見て 2 で止まる。
2. 脚注の正の向きを二本（`006-28d`・`006-22f`）。
3. 写しの門が、走行のあとに置き場を数え直す。
4. 写しの門が `docMetaFrom` を通る。python の一行スクリプトを捨てる。
   `tools/preview-webview.test.mjs` で経路を凍らせる。
5. `design.test` の長形・零件・`line-height` を塞ぐ。補助段に行送り 1.5 を当てる。
6〜8. 文書の数を実測値へ（11 本・六つ・三つ・二つ・五本）。
9. `checksRun` を `null` で運ぶ。橋の層に門（`006-29b`）。
10. 死枝と `#ready` を消し、`partialName` の引数を `PartialFetch["what"]` へ。
11. 注釈の数を**刻印つきで**書き直す。
12. 引数の無い呼びに、理由を出す。README で三命令を区別する。
13. 案内を `l10n` へ移し、**帯と明細が同じ文を使う**。

## 却下する見込みのもの

**「いま一致しているから」で経路を二つ残す**（4）。却下する。
一致は**測って初めて言える**。測っていない一致は、ずれた日に気づけない。

**`line-height` を DESIGN.md の表から落とす**（5）。却下する。
表が四段を定めていて実装が三段しか使っていないなら、**足りないのは実装の側**である。

**古びた数を消す**（11）。却下する。「43 件は 280px で読めない」は
推移の全部を並べない理由である。消すと理由の根拠が消える。刻印を添えて残す。

## 見えている難所

**注釈の中の数には、門が無い。** 文書の実測（`docs:measured`）は
「`<id>` を起点に置くと `<N>` 行」の形だけを見る。
実装の注釈に書いた「最大 68 件」は、木が育てば古びるが誰も咎めない。
いまは刻印を添えることでしか守っていない。

**`design.test` は `src/panel/html.ts` しか見ない。** webview 側に
別の style が生えたら、そちらは検められない。

## 理由（要求元）

`ADR-023`（取れていない数を出さない）・`ADR-024`（発火していない門を緑と呼ばない）・
`ADR-021` 決定 5（測った数には刻印）。
六観点の走査が挙げ、六体の検証が**実物で走らせて**再現した。
