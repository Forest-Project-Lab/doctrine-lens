# 「現行だ」と言うのをやめる

## 変更内容

上流 0.8.0 が節点の白名簿を捨てたので、届く項が 8 から 14 に増えた。
何を足せるかを見にいったが、**測ったら足すものは無く、消すものが在った。**

### 1. 上流が現行と呼ぶ status を、行に出さない（消す）

280px で行の見出しを実測した。

```
1 行 :: 帰結の明細 / SPEC-006 / current / 2
2 行 :: コード側の面の受入 / TEST-005 / current
2 行 :: 拡張機能の部品の配置 / IMPL-001 / current
1 行 :: 帰結の明細の受入 / TEST-006 / current
```

**四行すべてに `current` が出ていて、何も区別していない。**

木の全体で測る。67 節点を順に起点に置き、出た行を全部数えた。

| 何 | 実測 |
|---|---|
| 行の総数 | 256 |
| うち非現行 | **48（18.8%）** |
| うち現行 | 208（81.2%） |

`ADR-014` が status を行に出したのは「非現行が現行と交互に混ざる」ためだった。
**混ざっていることが分かればよく、現行だと言う必要は無い。**

`SPEC-006` の受入 14 も既にこう書いている——「**非現行の行に** status が出て」。
**仕様は最初から非現行だけを求めていた。実装が言い過ぎていた。**

判定はしない。**上流に訊く。** 上流の `_registry` はこう書いている。

```python
CURRENT_STATUSES = frozenset({"current", "accepted"})
# Other slices MUST use this, never a bare `== "current"`.
```

そしてこの値は、**すでにこの実装が取得している**（`registry.ts` の問い合わせが
`currentStatuses` を返している）。**取って、使わずに捨てていた。**

### 2. 要約に「非現行 u」を足す（数で支える）

`ADR-014` は「良い状態を空白で表さない」と決めている。
行から語を消すのは、その決定と正面からぶつかる。

**消した分を数で支える。** 要約の事実の行に非現行の件数を足す。

```
既に壊れている p ・ 足りない q ・ 範囲が無い r ・ 非現行 u
```

読み手は u を見て、明細の中に status の付いた行が u 本在ることを確かめられる。
**空白が「良い」を意味するのではなく、数がそう言う。**

### 3. 上流が現行を教えてくれない回は、今までどおり全部出す

登録簿は部分失敗しうる（`SPEC-005`）。取れなければ**どれが現行かを判じられない。**

そのときは**隠さない。** 全行に status を出し、非現行の件数も出さない。
**隠す根拠が無いときに隠さない**（`ADR-017`「画面は確かめたことだけを言う」）。

### 4. `projectionTypes` の取得をやめる（捨てる）

登録簿の問い合わせは `projectionTypes` を返しているが、**実装のどこからも使われていない。**
`CHANGE-004` で地図を捨てたときの取り残しである。

| 登録簿の項 | 実装での使用 |
|---|---|
| `types` | 門（`REQ-003` の語彙）だけ |
| `allStatuses` | 門（`REQ-003` の語彙）だけ |
| `currentStatuses` | **0 → この変更で使う** |
| `projectionTypes` | **0 → 捨てる** |

## 却下したこと

**足す案を四つ検討し、四つとも実測で却下した。** 記録を残す。

### 却下 1 — 行に型を語で出す

「初学者は `SPEC` が何かを知らない」ので、節点の `type` を語で出そうとした。却下した。

**`type` は id の接頭辞と 67 節点すべてで一致する。**

```
節点 67 / type と id 接頭辞が一致 67
例: (ADR-001, ADR) (ADR-002, ADR) (ADR-003, ADR) (ADR-004, ADR)
```

`SPEC-006` の隣に `SPEC` と出しても、**情報が一つも増えない。**
初学者に効くのは型名ではなく**型の意味**だが、それは上流の語彙であり
この木が定義してはならない（`REQ-003`）。上流の用語辞書にも型の意味の表は無い。

### 却下 2 — ドメインを越える行に印を出す

`ICD` を通してしか越えられない境界を越えているのは、読み手に効く事実だと考えた。却下した。

**全 67 起点・256 行で、ドメインを越えた行は 0 件だった。**
この木は `lens` 61・`_system` 6 の二ドメインだが、`_system` の 6 文書は帰結の辺を持たない。

**自分の木で一行も効かないものを足さない。**

### 却下 3 — `review_by` を副文へ出す

期限前に手が打てる、と考えた。却下した。

**67 節点のうち `review_by` を持つのは 1 件である。**
66 行に何も出ない項のために、行の形と試験と意匠の正本を変える価値が無い。
期限切れは上流の所見が挙げ、`CHANGE-006` で所見は既に行へ出る。

### 却下 4 — `owner` を上流へ頼む

節点に `owner` が載らない。役割別の読解でも「誰が直すのか」が三役から挙がった。却下した。

```
63  owner: doctrine-lens-maintainer
 3  owner: render-projection      （投影が書き出すもの）
 1  owner: <記入>                 ← 雛形のまま残っていた
```

**この木では owner が誰も区別しない。自分の木で効かないものを上流へ頼まない。**

ただし `owner: <記入>` は別の問題だった。**用語辞書の正本が、初期化から今日まで
雛形の指示文を持ったままだった。** 直したうえで上流へ報告した（`doctrine#182`）。
36 検査すべてが、この値を素通しする。

## 理由

`DESIGN.md` 9-4 は「説明を足したくなったら、まず消すものを探す」と書いている。
**探したら見つかった。** 足す案は四つとも実測で死に、消す案だけが残った。

`REQ-002`「一つの画面は一つの問いだけに答える」。画面は増やさない。行は短くなる。

### 見積が外したこと 1 — 必要な値は、既に手元に在った

「上流に頼む必要が在るか」から考え始めたが、**`currentStatuses` は最初から取得されていた。**
`CHANGE-004` で地図を捨てたときに使い手が消え、取ったまま捨てる値になっていた。

**設計を「無いもの」から始めていた。** 手元に何が在るかを先に測るべきだった。

その反省をそのまま門にした——「登録簿の写しの各項に使い手が居ること」。
そして**その門が、書いた直後に本物を挙げた。**

```
not ok - 006-26. 上流から取って使わない値を、登録簿の写しに残さない
  登録簿の types を取っておいて使っていない（字面 2 箇所）
```

`types` と `allStatuses` は**門だけが使っていた**（実装が語彙を持たないことを、
上流の語彙そのもので検める）。門も使い手である。規則を「偽の登録簿を除いた
どこかで使われていること」に書き直した。**自分の門の言い分を、自分で疑う**（`ADR-017`）。

### 見積が外したこと 2 — 写しの道具が、三度同じ形で落ちた

写しの道具が新しい項（`currentStatuses`）を渡しておらず、`Cannot read properties of undefined`
で落ちた。**`checksRun`・`glossary` と同じ形で、三度目である。**

原因は道具が**登録簿の問い合わせを自前で持っていた**ことだった（本体と二重）。
本体の `fetchRegistry` を使う形に直し、二重を捨てた。

そのうえで、**画面の上で数と行が一致すること**を門にした。
故意にずらして両方向で赤くなることを確かめた。

```
語る行 17 本と要約の非現行 4 が食い違う      ← 現行の行にも出したとき
要約に非現行の数が出ていない                 ← 数を落としたとき
```

### 見積が外したこと 3 — 門を、手元の版に当てていなかった

突然変異の門を、**未コミットのまま回した。** この道具は commit から隔離木を立てるので
（`ADR-016`）、検めていたのは**一つ前の版**だった。

気づいたのは 20 分後で、新しく足した五行が「対象不明」と報告されたからである。
**古い 50 行は、古い版に対して緑を返し続けていた。**

道具の頭注には「既定は commit を潰すので、未コミットの変更は検査対象に入らない」と
書いてあった。**書いてあることは、走行中に読まれない。**

始めに言うようにした。

```
注意: 作業木に未コミットの変更が 12 件ある。
検めているのは 16048d9a であって、手元の版ではない。
  手元の版を検めるには、先にコミットすること。
```

`ADR-017` 決定 2 の一例である——**門が緑でも、それが何についての緑かは別に確かめる。**

### 見積が外したこと 4 — 足したら、要約が 280px で六行になった

非現行を足した結果、要約の三行目に括弧の注記まで載って行が伸びた。
**足すことで、消したぶんを取り返していた。**

説明を脚注へ移した。「右端の数が何を数えたものか」を脚注で言うのと同じ扱いである。
そして**食い違っている回だけ出す**——一致している画面では説明だけが浮く。

### ついでに直したこと — README の写真が四版古かった

写真は 7/29 のもので、**`CHANGE-009` で捨てた `titles.ts` がまだ写っていた。**
要約の形も四行前の版だった。

この製品は「文書とコードの食い違い」を見せる道具である。
**その README が四版ぶん食い違っていた。** 撮り直した。

起点を `REQ-001` に取った。11 行のうち 4 行だけが `deprecated` と言い、
要約が `not current 4` と言う画面である。**写真そのものが主張の証拠になる。**
