# この製品が何を解くかを、木の中に置く

## 何が起きているか

**この木は「何を解くか」を木の外にしか持っていない。**

利用者から挙がった問いがそのままこれだった。

> このプロダクトはなにか。コアドメインは何で何が実現しないといけないのか。
> そうなるまでの変異は何か。……時系列と、意思決定、何を解決しようとしているのかが分からない。

測ったら、`REQ` 四本はすべて**機能の粒度**だった。

| | 題 | 粒度 |
|---|---|---|
| `REQ-001` | いま触れているものから、直すことになるものを順に辿る | 機能 |
| `REQ-002` | 一つの画面は一つの問いだけに答える | 機能 |
| `REQ-003` | 統治の規則を二重定義しない | 機能 |
| `REQ-004` | コードを読んでいるときに、その根拠の文書へ行ける | 機能 |

**製品として何を解くかを言う文書は無い。** 内容は `README.md` にしか無く、
`README` は**ビュー**である（人が手で書く体系外の文書。刻印で参照時点を示す）。

**この体系の値打ちは「正本を一つ持つ」ことなのに、その一点だけ正本が木の外に在る。**

## 上流が同じことを見つけていた

`doctrine#153` として出したところ、上流も自分の木で同じ形を見つけた（上流の決定・doctrine#153 の返答）。

> 呼び手の木でも `REQ` 四本すべてが機能の粒度で、製品として何を解くかを言う文書は無かった。
> つまり製品の目的は、この体系が唯一「外を指して済ませている」ものだった。

上流は**新しい型を足す案を却下**し、`REQ` の置き場所へ `_system/` を足した。

> 型を一つ足すと登録簿・リンタ・雛形・投影・技能・受入の全面に手が入るが、
> 置きたい内容は既に `REQ` の意味に収まる。**粒度は置き場所が言う**（新しい欄を作らない）。

`v0.9.0` で降りてきた。実測で確かめた。

```
REQ の置き場所: ['<domain>/', '_system/']    ← 0.8.0 は ['<domain>/'] のみ
```

## 変更内容

1. `_system/` へ製品の粒度の要求を書く。**粒度は置き場所が言う。**
2. 内容は `README.md` から移す。**新しく考えない**——既に在るものへ正本を与える。
3. `README` の側は**ビューのまま**にする。正本を指し、刻印で参照時点を示す。
4. 既存の `REQ` 四本との関係を書く。新しい要求は**辺では指されない**——
   横断の正本は本文で参照される（上流が実装で確かめた不変条件）。

## 見えている難所

**この要求に辺を張れない。** ドメインの文書から `_system` の文書へ `depends_on` を
張ろうとすると、越境依存のガードが「`_system` の ICD 宛にしてください」と拒み、
**`_system` に ICD は無い**。実測で確かめた。

```
[error] icd_dependency_violation: 対象は _system の内部です。_system の ICD 宛にしてください。
```

上流は逆孤児の検査から `_system/` の `REQ` を外すことでこれを解いている。
**辺では指さず、本文で参照する。** それがこの体系の規約である。

**`README` を正本にしない。** 内容を移しても `README` から消さない——
`README` は利用者が最初に読む面であり、**ビューが正本を写すのは正しい**（上流の刻印がその印）。

## 理由（要求元）

`REQ-003`「統治の規則を二重定義しない」の裏返しである。
規則の正本を上流に置くのと同じ理由で、**目的の正本も木の中に置く。**

### 上流の版を、自分で切った

`0.8.0` のままでは書けなかった。実測で行き止まりを確かめてある。

```
_system/ に置く          → [error] reverse_orphan_req_no_spec
仕様を繋いで解こうとする → [error] icd_dependency_violation（_system に ICD は無い）
```

利用者から「バージョン書き換えておいて／書き換えられない理由がわからない」と言われ、
**権限を測ったら `push=true` だった。** 「動かせない」は私の誤りだった。

上流のリリース手順（PROC）に従って `v0.9.0` を切った（上流 PR #186）。
全門を先に回し（試験 **1116 件**緑・監査 error 0・`release-check` ほか rc=0）、
**公開ビュー 3 件の内容を検めてから刻印を打ち直した**——
その検めで `plugin/README.md` の古び（共有コア `_hookio.py` が一覧に無い）が出て、直した。

`claude plugin update --scope project` で `0.8.0 → 0.9.0` に降ろし、
**この木が使う版が切り替わったこと**まで確かめた。

### 分かったこと — 版番号は中身を指していない

手元の「0.8.0」は `7d2769b` の時点の中身だった。

```
installed_plugins.json:  版 0.8.0  sha 7d2769b1
```

**キャッシュのフォルダ名＝版番号、中身＝取り込んだ時点のコミット。**
同じ版番号でも人によって中身が違う。版を上げないと取り直されないのは、
**版番号がキャッシュの鍵だから**である。

### 見積が外したこと — 「待つしかない」は誤りだった

手元の marketplace の複製には上流 main が既に取ってあり、
**取り出せば今日でも確かめられた**（`git archive origin/main plugin`）。

私は「書けない」と言っていたが、正しくは**「書けるが、まだ入れられない」**だった。
利用者の「主語は何でしょうか？」がそれを暴いた。
