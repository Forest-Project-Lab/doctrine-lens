# 生きている ICD が、捨てた概念の正本を名乗っている

## 何が起きているか

`ICD-001` は `status: current` で、こう名乗っている。

```yaml
canonical_for: [depth-levels, lens-dials, upstream-json-contracts]
```

**前の二つは、この製品が捨てた概念である。**

| 名乗っている事実 | 実体 |
|---|---|
| `depth-levels`「深度の段は L0・L1・L2・L3 の四つである。四段すべてを実装する」 | **`ADR-012` が深度を捨てた。** `SPEC-002` は `deprecated` |
| `lens-dials`「レンズが持つダイヤルは色・絞り・配置・深度の四つである」 | **`NONGOAL-001` が「ダイヤルを画面に持たない」と決めた。** 実測で「四つのうち一つは数を四つにするために足した」 |
| `upstream-json-contracts` | **現役。** 上流から受け取る四つの入力の分担表 |

本文も同じ状態である。

- 公開する用語に **`レンズ`・`深度`・`地図`** が並ぶ（三つとも捨てた）
- 入力の用途に「**地図の描画に使う**」「**深度 L3** とコード側の面で使う」

## 根本原因 — `canonical_for` は辺ではない

**この製品自身が解こうとしている問題を、自分の木で踏んだ。**

`ADR-012`（地図を捨てる）を起点に置いても、`CHANGE-004`（帰結へ作り直す）を起点に置いても、
**画面は `ICD-001` を出さない。** 実測した。

```
起点 ADR-012:    行 3   SPEC-006 IMPL-001 TEST-006          ← ICD-001 は出ない
起点 CHANGE-004: 行 12  ADR-015 … TEST-008                  ← ICD-001 は出ない
ICD-001 の辺: 3 本  SPEC-001-depends_on->ICD-001  SPEC-004-depends_on->ICD-001  …
```

**深度とダイヤルの正本を名乗っているのに、深度とダイヤルを決めた文書と一本も繋がっていない。**

`canonical_for` は**名乗りであって辺ではない。** だから概念を捨てても、
その正本を名乗る文書は帰結に出ない。**画面は正しく動いている。木の繋ぎ方が足りない。**

### 上流の欠陥ではない

測って二つ確かめた。

- **`stale_current` が既に在る。** 型の既定点検周期で全現行文書に実効期限を張る。
  `ICD` の周期は **180 日**で、`ICD-001` は `updated: 2026-07-28`——**あと 174 日で咎める。**
  「機械が咎めない」ではなく「**まだ時が来ていない**」だった。
- **「参照されていないトピックを咎める」検査は作れない。** 実測すると、
  この木の 7 トピックのうち参照が在るのは `glossary` だけ（16 件）で、
  それは `src/doctrine/glossary.ts` が**トピック名で場所を引いている**からである。
  現役の `upstream-json-contracts` も参照 0 なので、**参照の有無では生死を判じられない。**

`CHANGE-004` で地図を捨てたとき、`SPEC-002`・`SPEC-003` は `deprecated` にしたが、
**`ICD-001` を影響の一覧に入れなかった。** 辺が無いので画面も教えなかった。

## どうやって見つけたか

**サブドメインの分類を三観点で独立に取ったとき**、二観点が「判じきれない」と返し、
その理由がこれだった。

> `status: current` かつ `canonical_for` が `[depth-levels, lens-dials, upstream-json-contracts]` で、
> 前の二つは `ADR-012`・`NONGOAL-001` が捨てた概念である。
> **生きている文書が退役した事実の正本を名乗っている。**

**分類しようとして初めて、分類できないことが見えた。**

## この変更でやること

1. `ICD-001` から `depth-levels` と `lens-dials` の名乗りを外す。
2. 本文の退役した記述（公開する用語・深度の段・ダイヤル・地図の描画）を、
   **いまの実体に書き直す。**
3. `upstream-json-contracts` は残す。**現役であり、支援層の契約である。**
4. `_system/icd-index.md`（投影）が追随することを確かめる。
5. **残す名乗りを、辺で繋ぐ。** `upstream-json-contracts` の中身を決めているのは
   `SPEC-001`（上流への橋）である。既に `SPEC-001-depends_on->ICD-001` が在るので、
   **上流の契約が変われば `ICD-001` は帰結に出る。** 名乗りと辺が揃う。
6. **直したあとで、同じ形が他に無いかを測る。**
   `canonical_for` を持つのは `ICD-001`・`glossary.md`・`decided-facts.md` の三つである。

## 却下する見込みのもの

- **`ICD-001` を `deprecated` にする。** 三つ目の名乗りは現役であり、
  上流との契約はこの文書にしか無い。**半分が生きている文書を丸ごと殺さない。**
- **`canonical_for` の検査を上流へ頼む。** 実測で、参照の有無では判じられない
  （現役の `upstream-json-contracts` も参照 0）。そして `stale_current` が
  180 日で既に咎める。**上流へ出す前に、この木で直して効くかを確かめる**——
  この一周でそれをやる。効いたうえでなお足りなければ、そのとき測って出す。

## 要求元

`REQ-003`「統治の規則を二重定義しない」の裏側——**捨てた規則を正本として残さない。**

## 実施の記録

2026-08-03 に一周を終えた。

| 何 | 前 | 後 |
|---|---|---|
| `canonical_for` の名乗り | 3（うち **2 つは捨てた概念**） | **1** |
| 生きた文に残る捨てた語 | **11 箇所** | **0** |

### 直したら、上流の検査が連鎖して古びを掘り出した

`ICD-001` の `updated` を上げた瞬間、`source_drift` と `view_stale` が **12 件**発火した。
一件ずつ中身を読んだところ、**`SPEC-001` のエラー時挙動の表に「地図」が 4 箇所**、
`REQ-003`・`REQ-004`・`IMPL-001`・`SPEC-006` の受入 11 にも残っていた。合計 11 箇所。

**`updated` を機械的に上げていたら、全部見落としていた。**
刻印を打ち直すのは「確かめた」の宣言である。

### 残したもの

`REQ-001`・`REQ-002` の言及は「**以前はこう書いてあった**（`ADR-012` で改めた）」という
**変異の記録**であり、`TEST-006` の「深度・レンズ・地図を**戻さないこと**」は退行観点である。
**機械が挙げた 12 件を、一件ずつ人が読んで分けた。**

### 見積が外したこと — 「機械が咎めない」は誤りだった

二つとも測って否定された。

- **`stale_current` が既に在る。** `ICD` の点検周期は 180 日で、
  `ICD-001` は `updated: 2026-07-28`——**あと 174 日で咎める。**
  「咎めない」ではなく「**まだ時が来ていない**」だった。
- **「参照されていないトピックを咎める」検査は作れない。**
  この木の 7 トピックのうち参照が在るのは `glossary` だけ（16 件）で、
  それは `src/doctrine/glossary.ts` が**トピック名で場所を引いている**からである。
  現役の `upstream-json-contracts` も参照 0 なので、参照の有無では生死を判じられない。

**上流へ出すのをやめた。** 自分の木で直して効いた。
