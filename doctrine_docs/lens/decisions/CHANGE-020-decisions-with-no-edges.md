# 決定を変えても、直すものが出てこない

## 何が起きているか

**`ADR-008`（取得を二つの拍に分ける）を起点に置くと、明細は 0 行である**（`40dd24f` の木）。

```
直すことになる文書 0 件 / 前提 0 / 繋がらない 92
```

だがこの決定の実装は在る——`src/session.ts` と `src/model/cadence.ts` である。
**決定を変えても、この製品は何も教えない。**

同じ形が七本ある。

| | 題 | 辺 |
|---|---|---|
| `ADR-001` | グラフの取得を doctrine の Python CLI に委ねる | **0** |
| `ADR-006` | 作業フォルダが複数のときは統治木を持つものを選ぶ | **0** |
| `ADR-007` | 表示の原文を英語にし、日本語を翻訳として持つ | **0** |
| `ADR-008` | 取得を二つの拍に分ける | **0** |
| `ADR-009` | 既定のキー割り当てを持たない | **0** |
| `ADR-010` | 実行体を選ぶ設定は作業フォルダから上書きさせない | **0** |
| `ADR-011` | 起動条件に `onStartupFinished` を足す | **0** |

**七本とも `impacts` も `depends_on` も持たない。**

## 上流は正しく判じている

`adr_not_landed` は鳴らない。**鳴らないのが正解である**——
この検査は本文の id 参照も数えており、七本とも現行の文書から本文で参照されている。

```
ADR-001: 本文から参照している現行文書 6 件
ADR-008: 6 件 / ADR-006: 4 件 / ADR-009: 4 件 …
```

**「決定が文書の上で着地しているか」と「変えたときに何を直すかが引けるか」は別である。**
上流は前者を見ている。後者はこの製品の問いであり、**この製品が答えられていない。**

## なぜ効くか

`REQ-000` はこう書いている。

> これを変えたら、何を、どの順で直すことになるか。

**決定は変わる。** `ADR-013` の「等幅は二段」は `ADR-027` が置き換えた。
`ADR-005` は `deprecated` である。**決定を変えるときこそ、この画面が要る。**

七本のうち `ADR-008`（拍）と `ADR-010`（設定の scope）は、
**変えると利用者の環境に触る**。そこで「直すものは無い」と出るのは危うい。

## 変更内容

1. 七本に `impacts` を書く。**その決定が縛っている仕様・実装の文書**を指す。
2. **辺を捏造しない。** 本当に縛っていないものは指さない。一本ずつ本文を読んで決める。
3. **「辺を持たない現行の決定」を門にするかを、測ってから決める。**
   `CTXMAP`・`OVERVIEW`・`DECIDED`・`NONGOAL`・`REQ-000` は辺を持たないのが正しい形なので、
   型で除くだけの門は擬陽性を生む。

## 見えている難所

**`ADR` は不変である。** 本文は書き換えない。だが `impacts` は frontmatter であり、
**決定の中身ではなく、決定がどこへ効くかの宣言である。**
上流の雛形も `impacts` を任意項として持つ。**足すことは決定の書き換えではない。**

ただし**これは判断を含む**。「`ADR-007`（原文は英語）は何を縛っているか」は、
`src/l10n.ts` と `l10n/bundle.l10n.ja.json` だが、**文書としては `IMPL-001` である。**
一本ずつ読んで決める。

## 理由（要求元）

`REQ-000`「これを変えたら、何を、どの順で直すことになるか」——
**決定を変えるときに答えられないなら、この製品の中核が自分の木で働いていない。**

## 影響の初期見積

| 区分 | 見積 |
|---|---|
| 書き直す文書 | `ADR-001`・`006`〜`011` の frontmatter（7 本） |
| 新しく作る文書 | `IMPACT-020` |

| 触る門 | 無し（門にするかは測ってから） |

## 実施の記録

2026-08-03 に一周を終えた。

| 起点 | 前 | 後 |
|---|---|---|
| `ADR-008`（二つの拍） | **0 件** | **13 文書・コード 18 か所・波 5** |
| 辺を持たない現行の文書 | 13 件 | **6 件** |

### 逆から測った

「この `ADR` は何を縛っているか」を本文から読むと、**七本のうち六本は自分では何も引いていない。**

代わりに「**どの文書がこの `ADR` を引いているか**」を測った。
それが実際に効いている先である。決定の側から想像して書くと、**辺を捏造する。**

### 残る 6 件は、辺を持たないのが正しい

`CTXMAP-001`・`DECIDED-001`・`NONGOAL-001`・`OVERVIEW-001`・`OVERVIEW-002`・`REQ-000`。
投影と横断の正本であり、`ADR-026` が「辺では指さず、本文で参照する」と決めている。

**門にしなかった。** 型で除くだけの門は、この 6 件を毎回咎める。
「辺を持たないのが正しい型」を実装が持つと、それは上流の語彙を持つことになる（`REQ-003`）。
