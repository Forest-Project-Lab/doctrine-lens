## 影響する文書

| 文書 | 何を直したか |
|---|---|
| `REQ-000`（`_system/`） | **新設。** 製品の粒度の要求 |
| `README.md` | 正本を指す一行を足す（内容は消さない。ビューのまま） |
| `OVERVIEW-001` | 投影が自動で拾う |
| `ADR-026`・`IMPACT-015` | 新設 |

`REQ-001` 〜 `REQ-004` は**直していない**。四本の内容は変わらず、
`REQ-000` が本文でそれらとの関係を言う（辺は張らない）。

## 影響する実装

**無い。**

## 影響するテスト

**無い。** `REQ-000` は辺を持たないので、帰結の明細に出ない。
文書の実測を検める門（`check-measured-claims`）にも当たらない。

## 実測

| 何 | 前 | 後 |
|---|---|---|
| 製品の粒度の要求 | **無い**（`README` にしか無い） | **`REQ-000`** |
| `REQ` の粒度の内訳 | 機能 4 | 製品 1・機能 4 |
| 監査 | error 0 / warn 0 | **error 0 / warn 0** |
| 上流の検査 | 36 | **37**（雛形が定める節の検査が加わった） |

**上流の版を上げてから書いた。** `0.8.0` では逆孤児の error が出る
（`_system/` の `REQ` が検査から外れていなかった）。実測で確かめてある。

## 工数見積

**事後に立てた見積は置かない**（`ADR-017`。確かめたことだけを言う）。
この変更に先立つ見積は無い。見つけたその巡で直し、PR まで通した。
実際に動いた量は `090ac69`——8 ファイル・+455／−1。

## 順序の不変条件

**上流の版を先に上げる。** `v0.9.0` を切ってから書いた。
`0.8.0` のままで書くと、`reverse_orphan_req_no_spec` が error になり、
**それを解こうとして辺を張ると越境依存の error になる**（行き止まり）。

**`README` から消さない。** 消すと、この製品を初めて見る人が何も読めなくなる。
ビューが正本を写すのは正しい。
