# 受入の番号が、仕様と試験でずれている

## 何が起きているか

`TEST-006` は冒頭でこう書いている。

> SPEC-006 の受入基準の十二項に一対一で対応させる。

**一対一でない。そして十二項でもない**（`SPEC-006` の受入は 26 項ある）。

`CHANGE-010` で受入 23〜26 を足したとき、**既に別の主題が同じ番号を使っていた。**
同名の試験が四組できた。

実測で対応を出した。

| `SPEC-006` の受入 | それを検める試験の名 |
|---|---|
| 15 起点自身に所見 | `006-16.` |
| 16 「外」の定義 | `006-17.` |
| 17 記号の和 | `006-19.` |
| 18 強連結成分 | `006-15.` |
| 19 辿る向き | `006-20.` |
| 20 範囲の不在と未取得 | `006-21.` |
| 21 語の定義 | 番号を持たない名前（`titles.test.ts`） |
| 22 出ていない所見の行き先 | `006-25.` |

そして、仕様に番号の無い主題が番号を占めている。

| 試験 | 仕様のどこ |
|---|---|
| `006-18.` 排他に負けた事実 | 受入 17 の後半 |
| `006-22.` 迂回路と直の辺 | 制約（番号無し） |
| `006-23.` 空白だけの題名 | 受入 5 の周辺 |
| `006-24.` 所見の六項 | 受入 9 |

**番号は飾りになっていた。** 誰も突き合わせていないので、ずれても誰も気づかない。

## 実害

潰しの門の判定は `not ok N - <名>` から**名前だけ**を取る（`mutate-verdict.mjs`）。
同名の試験が二つ在ると、**「どちらが捕まえたのか」が報告から読めない。**

`node:test` は同名を黙って許すので、機械も人も止めなかった。

## いま打った手（`CHANGE-010` の中）

- 番号を先取りしていた古い試験六本を「（受入 N）」の形へ改名した。
  **虚構の番号を増やさない**ためであり、対応そのものは直していない。
- **同名の試験を禁じる門**を足した（`SPEC-007` 受入 10）。両方向で確かめた。

## この変更でやること

1. `SPEC-006` の受入番号と、試験の名の番号を**一対一に揃える**。
2. 番号を持たない試験（語の定義など）にも、受入の番号を与える。
3. 仕様に番号の無い主題（迂回路・排他に負けた事実）に受入の番号を与えるか、
   「制約を検める試験」として番号を持たない形へ寄せる。**どちらかに決める。**
4. `TEST-006` 冒頭の「十二項に一対一で対応させる」を実態に合わせる。
5. **突き合わせを門にする。** 受入 N には `006-N` の試験が在るか、
   `TEST-006` が「画面側が受け持つ」と明記しているか、のどちらかであること。

## なぜ `CHANGE-010` に混ぜないか

`CHANGE-010` の主題は「既定を語らない」であり、これは別の欠陥である。
**一周に主題を二つ入れると、どちらの影響も測れなくなる。**

ただし**同名の試験は実害が在る**（潰しの報告が読めない）ので、
そこだけは `CHANGE-010` の中で塞いだ。

## 要求元

`REQ-001`「いま触れているものから、直すことになるものを順に辿る」——
この製品自身の木で、仕様から試験へ辿れないなら、製品の主張が立たない。
