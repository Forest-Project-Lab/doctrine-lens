# 潰しの合否は試験の終了符号で決め、出力の照合は補助に降ろす

## 背景

`tools/mutate-check.mjs` は、潰した行に対応する試験が本当に落ちるかを実測する道具である。
その合否が、試験の出力を `^not ok \d+ - (.+)$` に掛けた**一致数だけ**で決まっていた。

```js
const out = capture(`node --test ${TEST_GLOB}`);
const failed = [...out.matchAll(/^not ok \d+ - (.+)$/gm)].map((m) => m[1].trim());
return { verdict: failed.length > 0 ? "試験が落ちた" : "試験は通った", failed };
```

`capture` は子processの終了符号を捨てていた。例外を捕らえて `stdout` と `stderr` を
連結して返すだけで、`status` も `signal` も呼び出し側へ届かない。

**同じファイルが、そのすぐ上のコメントで逆のことを宣言していた** ——
「合否は試験の終了符号だけで決め、型検査が落ちる潰しは『潰し方が不正』として別に扱う」。
宣言は終了符号で決めると言い、実装は終了符号を捨てて正規表現で決めていた。

実測（Node v22.22.3、`capture` と同じ `execFileSync("sh", …, {stdio:"pipe"})` 経路）:

| 与えた状況 | 終了符号 | `^not ok` の一致数 | 道具の判定 |
|---|---|---|---|
| 存在しない試験ファイルを指す | 非ゼロ | 0 | **「試験は通った」** |
| 既定 reporter が TTY で `spec` になる | 1 | 0 | **「試験は通った」** |
| パイプ経由で既定が `tap` になる | 1 | 1 | 「試験が落ちた」（正しい） |

外部レビューは Node v24.14.0 の既定 reporter で同じ「一致数 0・終了符号 1」を観測している。
つまりこれは特定の版の問題ではなく、**終了符号を捨てていることの帰結**である。

帰結は二段に効く。baseline の門で誤ると、木が緑でないのに緑として走り出し、以降の全行の
判定が無意味になる。各行で誤ると「試験は通った」＝守られていない側へ積まれ、その一覧が
もはや「守られていない直し」の一覧ではなくなる。

`npm run mutate` の最終行「表に載せた N 件は、いずれも試験が捕まえる」は、この parser に
乗っている限り保証値ではない。

## 却下した選択肢

**正規表現を reporter ごとに増やす。** `✖` 形式も読めるようにする案。reporter は増える
一方であり、追いかけ続ける前提を新たに作る。しかも「読めない形式が出たら通った」という
fail-open の芯は残る。

**既定 reporter に依存したまま、TTY のときだけ形式を変える。** 実行環境の性質（出力先が
端末か）で判定の根拠が変わる設計を温存する。CI と手元で違う答えが出る。

**parser が読めない非ゼロを `survived` に寄せる。** 安全側に倒しているように見えるが、
足場の故障（読み込み失敗・timeout・シグナル死）を「試験に守られていない直し」として
報告することになり、直す先を誤らせる。故障は故障として立てる必要がある。

## 決定

**合否は試験processの終了符号とシグナルで決める。出力の照合は「どれが落ちたか」を人へ
見せるための補助に降ろし、判定の根拠から外す。**

1. `capture` は `status` / `signal` / `stdout` / `stderr` を保持して返す。
2. 非ゼロは必ず失敗として扱う。ゼロは必ず成功として扱う。
3. reporter は `--test-reporter=tap` で明示的に固定する。既定に頼らない。
4. 次を別々の状態にする —— `試験は通った` / `試験が落ちた` / `型検査が落ちた` /
   **`検査器の異常`**。最後の一つは、終了符号と出力が噛み合わない全ての場合を引き受ける
   （非ゼロなのに `not ok` が無い、ゼロなのに `not ok` が在る、シグナルで死んだ）。
5. `検査器の異常` は `survived` へ寄せず、走行を止めて非ゼロで終える。
6. **道具は自分の判定器を、走り出す前に検める。** 意図的に落ちる canary と通る canary を
   一時ディレクトリで走らせ、前者を「落ちた」、後者を「通った」と読めることを確かめる。
   読めなければ score を出さずに終える。
7. 報告に Node の版・reporter・試験コマンド・対象 commit を刻む。

## 帰結

- 「表に載せた N 件は、いずれも試験が捕まえる」が、parser の運ではなく終了符号に係る。
- reporter が将来また変わっても、判定は変わらない。壊れるのは補助表示だけである。
- 足場の故障が、守られていない直しの一覧に混ざらなくなる。
- 検査器が自分を検めるので、判定器が壊れた走行では数字が出ない（R11 の型）。
- 保証限界: canary が検めるのは判定器（終了符号の読み・TAP の照合）だけである。潰す表が
  正しいこと、覆う範囲が十分であることは、依然として検めない（頭注の但し書きのとおり）。
