# 目的の正本も、木の中に置く

## 背景

**この木は「何を解くか」を木の外にしか持っていなかった。**

`REQ` 四本はすべて機能の粒度で、製品として何を解くかを言う文書は無い。
内容は `README.md` にしか無く、`README` は**ビュー**である
（人が手で書く体系外の文書。刻印で参照時点を示す）。

**この体系の値打ちは「正本を一つ持つ」ことなのに、その一点だけ正本が木の外に在った。**

利用者の問いがそれを突いた——「時系列と、意思決定、何を解決しようとしているのかが分からない」。

## 決定

### 1. 製品の粒度の要求を `_system/` に置く

粒度は**置き場所が言う**。新しい欄も新しい型も作らない。

- `<domain>/` の `REQ` — その区画の機能の粒度
- `_system/` の `REQ` — 製品の粒度

上流が `v0.9.0` で `REQ` の置き場所へ `_system/` を足した（`doctrine#153` の返答）。
**新しい型を足す案は上流が却下している**——置きたい内容は既に `REQ` の意味に収まる。

### 2. 内容は `README` から移す。**新しく考えない**

既に在るものへ正本を与えるだけである。**新しく考えると、`README` と食い違う。**

上流も同じ形を採った——「内容は README の記述から移した —— 新しく考えず、
既に在るものへ正本を与えた。使わない仕掛けを足さない」。

### 3. `README` は残す。ビューのまま、正本を指す

内容を移しても `README` から消さない。**`README` は利用者が最初に読む面**であり、
**ビューが正本を写すのは正しい**（刻印がその印である）。

**消すと、この製品を初めて見る人が何も読めなくなる。**

### 4. 辺では指さない。本文で参照する

ドメインの文書から `_system` の文書へ `depends_on` を張ろうとすると、
越境依存のガードが「`_system` の ICD 宛にしてください」と拒み、**`_system` に ICD は無い。**
実測で確かめた。

```
[error] icd_dependency_violation: 対象は _system の内部です。_system の ICD 宛にしてください。
```

**横断の正本は本文で参照され、辺では指されない。** それがこの体系の規約である。
上流も当初は「要求は要求が実現してよい」として逆孤児の判定を広げる案だったが、
**実装してできないことが分かって捨てている。**

したがって `REQ-000` は帰結の明細に**出ない**。それでよい——
この画面は「これを変えたら何を直すか」に答えるものであり、
**製品の目的は「変えたら直すもの」ではない。**

## 却下した選択肢

### 却下 1 — `README` を正本と宣言する

内容は既に `README` に在るのだから、それを正本と呼べばよい。却下した。

**`README` はビューである。** 手で保守し、参照時点を刻印で示す文書であって、
機械が検める対象ではない。実測で、この製品の `README` は**四版ぶん古びていた**
（`CHANGE-010` で撮り直すまで、捨てた `titles.ts` が写真に写っていた）。

**古びる文書を正本にしない。**

### 却下 2 — `lens/` に置く

置き場所は `v0.9.0` 以前でも通った（`<domain>` は文書自身の domain に置き換わる）。却下した。

**粒度は置き場所が言う**（決定 1）。`lens/` に置けば「lens ドメインの要求」と名乗る。
そして逆孤児を解くために**どれか一つの `SPEC` を選んで繋ぐ**ことになるが、
この要求はすべての仕様の前提なので、一つ選ぶのは恣意的である。

### 却下 3 — 新しい型（`PURPOSE` など）を足すよう上流へ頼む

製品の目的は要求とは違う、という考え方もありうる。却下した（上流も却下している）。

**型を一つ足すと登録簿・リンタ・雛形・投影・技能・受入の全面に手が入る。**
置きたい内容は `REQ` の意味に収まる——`REQ` は「存在してよい理由」を持つ型であり、
主語が文書か機能か製品かの違いに過ぎない。

## 帰結

- **この体系が唯一「外を指して済ませていた」ものが、木の中に入った。**
- `REQ-000` は辺を持たないので、帰結の明細には出ない。
- `REQ-001` 〜 `REQ-004` が「どう満たすか」を言う関係が、本文で読めるようになる。

## この決定が及ばないところ

- **`README` の書き方には及ばない。** ビューは人向けの解釈であり、
  正本の書き写しである必要は無い。
- **コアドメイン・サブドメインの分類には及ばない。** 上流が `v0.9.0` で
  `subdomain`（`core`／`supporting`／`generic`）を足したので、それは別に決める。
