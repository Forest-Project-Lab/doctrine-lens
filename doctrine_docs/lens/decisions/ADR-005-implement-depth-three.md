# 深度 L3 を実装し、対象を L0 から L2 に限る決定を解く

## 背景

ADR-003 は最初のスライスを深度 L0 から L2 に限った。その狙いは「地図は描くものではなく
導出されるもの」という主張を最小の実装で確かめることであり、確かめは済んだ。

いま L3 が無いことで、地図は文書の層で止まっている。要求から実装までを一続きでたどる
という REQ-001 の狙いは、コードに届いて初めて満たされる。

コード側の印（`doctrine:begin`／`doctrine:end`）と、各 SPEC の `## 実装の指紋` は
既に打ってある。上流の `trace-index.py` は範囲を、`docs-audit.py` は指紋の食い違いを、
いずれも読み取り専用で返す。土台は揃っている。

## 却下した選択肢

**片方向だけ作る（文書からコードへ）。** 地図に L3 を足すだけで済み、安い。
しかし読み手が地図を開いているとは限らない。コードを読んでいるときに
「この範囲は何の実装か」を問えないなら、往復の半分が欠ける。
往復は片方向を二つ並べたものではなく、どちらから入っても同じ対応を引けることを言う。

**指紋の食い違いを自前で判定する。** 文書の `## 実装の指紋` 節を読み、
`trace-index.py` が返す指紋と突き合わせれば、`docs-audit.py` を呼ばずに済む。
しかしそれは節の書式と突き合わせの規則をこちらに写すことであり、REQ-003 の破れになる。
上流が書式を変えれば、ゲートは新しい規則で、画面は古い規則で判じることになる。

**印なしのコードを「根拠を持たないコード」として挙げる。** 覆いの数字が締まって見える。
しかし上流はこれを既知の限界としている（doctrine 側 ADR 054）。印は任意であり、
印が無いことが欠陥かどうかは原理的に判じられない。挙げれば擬陽性を量産する。

## 決定

深度 L3 を実装し、文書とコードを双方向に行き来できるようにする。ADR-003 を置換する。

事実と判定を分ける。**範囲の在処は `trace-index.py` から、食い違いの判定は
`docs-audit.py` の所見から**取る。こちらでは判定しない。

## 帰結

- コードを読んでいるときも、地図を見ているときも、同じ対応を引ける。
- 指紋の食い違いは上流が判じた結果として表示される。上流が判定を変えれば表示も変わる。
- 上流の CLI を呼ぶ回数が一回から三回に増える。取得はこれまでどおり一つに束ねる。
- 印なしのコードは挙げない。覆いの数字は示すが、不足として鳴らさない。
- ADR-003 の「最初のスライス」という枠は役目を終える。以降の未実装
  （監査の所見の全面表示・力学配置・追跡マトリクス）は、この ADR の枠外にある。
